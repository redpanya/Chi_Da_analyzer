# 분석 리포트 화면용 테스트 데이터

> **2026-10-18 후속 변경:** 서버·Google Drive 자동 제출은 제거하고 JSON 저장 후 이메일 수동 첨부로 전환했다. 새 내보내기에는 VOD 번호가 포함된다. 아래 내용은 당시 기록이며 현재 동작은 [이메일 리포트 변경 기록](2026-10-18-리포트-이메일안내-VOD번호-개선.md)을 따른다.

작성일: 2026-10-18

## 작성 내용

기존 실제 보관함과 분리한 가상 보관함에 리포트 4종을 추가했다. 영상·채팅·전사·모델 파일은 복사하지 않았다. 처리 시간, 발언/문자/토큰 수, 하드웨어 값은 화면 확인용 임의 수치이며 실제 성능 측정값이 아니다.

데이터 위치: `로컬 검증용 outputs/chida-report-samples-20261018/`

| 사례 | 주요 확인 내용 |
|---|---|
| 가상 테스트 01 · 정상 완료 | 1시간 영상의 단계별 완료/소요 시간, 화자 구분 생략, 처리량 |
| 가상 테스트 02 · 화자 실패 후 요약 일부 완료 | task_failed, 화자 불명으로 계속 진행, needs_review와 일부 완료 |
| 가상 테스트 03 · 전사 중단·미계측 | 2시간 영상 중 30분 완료, 중단 시간/미진행 요약 수치의 null 처리 |
| 가상 테스트 04 · 결과 재사용·요약 이어가기 | 재사용 단계, 이번 세션 시간과 실행 폴더 누적 계측 구분 |

각 프로젝트 제목, 로컬 로그, 리포트 하드웨어, README, manifest에 가상 자료임을 표시했다. 제출 페이로드 자체의 CPU/GPU 이름에도 가상 테스트 표기가 있다. `test_fixture.do_not_submit`은 설명용 메타데이터이며 별도 전송 차단 기능은 아니다. 실제 제출은 하지 않았고 수집 서버 미연결 상태를 유지했다.

리포트 상단 사양은 현재 컴퓨터의 조회값이므로 가상 페이로드의 사양과 구분해야 한다. 예시 수치를 실제 Mac 성능으로 해석하지 않는다.

## 검증

- 가상 리포트 4종 모두 기존 닫힌 제출 스키마 검증 통과.
- 기존 리포트 목록 조회와 snapshot 조회 통과. manifest의 파일 해시 일치 확인.
- 내부 브라우저에서 테스트 보관함 4개 항목 표시 확인.
- 정상 완료 사례에서 6단계 표, 처리량, 제출 미리보기 UI와 전송 버튼 비활성 상태 확인.
- 실제 데이터 다운로드·추론·전송·빌드·앱 코드 변경은 하지 않았다.

## 사용과 복귀

현재 브라우저 탭의 보관함을 테스트 자료의 `library` 폴더로 바꾸어 열었다. 왼쪽의 가상 테스트 항목을 선택하고 **7 리포트**로 이동하면 사례를 바꿔 볼 수 있다. 앱의 공용 모델 설정과 기존 보관함 파일은 변경하지 않았다.

기존 자료로 돌아가려면 **새 VOD 가져오기 → VOD 보관함 폴더**를 `기존 VOD 보관함 경로`로 입력하고 **폴더 확인**을 누른다. 브라우저 세션에 선택된 테스트 프로젝트가 남을 수 있으므로 실제 분석 전 보관함 경로를 확인한다.
