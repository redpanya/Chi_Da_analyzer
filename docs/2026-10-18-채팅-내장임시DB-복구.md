# 채팅 작업용 내장 임시 DB와 외장 보관함 복구

## 반영 내용

2026-10-18. exFAT 보관함에서 배포본 SQLite가 `SQLITE_READONLY_DBMOVED`로 중단되는 문제에 대응했다. 특정 VOD나 디스크 이름을 예외 처리하지 않고 모든 채팅 대조 작업에 같은 저장 구조를 적용했다.

- `archive/chat_workdb.py`에서 작업마다 고유한 임시 폴더와 SQLite 연결을 만든다. macOS는 `/private/tmp/chida-chat-*`, Windows는 기존 앱의 사용자 로컬 지원 폴더 아래 `temporary/chida-chat-*`를 사용한다. macOS에서는 외장 위치로 바뀐 `TMPDIR`을 따르지 않는다.
- 원본 페이지·경계 응답·JSON/JSONL/CSV/TXT·검사 기록은 기존 보관함에 유지한다. 대조용 DB와 저널만 임시 위치에서 사용하며 새 `exports`에는 SQLite 파일을 만들지 않는다. 기존 `counts.sqlite`는 삭제하거나 다시 열어 수정하지 않는다.
- 첫 내보내기에서 만든 대조 인덱스를 경계 검사와 최종 병합에 한 연결로 재사용한다. 최종·부분 내보내기는 불필요한 대조 인덱스를 추가 생성하지 않는다.
- 완료·취소·예외 시 커서와 DB 연결을 닫고 임시 폴더를 정리한다. 기존 완료 결과의 선택은 최종 내보내기 및 임시 DB 정리가 끝난 뒤에만 바꾼다.
- 기존 페이지와 경계 응답이 있으면 재사용한다. 임시 DB는 재시도 때 재구성하며 원본 다운로드를 요구하지 않는다. 저장되지 않은 응답은 기존 수집 흐름대로 요청한다.
- 내장 임시 DB 공간 부족·읽기 전용·열기 실패는 기존 자료 보존과 재시도 방법을 한국어로 안내한다. SQLite의 파일 이동 보호·저널·커밋을 비활성화하지 않는다.
- 화면과 새 리포트의 버전, 패키지 기본 버전을 `0.18.2`로 올렸다. 기존 리포트는 변경하지 않는다.

## 영향과 예외

- DB 작업 공간만큼 내장 디스크의 여유 공간이 필요하다. 보관함 디스크의 용량만으로 작업 가능 여부를 판단해서는 안 된다.
- 내장 임시 공간이나 외장 보관함에 기록하지 못하면 완료로 처리하지 않는다. 그전에 받은 페이지와 기존 결과는 유지한다. 실패 중 생성된 부분 내보내기는 이전 정책대로 남긴다.
- 강제 종료·전원 차단은 정리 코드를 실행할 수 없어 고유한 임시 폴더가 남을 수 있다. 다음 작업은 해당 DB를 재사용하지 않으며 보존된 페이지에서 새 DB를 만든다. 다른 실행의 작업 폴더를 추측해 삭제하지 않는다. macOS 시스템 임시 폴더 안의 잔여 파일 정리는 OS 정책을 따른다.
- SQLite 파일에는 작업 중 채팅 내용이 포함된다. 임시 폴더는 표준 `TemporaryDirectory`의 사용자 전용 권한으로 만들고 외부 전송은 추가하지 않았다.
- 새로운 채팅 결과를 선택하면 이전 분석에서 입력 변경으로 표시될 수 있다. 전사·수동 교정·화자 배정·분석·요약을 자동 재생성하지 않는다.
- 외장 출력 폴더 자체가 읽기 전용이거나 분리되면 결과 파일 저장은 여전히 불가능하다. 이번 변경이 모든 디스크 장애를 우회하는 것은 아니다.

## 검증

### 자동 회귀 검사

`test_archive`, `test_import_recovery`, `test_local_import`, `test_automation_reports` 총 52개를 macOS에서 실행해 모두 통과했다. 전체 모델 추론 검사는 수행하지 않았다.

새 검사는 작업 DB의 보관함 외부 배치, 하나의 연결 재사용, 연결 종료·임시 파일 정리, 기존 DB 보존, 임시 공간 부족 시 기존 선택 결과 보존, 네트워크 없는 재시도, 검사 중 취소·재시도, 외장 `TMPDIR` 무시를 확인한다. 기존 경계 누락·실제 동일 반복·응답 변경·포화 응답 검사도 유지한다.

### 실제 exFAT 보관함 복구

`<VOD 보관함>/vod-15655103`을 이동하지 않고 수정된 수집 코드를 실행했다. 이전 배포본의 SQLite 3.45.1 모듈을 사용하여 단순한 SQLite 업데이트 효과와 구분했다. 프로젝트 쓰기 잠금을 확보한 후 기존 프로젝트와 체크포인트를 새 진단 폴더에 백업했다.

- 저장 원본 90페이지와 경계 응답 90개 재사용, 네트워크 채팅 요청 0회.
- 채팅 **17,802건**, 경계 1건 보완, 상태 `complete`, 소요 18.13초.
- 기존 채팅·내보내기·진단 파일 312개의 실행 전후 SHA-256 일치.
- 영상·음성/전사 폴더 파일 41개의 크기와 수정 시각 일치. 영상·음성 전체 바이트 해시 재검사는 하지 않았다.
- SQLite 연결 1개가 `/private/tmp`만 사용했고 종료 후 임시 폴더가 제거됐다. 외장 보관함에 새 SQLite 파일은 0개다.
- 백업 위치: `diagnostics/chat-repair-ddb55a28f587408da402685bdc23decf`.
- 검사 수치: 작업공간의 `outputs/chida-chat-db-fix-20261018/actual-recovery.json`. 채팅 본문이나 개인 보관함을 앱 패키지에 포함하지 않는다.

## 패키징

macOS Apple Silicon용 `ChiDaanalyzer.app`을 로컬 빌드했다. 기존 패키지를 덮어쓰지 않고 별도 빌드 폴더를 사용했다. GitHub 업로드·릴리스·DMG·Windows 패키지는 만들지 않았다.

- 출력 폴더: `outputs/releases/ChiDaanalyzer-0.18.2-macOS`.
- 실행 앱: `ChiDaanalyzer.app`, 버전 `0.18.2`, macOS 14 이상·Apple Silicon.
- 전달용 ZIP: `ChiDaanalyzer-macOS-arm64.zip`, 99,260,589바이트.
- ZIP SHA-256: `93f986f594a5b92df09b4ad5fb8943e6c102194471449b487385a39293556d88`.
- 네이티브 도구는 직전 배포 패키지와 고정 소스 목록이 같은 것을 확인하고 재사용했다. Python 실행기는 수정 소스로 다시 빌드했다. 모델·사용자 보관함·채팅 본문·인증 자료를 포함하지 않았다.

패키지 기본 실행 검사에서 포함 도구, 미디어 읽기·원음 추출, 다운로드 후 복구, 경계 채팅 보완, 순차 작업 상태, 리포트·VOD 번호·기존 리포트 보존, 이메일 안내·자동 제출 비활성화, 로컬 서버 시작·정상 종료를 확인했다. 버전 검사도 `0.18.2`에 맞췄다.

완성 앱을 실제 외장 exFAT 볼륨의 별도 합성 보관함에서도 실행했다. 경계 누락 1건을 보완해 4건으로 완료됐고 채팅 요청 0회, 기존 파일 보존, 외장 SQLite 파일 0개를 확인했다. 합성 보관함과 검사 프로세스는 종료·정리했다.

최종 ZIP을 `ditto`와 `unzip`으로 각각 해제한 뒤 ASCII 파일명·엄격한 서명 검사가 통과했다. macOS LaunchServices로 실제 앱 실행기와 백엔드가 시작되고 로컬 HTTP 응답이 오는 것도 확인했다. 임시 서명만 적용했으며 Developer ID 서명·Apple 공증은 없다. Gatekeeper 평가는 `rejected`였고 다운로드 격리 속성이 붙은 최초 실행은 검증하지 않았다.

새 앱에서는 같은 외장 보관함을 선택하면 된다. 실제 대상 VOD의 채팅은 이번 작업에서 이미 복구했으며 다시 다운로드할 필요가 없다. 다른 중단 VOD는 채팅의 다시 시도로 저장 자료를 재사용한다. 기존 앱과 새 앱을 동시에 같은 VOD에 실행하지 않는다.

Windows 실제 실행·패키징과 장시간 모델 추론은 이번 검증에 포함하지 않았다. 검사 JSON과 체크섬은 출력 폴더에 함께 보관했다.
