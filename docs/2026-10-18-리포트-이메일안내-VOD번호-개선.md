# 리포트 이메일 안내와 VOD 번호 포함

작성일: 2026-10-18
범위: 소스 수정·대상 검사·macOS 내부 브라우저 확인. 서버 배포·메일 발송·앱 빌드·GitHub 업로드는 하지 않는다.

## 변경한 이용 흐름

`7 리포트 → 실행 기록 선택 → 이메일 첨부용 JSON 미리보기 → JSON 파일 저장 → 메일에서 직접 첨부·발송`

- 수신 주소: **redpanyaday@gmail.com**. 메일 작성 링크와 직접 첨부하는 순서를 화면에 표시한다.
- 앱은 이메일을 자동 발송하거나 파일을 자동 첨부하지 않는다. JSON 저장도 외부 전송이 아니다.
- 서버·Google Drive 자동 제출 기능, 제출 동의 체크박스/전송 버튼, 서버 연결 상태 안내를 제거했다.
- `archive/report_submission.py`, 운영자용 `report_collector` 서버 코드·안내를 제거했다. Manager의 제출 객체와 설정 로딩도 제거했다.
- 예전 화면이 호출할 수 있는 `/api/report-submit`은 410과 제거 안내만 반환한다. 전송 경로로 연결되지 않는다.
- 기존 `report-submission.json`이 사용자 설정 폴더에 있더라도 읽거나 실행하지 않는다. 기존 개인 설정 파일 자체는 삭제하지 않았다.
- 수집 서버 준비 계획과 이전 제출 문서에는 현재 방식으로 변경됐다는 안내를 추가하고 당시 기록을 보존했다.

## JSON 형식과 비교 방법

새 형식은 `schema: 2`, `policy: "2026-10-18.2"`이며 최상위에 `vod_id`를 추가한다. 아래는 필드 설명을 위한 일부 발췌다.

```json
{
  "schema": 2,
  "policy": "2026-10-18.2",
  "vod_id": "15655103",
  "report_id": "실행별로 생성되는 32자리 식별자"
}
```

- `vod_id`는 앱에 등록한 VOD 번호다. 긴 번호의 자릿수를 잃지 않도록 숫자가 아닌 문자열로 저장한다.
- 저장 파일명: `chida-report-vod-{vod_id}-{report_id}.json`.
- 같은 VOD의 자료를 `vod_id`로 모은 뒤, `hardware`, `options`, `counts`, `stages`를 함께 비교한다. 같은 실행의 파일을 여러 번 받았을 때는 `report_id`와 내용도 확인한다.
- CPU·GPU·RAM은 해당 실행 때 기록한 값이다. 화면에서도 현재 PC와 선택한 실행의 PC 사양을 구분해 표시한다.
- VOD 번호가 같더라도 영상 길이·전사/채팅량·모델/옵션·이어하기·기존 결과 재사용·다운로드 네트워크 조건이 다르면 동일 조건의 속도 비교가 아니다. 재사용/중단/부분 완료 상태와 미계측 null 값을 유지한다.
- 로컬 비디오에 치지직 VOD 주소를 연결한 자료는 등록한 번호를 사용한다. 별도 번호로 만든 시험용 VOD는 그 시험 번호를 유지한다. 출처가 입증되지 않은 번호로 자동 합치지 않는다.

## 기존 자료 보존과 예외 처리

- 신규 실행은 처음부터 VOD 번호를 기록한다.
- 이전 `schema: 1 / policy: 2026-10-18.1` 리포트는 열람·내보내기 사본에만 현재 VOD 번호를 보완한다. 기존 저장 JSON을 일괄 변환하거나 덮어쓰지 않는다.
- 새 형식에 기록된 번호가 선택한 VOD와 다르면 오류를 표시한다. 번호를 임의로 고치지 않는다. 알 수 없는 버전·정책도 강제로 변환하지 않는다.
- VOD 번호는 0으로 시작하지 않는 최대 18자리 ASCII 숫자 문자열 규칙을 적용한다. URL·경로·문자·숫자형 값은 거절한다.
- 미리보기 사본을 만든 뒤 작업이 진행돼도 이미 표시한 사본은 바뀌지 않는다. 최신 기록이 필요하면 새로고침 후 미리보기를 다시 만든다.
- 다른 실행 선택·화면 이동·새로고침 시 미리보기와 저장 가능 상태를 초기화한다. 이전 화면에서 늦게 도착한 미리보기 응답도 무시한다.
- 영상·채팅·원음·전사·수동 교정·화자 배정·요약·기존 리포트 내용은 수정하지 않는다.

## 제공 정보 안내 변경

JSON에는 VOD 번호와 기존 성능 수치만 추가·유지한다. 영상·음성·전사/채팅/요약 원문, 용어 힌트 본문, 닉네임·수동 화자명, VOD 주소·제목, 파일 경로, 로그인 정보, 컴퓨터 이름·장치 ID, 자유 형식 상세 로그는 포함하지 않는다.

VOD 번호로 분석한 방송을 알아볼 수 있다는 점을 명시한다. 이메일을 보내면 발신 주소·표시 이름이 수신자에게 전달될 수 있다는 안내도 추가했다. 완전 익명이라고 안내하지 않는다. 보내준 정보는 분석기 개선에 사용하며 제공하지 않아도 분석 기능을 이용할 수 있다. 삭제 문의는 같은 이메일로 안내한다.

수집 서버용 보관기간 제안은 확정된 이메일 보관 정책으로 승계하지 않는다. 메일함의 실제 보관·삭제 운영은 운영자가 별도로 정해야 한다. 앱에 임의의 보관기간 약속을 추가하지 않았다.

## 검증 결과

- Python 대상 검사 **17개 통과**: 순차 작업 기존 동작, 신규 VOD 번호, 구형 사본 변환과 파일 바이트 보존, 잘못된 번호/버전 거절, 로컬 상세 로그 배제, 같은 VOD의 서로 다른 사양·시간 유지, 정적 자산, 제거된 전송 API의 410 응답.
- 명령: `PYTHONPATH=tests .venv/bin/python -m unittest test_automation_reports test_server_assets -q`.
- 첫 실행에서는 샌드박스가 임시 루프백 서버 바인딩을 차단해 HTTP 검사 3개가 실패했다. 루프백 검사 실행 권한으로 다시 실행해 17개가 통과했다.
- `node tests/test_reports_ui.mjs` 통과: 이메일 안내/수신 주소, VOD 번호, 현재/실행 당시 사양 구분, 저장 파일명·사본 내용, 새로고침/화면 전환 후 초기화, 자동 제출 호출 없음.
- `node --check web/help-content.js` 통과.
- macOS 내부 브라우저에서 합성 리포트를 열어 수신 주소·수동 첨부 안내·자동 전송 버튼 제거·현재/실행 당시 사양 구분을 확인했다. 미리보기에 `schema: 2`, 새 정책과 VOD 번호가 표시되고 JSON 저장 버튼이 활성화된다.
- 기존 합성 리포트 4개를 실제 저장 파일에서 읽어 새 형식 사본으로 변환하고, 원본 SHA-256이 기존 manifest와 모두 일치함을 확인했다.
- 화면 기록: 이메일 리포트 미리보기(개발 환경의 로컬 검증 자료). 기존 유휴 개발 서버를 종료하고 합성 보관함을 사용하는 새 루프백 실행기를 열어 두었다. 원래 보관함과 앱 저장 설정은 변경하지 않았다.

## 검증 한계

실제 메일 발송이나 수신 확인은 하지 않는다. 메일 앱 열기와 첨부는 이용자가 사용하는 프로그램/웹메일에서 진행해야 한다. Windows 실기 검증과 전체 분석 재실행은 하지 않으며 앱 패키지·배포본도 생성하지 않는다. 기존 합성 리포트는 속도 실측 결과가 아니다.
