# GitHub 공개 파일 보안·정리 대상 점검

점검일: 2026-10-27 (한국 시간)

## 범위와 결론

후속 정리: [공개 파일·구버전 실행 파일 정리](2026-10-27-공개파일-구버전실행파일-정리.md). 아래 내용은 정리 전 점검 시점의 기록이다.

치다 분석기는 개인 PC에서 실행하는 로컬 VOD 분석 앱이다. 이번 검사는 공개 파일 노출과 불필요한 파일을 대상으로 하며, 인터넷에 서비스하는 다중 사용자 서버나 모든 코드 경로의 침투 시험을 가정하지 않는다.

- 공개 저장소: `redpanya/Chi_Da_analyzer`, main `3cf87b2753ad6c8e321ff8ca970da53e55e3f248`.
- 매뉴얼 브랜치: `codex/manual-site`, `a9a34cb2a14fde5e10964feeb8517fa262f361be`.
- 현재 main 394개·매뉴얼 47개 파일, 두 공개 브랜치와 공개 릴리즈 8개의 도달 이력에서 고유 blob 716개(UTF-8 텍스트 682개)를 검사했다.
- 최신 preview.4 첨부 9개가 현재 GitHub digest와 일치함을 확인했다. 두 앱 ZIP 및 라이선스/소스 ZIP의 파일 목록, 앱의 읽을 수 있는 설정·웹 텍스트를 검사했다.
- 이전 공개 릴리즈의 작은 검사 JSON·체크섬 등 22개도 내려받아 조사했다.

현재 검사에서 API 키·HF/GitHub 토큰·개인키 형식의 고위험 비밀정보를 발견하지 않았다. 다만 미사용 매뉴얼 스크린샷에서 실제 외장 디스크 경로·저장 방송 목록이 보이고, 과거 Git 이력에는 익명화 전의 개발자 PC 경로가 남는다. 비밀키 유출·외부 침입으로 분류할 근거는 없지만, 공개할 필요가 없는 개발자 환경 정보이므로 우선 정리 대상이다.

이 문서는 후보를 정리한 결과다. 파일 삭제, 기능 변경, Git 이력 재작성, GitHub 게시·릴리즈 변경은 하지 않았다.

## 2. 과거 Git 이력의 개인 PC 경로

대상: `docs/2026-10-16-macOS-배포본-손상경고-진단.md`의 이전 버전.

현재 main은 일반 경로로 치환됐다. 과거 공개 커밋에는 개발자 홈 계정명과 다운로드 위치가 남으며 다음 공개 태그의 소스에도 포함된다.

- `v0.18.0-preview.5`
- `v0.18.1-preview.1`
- `speaker-tools-v1`

경로 노출만 확인됐고 인증키나 사용자의 파일 본문 접근 권한은 확인되지 않았다. 현재 파일을 다시 지우는 것은 해결이 아니다. 이력까지 정리할 경우 커밋 해시·기존 태그·기여자의 체크아웃·배포 소스 연결이 바뀔 수 있으므로 별도 범위를 정해야 한다. 기존 클론·포크·다운로드 사본까지 회수할 수 있다고 안내하면 안 된다. 화자 도구 릴리즈를 단순 삭제하면 앱의 도구 다운로드도 끊길 수 있다.

## 3. 낮은 수준의 식별 정보: 매뉴얼 검사 스크립트

대상: `codex/manual-site/scripts/check.py:63`.

공개 HTML에 개발자 홈 경로와 특정 VOD 번호가 들어가지 않았는지 검사하려고 해당 문자열을 코드에 직접 넣었다. 검사 목적은 적절하지만 검사 코드 자체에는 계정명이 남는다. 실제 비밀번호·인증토큰이 아니다. 개인 이름 대신 일반 홈 경로 패턴과 합성 테스트 값을 사용하는 검사로 바꿀 수 있다. 검사 파일 전체를 삭제할 이유는 없다.

`tests/test_automation_reports.py:227`의 개인 경로·가짜 token=ABC, `tests/test_import_recovery.py:160`, `tests/test_model_paths.py:54`, `docs/2026-10-20-v0.19.0-빌드배포.md:45`는 합성 검증값이다. 실제 비밀정보로 분류하거나 이 이유로 테스트를 삭제하지 않는다.

## 5. 조건부 정리: 제거된 말소리 분리의 실행·빌드 코드

다음은 새 말소리 분리 기능과 공식 release 빌드에서 사용하지 않는 구형 실행 경로다. 파일 단위로 무조건 지우지 말고 테스트·모델 경로 참조를 함께 정리해야 한다.

- `archive/separation.py`
- `archive/roformer_separation.py`
- `workers/sam.py`
- `workers/roformer.py`
- `packaging/sam.spec`
- `packaging/roformer.spec`
- `packaging/requirements-sam.txt`
- `packaging/requirements-roformer.txt`

연관: `archive/sam_models.py`, `archive/sam_catalog.json`, `tests/test_roformer.py`, `tests/test_speech_options.py`, `packaging/README.md`. 구형 모델 엔진 경로에 worker 파일명이 남고 spec에서도 worker를 참조한다. 라이선스 고지·이전 대응 소스는 이 코드의 현행 사용 여부와 별도로 보존할 수 있다.

특히 다음은 기존 결과를 위한 실제 의존성이므로 그대로 유지하거나 작은 호환 모듈로 분리한 후 정리한다.

- `archive/sam_options.py`: speech_store가 이전 SAM 처리 조건의 이름을 표시할 때 사용한다.
- `archive/roformer_models.py`, `archive/roformer_config.py`: speech_store가 기존 BS-Roformer 결과의 모델·프로필 이름을 표시할 때 사용한다.
- `archive/speech_store.py`, `archive/voice_store.py`, `web/speech.js`, `web/voices.js` 및 이전 분리본 재생 경로: 기존 원본과 결과 열람 유지에 필요하다.

단순 삭제의 부작용: 앱 import 실패, 이전 전사 목록 로딩 실패, 과거 분리본 이름·재생 누락, 관련 테스트/구형 도구 빌드 실패. 이번에는 참조 조사만 했고 이 코드를 삭제하거나 앱을 재실행하지 않았다.

## 6. 실행에는 불필요하지만 보관 가치가 있는 자료

- 날짜별 개발 문서 35개, 합계 300,212바이트. 앱 실행과 release 조립에는 사용하지 않지만 기존 설계·검증·실패 이력이다. 사용자 요청에 따라 docs에 작업 기록을 남겨왔으므로 통째로 삭제하기보다 별도 개발 기록 영역으로 모으는 편이 맞다. 이동 시 문서 링크도 함께 바꿔야 한다. 아래 부록에 전체 파일명을 적었다.
- `packaging/README.md`의 구형 SAM/BS 빌드 기록: 상단은 제거 사실을 안내하고 하단은 예전 절차다. 현행 release/README.md 안내와 구분되도록 과거 기록을 따로 옮길 수 있다. 이 파일 전체가 보안 위험이라는 뜻은 아니다.
- `macOS-arm64-smoke.json`, `Windows-x64-smoke.json`: 사용자 실행에는 불필요한 배포 검증 자료다. 공개본 12개에서 확인한 경로는 GitHub CI 러너의 설치·빌드 경로이며 실제 사용자 보관함·토큰이 아니다. 유지하되 릴리즈 화면에서 검증 자료로 구분하면 된다.
- 매뉴얼 `source/`, `scripts/`, README: 브라우저가 페이지를 읽는 데는 불필요하나 재생성·정합성 검사에 필요하다. 공개 웹 자원을 최소화하려면 배포 산출물만 Pages로 올리는 별도 설정 변경이 필요하며, 소스부터 삭제하면 매뉴얼 갱신이 어려워진다.

## 7. 삭제하면 안 되는 주요 파일

| 파일·자료 | 유지 이유 |
|---|---|
| `app.py`, `archive/`, `workers/`의 현재 호출 코드, `web/`의 현재 import·DOM 자원 | 앱 실행·이전 자료 호환 |
| `.github/workflows/build.yml`, `packaging/release/`, `requirements*.txt`의 현행 의존성 | macOS·Windows 재빌드·릴리즈 생성 |
| `tests/`의 현행 기능·경계·자료 보존 검사 | 사용자 실행에는 불필요하지만 CI가 실제 사용 |
| `LICENSE`, `THIRD-PARTY-NOTICES.md`, `licenses/`, 외부 소스 안내 | 현재 프로젝트의 이용·재배포 고지 |
| `legal-corresponding-sources.zip`, `native-corresponding-sources.zip`, `license-notices*.zip` | 현재 배포의 외부 도구 고지·대응 소스 제공 자료. 단순 용량 정리 대상으로 취급하지 않음 |
| `SHA256SUMS.txt`, `LICENSE-SHA256SUMS.txt` | 배포 파일 무결성 비교 |
| `speaker-tools-v1`의 실행 도구 ZIP·소스·고지 | archive/speaker_tools.py:12 및 설치기가 릴리즈를 참조해 별도 도구를 받음 |
| 현재 사용하는 `screenshots/020-*.jpg`, 패턴 이미지·CSS·JS | 매뉴얼 안내 및 앱·매뉴얼 배경 |

GitHub Actions의 `GH_TOKEN: ${{ github.token }}`는 실행 시 주입되는 참조이며 토큰 원문이 저장된 것이 아니다. 현재 workflow의 기본 권한은 contents:read, 초안 생성 작업만 contents:write이고 checkout 자격증명 저장을 끈다. 이 구문 때문에 workflow 파일을 삭제할 필요는 없다.

## 8. 공개 파일과 네트워크 노출의 구분

소스 파일이 공개돼 있다는 사실만으로 사용자 PC의 보관함이나 포트가 외부에 열린 것은 아니다. 현재 `archive/server.py:42,49-55,280`은 루프백 바인딩·실행별 난수 경로·Host/Origin 확인을 사용한다. `archive/context_server.py:50-55`도 루프백·실행별 임시 키를 사용한다. 공개된 고정 접속 비밀키는 발견하지 않았다.

이 확인은 설정·소스 검토다. 모든 네트워크 공격과 악성 파일 입력을 검증한 침투 시험은 아니다.

## 확인하지 않은 범위

- 전체 종속 라이브러리의 최신 CVE, 운영체제·드라이버 취약점, 정식 서명·공증의 추가 검사.
- 모든 이전 앱 ZIP·추가 화자 도구 ZIP을 다시 내려받아 바이너리 내부까지 전수 분석하는 검사.
- 이미지 전체의 OCR·EXIF 전수 검사. 이번 실제 화면 8개와 최근 교체된 댓글 예시는 직접 확인했다.
- 이미 복제된 포크·외부 다운로드·검색엔진 캐시 또는 GitHub에서 도달 불가능한 객체.
- 현재 코드 모든 경로의 동적 침투·오류 재현. 앱 기능·사용자 원본·분석 결과는 변경하지 않았다.
