# HTTPS·Windows 화자 도구·사양 리포트·미리듣기 수정

## 범위와 보존

2026-10-30 Windows 지원 재점검의 네 항목을 수정한다. 기존 VOD 영상·채팅·전사·화자 배정·문맥 결과·편집 초안을 변경하지 않는다. 기존 화자 모델과 설치 버전도 남긴다. 검증은 별도의 합성 자료와 임시 폴더에서 진행하며 사용자 보관함을 실행 대상으로 사용하지 않는다.

## 변경

- Windows FFmpeg는 Schannel, macOS FFmpeg는 SecureTransport를 명시한다. 원격 구간 수신은 인증서 검증을 켠다. 단순 프로토콜 목록 검사 외에 공개된 동일 커밋의 4초 합성 영상을 HTTPS로 받아 1~3초 구간 생성·전체 디코드를 검사한다.
- FFmpeg 오류는 프로토콜 미지원·인증서·공간 부족·시간 초과를 구별하고 로그의 전체 경로를 안내한다. 서명된 영상 URL이나 로그 본문은 화면에 노출하지 않는다.
- Windows sherpa·pyannote 실행 도구를 별도 ZIP으로 빌드한다. pyannote는 본체 NumPy 환경과 분리된 PyTorch CPU 전용 환경을 사용한다. 기존 macOS 도구는 교체하지 않는다. 앱 설치기의 SHA-256 검사, 검사 완료 후 활성화, 기존 모델·결과·이전 버전 보존을 실제 ZIP으로 검증한다.
- Windows 사양 조회는 절대 경로의 시스템 PowerShell을 사용한다. 기존 패키지 PATH 제한은 유지하며 UTF-8 출력을 명시한다. 조회가 거부되면 미확인 값으로 남기고 과거 리포트를 다시 쓰지 않는다.
- 선택 오디오 미리듣기는 HTTP 전송 중 파일을 유지하고 캐시 교체·종료 시 삭제를 유예한다. Windows 파일 점유로 삭제가 거부돼도 새 미리듣기 파일과 캐시 목록이 손상되지 않도록 했다.

## 예외·영향

- 인증서 검증 실패를 우회하지 않는다. 시스템 시각·인증서·네트워크 문제는 오류와 로그 경로로 확인한다.
- FluidAudio는 계속 macOS Apple Silicon 전용이다. pyannote의 Community-1 모델 이용 동의·HF 인증과 모델 다운로드는 실행 도구 설치와 별도다.
- 다른 프로그램이 임시 미리듣기 파일을 계속 잡고 있으면 OS 임시 폴더에 파일이 남을 수 있다. 원본·분할 결과는 정리 대상이 아니다.
- GPU 없는 CI의 통과는 Windows NVIDIA GPU 추론이나 사용자 PC 전체 GUI 검증을 뜻하지 않는다.

## 검증 진행

- 신규 사양 조회·캐시 검사 10개: 로컬 macOS에서 9개 통과, Windows 열린 파일 전용 1개는 건너뛰었다. 최종 Windows CI에서는 10개 모두 통과했다.
- HTTPS 관련 단위·범위 보존 검사 15개 통과. 실제 HTTPS 수신·인증서 거부 결과는 아래 최종 CI 기록에 별도로 기재한다.
- Python 3.11 로컬 배포 환경에는 현재 FontTools가 없어 전체 검사 환경으로 사용할 수 없었다. 의존성이 갖춰진 개발 환경으로 회귀 검사하며, 실제 패키지는 Python 3.11 CI에서 검증한다.
- 개발 환경의 기본 Python 회귀 133개 통과(플랫폼 전용 2개 제외) 및 연결된 JavaScript 검사 통과. 개발용 FFmpeg의 실제 HTTPS 1~3초 수신·전체 디코드 통과.
- 로컬 `build/native/ffmpeg`는 오래된 PNG 미지원 파일이라 추가 미디어 검사 진입에서 차단됐다. 해당 파일을 검증 근거로 사용하지 않고 CI에서 새로 만든 배포 바이너리로 검사한다.
- Windows 화자 도구 [빌드 41031186136](https://github.com/redpanya/Chi_Da_analyzer/actions/runs/41031186136) 두 종류 성공. 실제 ZIP 설치·검사 후 활성 버전 변경·재실행·기존 설치/모델/결과 보존·잘못된 해시 거부·8kHz 입력 거부 통과. 모델 추론은 실행하지 않았다.
- Windows ZIP 및 엔진별 고지·대응 소스·작업기 소스·해시·검사 JSON을 [speaker-tools-v1](https://github.com/redpanya/Chi_Da_analyzer/releases/tag/speaker-tools-v1)에 추가했다. 이전 자산 7개의 ID·크기·digest가 그대로임을 확인했다. 앱 설치기의 실제 공개 API 조회로 두 Windows 파일 인식과 크기·SHA-256 검사를 확인했다.
- sherpa ZIP: 33,667,016 bytes, `80074677ddf02f8af07b5a23352e6498662fb6bafc5ba20226d7de8f261bee93`.
- pyannote ZIP: 240,404,686 bytes, `0b6a5367bd203c203365064e59ae7d7f47c0433805c841bd5c328c9562fc169b`.
- 두 도구 소스 기준: `e8e4a1a14e5d3fbd4dcc7651b2732a387a74272d`. pyannote 라이브러리 자체의 약 960KB 샘플 WAV 외에 사용자 음성·HF 모델·인증 파일은 포함하지 않는다.

## HLS 인증서 검증 추가 보완

FFmpeg 8.1.3의 `ffio_copy_url_options`는 최상위 `tls_verify`를 하위 HLS 요청으로 복사하지 않았다. 또한 현재 기본값은 인증서 검증 꺼짐이다. 최상위 MP4만 검사하면 하위 재생목록·세그먼트·키 요청의 안전성을 놓칠 수 있다.

첫 앱 빌드 41031182104는 이 검토 결과에 따라 공개 전에 취소했다. 패치와 HLS 양성·신뢰할 수 없는 인증서 거부 검사를 추가한 뒤 두 OS 앱을 다시 빌드한다. 기존 사용자 자료와 공개 앱 릴리즈는 이 취소로 변경되지 않는다.

HTTPS 검사는 공개 합성 자료를 실제 `remote_media.receive`로 받는다. 치지직 주소 해석 부분만 고정된 시험 URL로 대체했다. 패키지에 들어간 FFmpeg와 ffprobe의 절대 경로를 사용했고 다운로드 ZIP의 바이너리 SHA-256과 검사 기록을 대조했다. 각 OS의 검사에서 FFmpeg 8회·ffprobe 2회 실행을 확인했다. 시스템 인증서 저장소나 보안 설정을 변경하지 않았다.

Windows 패키지는 제한된 PATH 그대로 CPU `AMD EPYC 7763`, 2코어·4스레드, RAM 17,174,360,064 bytes, GPU `Microsoft Hyper-V Video`를 조회했다. macOS는 Apple M1 가상 CPU 3코어·3스레드, RAM 7,516,192,768 bytes를 조회했으며 GPU는 미확인 값으로 남겼다. CI 가상 환경의 값이며 사용자 PC의 측정값이 아니다. 구형 리포트 파일은 바이트 단위로 보존됐다.

Windows 실제 파일 핸들을 연 채 미리듣기 캐시를 8개 넘게 교체하는 검사가 통과했다. 삭제를 유예한 뒤 핸들을 닫고 다시 접근하면 정리되며, 새 미리듣기는 정상 제공된다. HTTP 전송 중 보존·전송 실패·생성 실패·종료 시 삭제 거부 검사도 통과했다.

기존 자료 복구 검사에서 합성 영상·채팅·기존 출력 보존, 네트워크 재요청 0건의 채팅 복구, 기존 재생 파일 재사용을 확인했다. 사용자 보관함의 원본·실제 모델·결과 파일은 수정하거나 삭제하지 않았다.

## 배포 파일과 공개 범위

배포 대상은 [v0.20.0-preview.6](https://github.com/redpanya/Chi_Da_analyzer/releases/tag/v0.20.0-preview.6)이다. 이전 앱 릴리즈와 macOS 화자 도구는 유지한다. 앱 ZIP 2개, OS별 검사 JSON 2개, 고지 ZIP 2개, 네이티브 대응 소스, LGPL·MPL 대응 소스, SHA-256 목록으로 총 9개 파일을 제공한다. 원문 소스와 적용한 TLS 패치를 네이티브 대응 소스에 포함했다.

실제 업로드 파일을 다시 다운로드해 9개 자산의 GitHub digest·SHA-256·ZIP CRC를 대조했다. 웹 자산·동봉 글꼴·고지 원문·라이선스 해시·대응 소스·빌드 레시피도 해당 빌드 커밋과 일치했다.


- `macOS-arm64`: 117,394,606 bytes, SHA-256 `54abcd648eedf9c59a9eb9368dfacca3c52e4eb5f9f0b111639bac21df211930`.

- `Windows-x64`: 141,348,608 bytes, SHA-256 `b6988f86547bbec28d6e935859fd363bc8576a58cca1d95516940ac4db368398`.


## 남은 실환경 확인과 서명

- macOS는 ad-hoc 서명이다. `ditto`·`unzip` 압축 해제 뒤 서명과 Launch Services·실행기·HTTP 시작은 통과했지만 Apple 공증이 없어 CI의 Gatekeeper 평가는 거부였다. 인터넷에서 받은 앱의 최초 허용·실행까지 확인한 것은 아니다.
- Windows Authenticode 서명은 없다. Windows 실제 사용자 PC에서의 브라우저 조작, 보안 소프트웨어, 외장 디스크, GPU 드라이버별 동작은 별도 확인이 필요하다.
- 실제 치지직 장시간 VOD 구간 다운로드, Community-1 모델 추론·정확도, NVIDIA GPU 성능은 이번 검증 범위가 아니다. Windows 화자 도구는 CPU 실행 도구의 설치·재실행과 모델을 로드하기 전 입력 검증까지 확인했다.
- DMG는 생성하지 않았다. 앱·고지·대응 소스 ZIP을 제공한다.
- 로컬 근거는 `outputs/github-builds/2026-10-30-runtime-fixes/`의 `app-ci.log`, `download-verification.json`, `release/*-smoke.json`, `speaker-download-verification.json`에 보관했다. 원본 사용자 자료는 포함하지 않는다.
