# 최근 기능 통합 배포 및 OS 호환 검사

## 범위

현재까지 구현한 VOD 작업 설정·구간 다운로드, 세 분석 모드와 외부 AI 요청,
결과 탐색·댓글 편집, 클립 편집기, 자막·설치 글꼴·PNG 합성,
독립 영상 나누기와 전체/선택 오디오 트랙 보존을 두 OS 패키지에 반영한다.
릴리즈 태그는 `v0.20.0-preview.5`, 앱 표시 버전은 기존 `0.20.0`이다.
macOS Apple Silicon 및 Windows x64가 대상이며 DMG를 만들지 않는다.

사용자 영상·채팅·모델·전사·수동 교정·화자 배정·요약·편집 결과는 업로드하거나
수정하지 않는다. 개발 환경 전체 대신 배포용 체크아웃에 검토한 앱 파일만 반영한다.

## 확인된 문제와 보완

- 기존 FFmpeg의 `--disable-autodetect` 설정으로 PNG 디코더가 빠져 있었다.
  개발 Mac의 FFmpeg에서는 동작하던 자막/PNG 합성이 배포 FFmpeg 검사에서 실패했다.
  두 OS 빌드에 zlib를 명시하고 Windows 빌드 의존성을 추가한다.
- 기존 소스 내보내기는 글꼴 바이너리와 OFL 원문을 제외했다.
  출처 목록의 해시를 확인한 동봉 글꼴만 추가하고 사용자 설치 글꼴은 반출하지 않는다.
- 기존 Windows 검사는 최근 편집·분할 기능을 포함하지 않았다.
  OS별 네이티브 FFmpeg를 이용한 회귀 검사와 독립 실행 패키지 HTTP 검사를 추가한다.

## 검증 계획과 판정

- 기존 소스 회귀 검사와 신규 작업 설정·삭제·클립·글꼴·분할 검사.
- 가상 다중 오디오 영상의 전체/선택 트랙 분할: 영상·선택 오디오 패킷 SHA-256
  동일성, 제외 트랙 없음, 원본 파일 SHA-256 유지, 중단·재개.
- 실제 패키지에서 한글 글꼴 목록·한글/공백 자막 PNG 렌더링·PNG 클립 합성,
  선택 오디오 미리듣기 HTTP, 한글·공백 경로 검사.
- 배포 CSP와 개발 주석 옵션 차단, 포함 자산, ZIP·첨부 체크섬과 라이선스 자료 확인.

## 예외·영향 범위

- Windows는 GitHub Windows runner에서 빌드·실행한다. Mac에서의 검사만으로
  Windows 동작을 확정하지 않는다. 물리 Windows PC, GPU 추론, 브라우저 음향·재생,
  파일 선택창, 장시간 실제 VOD 처리는 별도 사용자 확인이 필요하다.
- 영상 나누기는 기존 지원 범위인 일정 프레임률 H.264/AAC MP4의 키프레임 경계에서
  스트림 복사한다. 클립 편집의 자막/효과 합성은 기존처럼 재인코딩한다.
- 기존 패키지·릴리즈는 덮어쓰지 않고 새 사전 릴리즈를 만든다.
- macOS 임시 서명만 적용하며 Developer ID 공증과 Windows Authenticode 서명은 없다.

## 진행 기록

- 개발 Mac: 기존 Python 검사 125개(Windows 전용 2개 제외), 신규 Python 검사
  138개와 관련 JavaScript 검사 통과. 신규 검사는 PNG 지원이 있는 개발용 FFmpeg로
  확인했으며, 최종 판정은 각 OS의 배포 FFmpeg와 패키지 검사로 별도 진행한다.
- 첫 CI에서 배포 진입점 동기화 누락으로 개발 주석 옵션 차단 검사 문구가 달랐다.
  진입점을 동기화했으며 패키지에서는 옵션 사용을 거부하는 동작을 유지한다.
- Windows 검사 도구가 자식 환경의 PATH만 전달해 FFmpeg를 찾지 못했다.
  검사 진입 명령은 OS별 실행 파일의 절대 경로를 쓰도록 변경했다.
- Windows Git의 개행 변환으로 글꼴 고지 원문 해시가 달라지지 않도록
  동봉 글꼴과 OFL 파일의 원문 보존 및 해시 검사를 추가했다.
- 재실행 CI: https://github.com/redpanya/Chi_Da_analyzer/actions/runs/41015129454

- Windows 추가 검사에서 클립 중간 파일의 경로 구분자 문제를 발견해
  소유 파일 목록을 POSIX 경로로 정규화했다.
- Windows PNG 합성 검사는 파일 생성과 길이 검사는 통과했으나 출력 픽셀 대조가
  실패했다. 합성 프레임 정규화만으로 해결되지 않아 입력 PNG 픽셀과 FFmpeg 로그를
  추가 수집한다. 실제 원인 및 최종 판정은 아래 결과에 기록한다.
- 테스트용 Python 실행 파일과 ZIP 경로가 Windows에서 다르게 해석되는 부분,
  NTFS 한 틱 안의 동일 크기 파일 교정 판정을 검사 데이터에서 보완했다.
  범위 작업 삭제는 Windows의 실제 휴지통 API로 검증한다.
- Windows 휴지통 이동은 폴더 안의 열린 잠금 핸들 때문에 거부됐다. 읽기 공유만으로는
  해결되지 않았다. 이동 중에는 경로별 Windows 커널 세마포어로 신규 잠금 진입을
  차단한 채 파일 핸들을 닫고, 실패하면 파일 잠금을 복구한다. 일반 작업의 파일 잠금과
  자식 프로세스 상속은 그대로 유지한다. 프로세스 간 이동 중 진입 차단·실패 복구를 검사한다.
- PNG 입력은 정상인데 Windows 합성 출력 색이 달라졌다. 같은 FFmpeg의 기본 실행은
  합성 RGB `(75, 0, 185)`, `-cpuflags 0` 대조는 정상 범위인 `(60, 10, 112)`였다.
  `--disable-x86asm`과 활성 inline SIMD가 섞인 색 변환 경로가 원인인 것으로 좁혔다.
  Windows 빌드에 NASM을 추가하고 FFmpeg x86 어셈블리를 함께 활성화한다.
  CPU 기능 자동 감지는 유지하고 특정 CPU 명령어를 강제하지 않는다. macOS와 x264
  설정은 유지한다. 최종 출력과 같은 YUV420 합성 및 기본/비최적화 RGB 대조 검사를 추가했다.
- Python의 Windows ZIP 경로 정규화 전에 원문(`orig_filename`)을 검사하도록
  수정해 역슬래시·NUL 경로 검사를 유지한다.
- 대응 소스 다운로드의 일시 TLS EOF로 중단된 빌드는 재시도해 통과했다.
  일시 네트워크 오류에 한해 최대 3회 재시도하도록 보완했다. 인증서·체크섬·내용 오류는
  즉시 실패하며 TLS 검증과 대응 소스 제공을 유지한다. 관련 단위 검사 9개 통과.
- Windows 경로별 이동 잠금, 휴지통 삭제, ZIP 원문 경로 검사는 실제 Windows CI에서 통과했다.

Windows FFmpeg 수정 후 PNG 합성 RGB는 기본 실행 `(60, 9, 113)`,
비최적화 대조 `(60, 10, 112)`로 일치 범위에 들어왔다. YUV 값도 두 경로 모두
`(48, 166, 143)`으로 같았다. 자막·PNG 검사를 느슨하게 바꾸지 않고 빌드 구성을 수정했다.

분할 검사는 가상의 한글·공백 경로 영상에서 원본 SHA-256과 영상/오디오 패킷 해시를
대조한다. 3개 오디오 전체 보존 및 2개 선택 보존, 선택 트랙 미리듣기, 재실행·취소·
재개를 확인했다. 사용자 보관함 자료와 모델로 새 분석을 실행하지 않았다.

릴리즈 초안에서 첨부 파일 9개를 다시 내려받아 다음 검사를 통과했다.

- GitHub 자산 digest·크기, `SHA256SUMS.txt`, 모든 ZIP CRC 일치.
- 두 앱의 전체 웹 파일·배경 8종·동봉 글꼴이 배포 소스와 일치.
- 앱 내부와 OS별 고지 ZIP의 파일 집합·원문이 일치하고 고지 manifest 해시 통과.
- 네이티브·LGPL/MPL 대응 소스의 목록·해시·크기·빌드 레시피 일치.
- 패키지 검사 JSON에서 원본 보존, 스트림 패킷 동일성, 새 채팅 요청 없는 복구,
  배포 CSP와 개발 주석 옵션 차단 확인. Windows Vulkan 엔진은 포함하지만 CI에
  Vulkan 드라이버가 없어 실제 GPU 추론은 수행하지 않았다.

### 남은 사용자 장치 확인

- 물리 Windows PC에서 파일 선택창, 브라우저 영상·오디오 미리보기와 트랙 전환.
- 설치된 개별 글꼴, GPU 드라이버별 Vulkan 전사·Gemma 추론, 외부 화자 도구 설치.
- 실제 장시간 VOD 다운로드·분석·편집, 저장 공간 부족·외장 디스크 연결 해제 상황.
- 공증/Authenticode 서명은 미적용. 자동 검사는 Gatekeeper·SmartScreen 경고 없는 실행이나
  모든 장치의 성능을 보장하지 않는다.
