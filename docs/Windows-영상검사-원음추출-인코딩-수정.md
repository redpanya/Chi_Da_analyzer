# Windows 영상 검사·원음 추출 인코딩 수정

작성일: 2026-10-15.

## 신고와 원인

Windows에서 치지직 다운로드 뒤 `the JSON object must be str, bytes or bytearray, not NoneType`가 표시되고 원음 추출을 진행할 수 없다는 신고를 조사했다.

`archive/video.py::probe`는 ffprobe의 UTF-8 JSON을 `subprocess.run(..., text=True)`로 받으면서 인코딩을 지정하지 않았다. Python 3.11의 Windows 기본 문자셋이 CP949 등일 때 한글 경로·제목·다국어 메타데이터에서 디코딩이 실패할 수 있다. Windows의 subprocess 읽기 스레드는 디코딩 예외가 나면 결과 버퍼를 채우지 못하고 `stdout=None`을 반환할 수 있다. ffprobe 자체는 정상 종료해 다음 `json.loads(None)`에서 신고된 오류가 나타난다. 다운로드 바이트가 잘못됐다는 뜻으로 해석해서는 안 된다.

이 함수는 다운로드 후 영상 검사, 로컬 영상 검사, 음성 트랙 조회와 원음 추출에서 공통으로 사용한다. GPU·CPU 선택이나 전사 모델 로딩 전의 단계다. 사용자 PC의 실제 로그를 수집하지 않았으므로 현장 문자셋·경로까지 확정한 것은 아니며, 동일 오류의 Windows 재현과 수정 경로 검증으로 구분한다.

## 변경과 영향

- ffprobe 출력을 바이트로 수집해 JSON 파서가 읽도록 했다. Windows 로캘과 무관하게 한글·다국어 경로와 메타데이터를 보존한다. 특정 VOD 제목·경로나 문자 예외 목록을 만들지 않았다.
- 빈 결과·잘못된 JSON·잘못된 정보 구조는 원본 보존을 알리는 오류로 표시한다. 실제 도구 실패, 시간 초과, 파일 권한 오류를 정상 완료로 바꾸지 않는다. 영상 트랙·유효 길이 검사를 유지하고 비정상 길이도 거부한다.
- 남아 있는 이전 SAM·BS-Roformer 검증 코드의 같은 ffprobe 수집 방식도 바이트로 통일했다. 제거된 기능을 다시 활성화하지 않는다.
- 앱 진단에 기본 문자셋과 Python UTF-8 모드 값을 추가했다. 시스템 로캘·콘솔 코드페이지를 변경하지 않는다.
- 원본 영상·채팅·전사·수동 교정·화자·요약 결과와 파일 형식을 변경하지 않는다. 새 다운로드나 음성 추출 파라미터도 바꾸지 않는다.

## 검증 기준과 현재 기록

- 새 미디어 JSON 검사 6개: macOS 5개 통과, Windows 읽기 스레드 재현 1개는 Windows CI에서 실행한다. CP949 환경을 모의한 실제 바이트 파이프, 한글·일본어·이모지 보존, 빈/손상 출력, 트랙·길이 검사, 시간 초과·파일 오류 전파를 확인했다.
- 기존 다운로드 검사 2개, 로컬 가져오기 검사 6개, 전사·원음 추출·보존 검사 17개 통과. 로컬 HTTP 검사는 샌드박스의 루프백 바인딩 제한을 해제한 뒤 통과했다. 전체 테스트 모음·모델 추론을 실행한 결과는 아니다.
- macOS 개발 실행에서 임시 1초 H.264/AAC 영상으로 수신 후 검사 재개 → 실제 ffprobe·전체 디코딩 → 원음 정보 API → 원음 추출 API를 통과했다. 출력은 16kHz·모노·16비트 PCM·16,000프레임이며 원본 SHA-256과 채팅 바이트가 유지됐다. 네트워크 수신 부분만 대체했고 실제 치지직 다운로드를 새로 실행하지 않았다.
- CI 기본 실행 검사를 위 미디어 흐름까지 확장했다. 패키지 자식 프로세스에 CI의 UTF-8 강제 설정을 넘기지 않는다. Windows CP949 재현 검사는 기존 `text=True` 방식에서 디코딩 예외·`stdout=None`·동일 TypeError가 함께 발생하는지 확인한다.
- Windows와 macOS의 수정 패키지 실행 결과 및 다운로드 위치는 CI 완료 후 아래에 기록한다. 실제 사용자 Windows PC의 장시간 다운로드·전사·GPU 추론은 별도 확인 대상이다.

## 기존 자료로 재시도

수정본으로 앱을 교체하되 보관함과 모델 폴더는 유지한다. 영상 검사가 오류로 남아 있으면 같은 VOD의 영상 이어받기/재시도로 검사부터 다시 진행한다. 기존 원본과 수신 식별 정보가 일치해야 하며 제공 영상 정보가 달라진 경우에는 기존 충돌 보호를 유지한다. 영상이 이미 완료 상태이면 음성 전사 메뉴에서 원음 정보를 다시 불러와 원음 추출을 실행한다. 보관함 삭제나 Windows 언어 설정 변경은 필요하지 않다.
