# HLS m4v 호환 수정과 두 OS 빌드

## 범위

첨부 로그에서 확인한 MP4 컨테이너·m4v 세그먼트 확장자의 호환 문제를 수정한다. 특정 VOD·방송자·CDN·화질을 예외로 두지 않는다. 사용자 원본·채팅·전사·화자·요약·편집 결과를 수정하거나 삭제하지 않는다. 이전 릴리즈와 실행 도구도 유지한다.

macOS arm64와 Windows x64의 새 FFmpeg 및 앱 패키지를 CI에서 빌드한다. 이번 요청의 산출물은 검증된 빌드 파일이다. 빌드 초안은 공개 릴리즈와 분리하며 현재 공개 다운로드 링크는 변경하지 않는다.

## 변경과 영향

- 초기 형식 판별 결과가 MP4인 HLS 입력에서만 `.m4v`를 HLS 별칭으로 허용하는 패치를 적용한다. 다른 형식과 허용 확장자 검사는 유지한다.
- 기존 TLS 기본 검증 패치를 유지하며, `extension_picky=0`이나 `allowed_extensions=ALL`로 검사 전체를 끄지 않는다.
- 빌드 캐시에 패치 변경을 반영해 이전 FFmpeg가 재사용되지 않게 한다. 변경 패치와 빌드 레시피를 대응 소스 ZIP에 포함한다.
- 형식·확장자 불일치와 허용하지 않는 확장자를 오류 안내에서 구분한다. 일반 `Invalid data` 오류는 원인을 단정하지 않는다. 서명된 CDN URL은 화면에 표시하지 않고 로그 전체 경로만 제공한다.

## 검증 기준

- 같은 합성 MP4 조각을 `.m4v`·`.m4s`로 제공하고 초기화 조각 및 URL 쿼리를 포함한 HTTPS 구간 수신을 실제 배포 바이너리로 확인한다.
- 기존 직접 MP4·TS HLS 다운로드를 유지하고 각 출력 길이·전체 디코드를 검사한다.
- 허용하지 않은 확장자와 잘못된 형식은 계속 거부하며, 직접 HTTPS·HLS 재생목록·세그먼트·키의 잘못된 인증서 거부 검사를 유지한다.
- 두 OS 패키지 시작·한글/공백 경로·원음 추출·다중 오디오·PNG/자막·미리듣기·자료 재사용과 보존 검사를 수행한다.
- 배포 ZIP의 해시·CRC·내부 도구 해시·고지 및 대응 소스를 검증한다.

## 진행 기록

- HTTPS 검사 자료·구간 복구·원본 보존·형식 오류 안내 관련 검사 18개가 로컬에서 통과했다. 단순 오류 문자열만으로 잘못 분류하지 않으며, 로그 원문과 서명 URL은 수정·화면 노출하지 않는다.
- 실제 사용자 Windows PC에서의 긴 VOD 다운로드·GPU 추론은 CI 합성 자료 검사와 구분한다.

HTTPS 5종은 직접 MP4, MPEG-TS HLS, fMP4 m4v, fMP4 m4s, 쿼리 URL fMP4다. 각 검사는 합성 4초 영상의 1~3초를 앱의 실제 구간 수신 경로로 저장한다. 네이티브 빌드와 최종 앱 내부 바이너리에서 각각 실행했다.

형식 거부는 AAC·MPEG-TS를 m4v로 이름 붙인 입력 2건과 허용하지 않는 확장자 1건이다. 인증서 거부는 직접 HTTPS·HLS 재생목록·세그먼트·키 연결 4건이다. MP4 별칭 추가로 전체 검사나 TLS 검증을 해제하지 않았음을 확인했다.

패키지 검사에는 기존 자료 재사용·원본과 채팅 보존, 음성 추출, 다중 오디오 분할·미리듣기, 자막·PNG, 리포트가 포함된다. 사용자 보관함 원본 및 결과를 수정하지 않고 합성 자료로 검사했다.

## 산출물 무결성과 보관

- GitHub 첨부 9개를 확보해 GitHub digest와 `SHA256SUMS.txt`, ZIP CRC를 대조했다.
- 지정 빌드 커밋·CI 성공 상태·초안 상태를 확인하고, 전체 웹 자산·글꼴·라이선스 고지·대응 소스 내부 해시 및 빌드 레시피를 대조했다.
- 앱 ZIP에 들어 있는 FFmpeg·ffprobe 해시와 패키지 실행 검사에 사용한 바이너리 해시가 일치했다.
- 대응 소스 ZIP의 `ffmpeg-hls-m4v.patch`, 기존 TLS 패치, 수정 고지와 재빌드 안내를 Git 원문과 대조했다.
- 로컬 자료: `outputs/github-builds/2026-10-30-hls-m4v-fix/`의 `release/`, `app-ci.log`, `ci-run.json`, `draft-release.json`, `download-verification.json`.
- 첨부받은 사용자 로그의 서명된 CDN URL은 공개 소스·문서·검사 자료에 포함하지 않았다.

## 남은 확인과 배포 제한

합성 자료 검사는 사용자 Windows PC의 실제 치지직 장시간 다운로드를 대신하지 않는다. 새 실행 파일로 기존 보관함을 열고 문제가 난 구간을 다시 실행하는 수동 확인은 남아 있다.

macOS ZIP 해제 후 임시 서명과 Launch Services 실행은 통과했다. Developer ID 서명·공증은 없고 Gatekeeper 검사는 거부 결과다. 인터넷에서 내려받은 첫 실행 허용은 검증하지 않았다. Windows Authenticode 서명은 제공하지 않는다.
