# 공개 파일·구버전 실행 파일 정리

작업일: 2026-10-27 (한국 시간)

## 목적과 보존 범위

사용자가 앞선 공개 파일 점검 후 로컬과 GitHub의 정리 및 이전 실행 파일 제거를 요청했다. 현행 앱·다운로드 도구·기존 결과 호환에 필요한 파일은 남기고, 미사용 코드·화면과 구버전 실행 파일을 정리했다.

- 유지할 최신 릴리즈: `v0.20.0-preview.4`, 빌드 Run `40263382544`.
- 최신 macOS·Windows 앱 ZIP, 최신 로컬 앱, 화자 도구 `speaker-tools-v1`, 라이선스 보완 릴리즈 및 모든 대응 소스·고지·체크섬·검사 기록을 보존한다.
- 사용자 VOD·채팅·전사·수동 교정·화자 배정·요약·모델 파일은 수정하거나 삭제하지 않는다.
- 개발 기록과 현행 테스트를 유지한다. 릴리즈·태그·Git 이력은 재작성하지 않는다.
- 이번 작업은 새 앱 빌드·패키징·릴리즈 생성 작업이 아니다. 소스 변경 이후에도 현재 배포 ZIP의 바이트와 해시는 그대로 유지한다.

## 앱 소스 정리

현행 UI와 공식 배포 경로에서 사용하지 않는 다음 12개를 개발 폴더와 GitHub용 체크아웃에서 제거했다.

- `web/sam-options.js`
- `archive/separation.py`, `archive/roformer_separation.py`
- `archive/sam_models.py`, `archive/sam_catalog.json`, `archive/roformer_models.py`
- `workers/sam.py`, `workers/roformer.py`
- `packaging/sam.spec`, `packaging/roformer.spec`
- `packaging/requirements-sam.txt`, `packaging/requirements-roformer.txt`

서버의 미사용 정적 파일 허용 항목과 두 backend spec의 SAM 카탈로그 포함 설정도 제거했다. 화자 실행기 고지 수집기는 현행 pyannote 대상으로 제한하고, 패키징 설명은 현행 macOS·Windows 배포 절차로 연결했다.

`archive/sam_options.py`와 `archive/roformer_config.py`는 이전 결과의 모델·프로필 표시를 위해 남겼다. speech_store는 모델 다운로드 모듈 대신 작은 설정 모듈만 참조한다. 기존 분리본·전사·교정·재생 경로는 보존하며, 제거된 새 분리 작업 요청은 기존처럼 오류로 거부하고 선택한 결과를 바꾸지 않는다. 제거된 구현만 검사하던 테스트는 정리하고 기존 결과·설정·이어받기 검사는 유지했다.

부작용: 과거 SAM/BS 분리 실행기 자체를 새로 빌드하려면 해당 시점 Git 이력을 사용해야 한다. 현재 릴리즈 실행 기능에는 해당 새 분리 기능이 이미 제거되어 있어 이번 변경으로 현행 메뉴가 줄어들지는 않는다. 현재 배포 ZIP은 다시 만들지 않으므로 미사용 코드 제거가 바이너리에 반영되는 시점은 다음 빌드다.

## 매뉴얼

현재 본문에서 참조하지 않는 실제 환경 화면 8개와 구형 댓글 메모 화면 1개를 제거했다.

`01-import.jpg`, `02-progress.jpg`, `03-transcription.jpg`, `04-speakers.jpg`, `05-explore.jpg`, `06-summary.jpg`, `07-help.jpg`, `08-local-import.jpg`, `020-comment-editor.jpg`.

Git 매뉴얼과 로컬 미리보기의 두 사본을 정리하고, images.json의 미사용 크기 정보도 제거했다. 검사 스크립트에 적혀 있던 개인 경로·특정 VOD 문자열을 일반 경로 패턴 검사로 바꿨다. 실제 설명에 쓰는 32개 화면과 패턴 배경은 유지한다.

기존 URL이나 과거 커밋에서 열던 미사용 화면 링크는 더 이상 현행 Pages 자료를 가리키지 않는다. 과거 Git blob·포크·이미 내려받은 사본은 이번 정리로 제거되지 않는다.

## 로컬 실행 파일

이전 앱 2개, 이전 앱 ZIP 8개, 오래된 매뉴얼 ZIP 1개를 macOS 휴지통으로 이동했다. 총 11개, 1,618,419,755바이트(약 1.51GiB)다. 미사용 화면 9개씩 두 사본 18개(1,061,112바이트)도 휴지통으로 옮겼다.

- 이전 앱: 한글 이름의 0.18.0 빌드 1, 치지직 보관함 0.8.0 빌드 8.
- 이전 앱 ZIP: 10월 23일 패턴 배경, 10월 24일 배경 배포, 10월 26일 댓글 체크박스 배포의 사본.
- 현재 Downloads의 ChiDaanalyzer 앱과 최신 ZIP, 10월 26일 댓글 목록 preview.4 배포 자료는 보존했다.
- 삭제 전 실행 중인 앱인지 확인했으며, 대상 이전 앱은 실행 중이 아니었다. 휴지통은 비우지 않았다. 따라서 디스크 여유 공간이 즉시 늘었다고 볼 수 없다.

휴지통 위치와 개별 완료 기록은 로컬 정리 증거에 저장했다. 공개 문서에는 개인 PC 경로를 복사하지 않는다.

## GitHub 정리

구버전 릴리즈 10개의 앱 ZIP 20개(2,242,205,798바이트)와 이전 빌드의 package 아티팩트 32개(5,935,110,807바이트)를 정리 대상으로 확정했다. 최신 두 OS 아티팩트는 보존한다. 구 릴리즈 본문에는 최신 preview.4 다운로드 안내를 추가하며, 기존 본문·초안 여부·태그는 유지한다. 대응 소스와 고지 첨부는 삭제하지 않는다.

정리 전 GitHub 메타데이터를 보관하고 각 삭제 직후 완료 기록을 저장한다. 파일 ID·이름·크기·해시가 계획과 다른 경우 삭제를 중단한다. 이전 체크섬은 당시 배포 기록으로 남기며, 앱 ZIP 제거 사실을 릴리즈 본문에 명시한다.

위 앱 ZIP 20개·빌드 아티팩트 32개와 구 릴리즈 안내 10개의 반영을 완료하고 보존 파일을 대조했다. 새 Pages 배포 완료 후 이전 매뉴얼 아티팩트 2개도 제거했다. 현재 Actions 첨부는 최신 앱 두 OS와 최신 Pages의 3개만 남는다.

## 검증

- 관련 Python 검사 54개 통과: speech_options, roformer, speech, simplification, server_assets, analysis_inputs, legal_packaging. 기존 전사·수동 교정·선택 결과 보존, 잘못된 새 분리 요청 차단, 서버 자원 및 라이선스 경로 검사 포함.
- 수정 Python 문법 검사와 두 체크아웃의 `git diff --check` 통과.
- 삭제 이후 매뉴얼 검사 통과: 11개 주제, 기본 펼침 63개, 설명별 화면 32개, 링크·로컬 자원·크롭·표시 경계.
- 최신 로컬 앱 ZIP 두 개의 SHA256을 보존 기준과 대조했다.
- 실제 사용자 VOD로 전사·요약을 다시 실행하지 않았으며 새 macOS·Windows 패키지, Windows 실기기, 서명·공증을 검사하지 않았다. 최신 배포본을 재빌드하는 작업도 수행하지 않는다.

## 최종 게시·보존 대조

- 매뉴얼 정리 커밋: `ef1e0d098c7cfd04daff44c744aa3a17e32d63e8`, `codex/manual-site`에 푸시. Pages API의 `built` 및 동일 커밋 확인.
- 공개 매뉴얼 HTTP 200, 제거한 화면 9개의 원래 URL은 모두 HTTP 404. 최신 macOS·Windows 앱 ZIP 다운로드 링크 둘 다 HTTP 200.
- 모든 릴리즈 13개의 남은 첨부를 정리 전과 대조했다. 계획한 앱 ZIP 20개 외 자산은 ID·이름·크기·digest가 같고, 릴리즈·태그명·초안 여부를 보존했다.
- GitHub에서 초안 본문만 수정할 때 예약 태그명이 `untagged`로 바뀌는 현상이 검출되어, 정리 전의 태그명과 초안 상태를 명시해 복원하고 다시 확인했다. 초안을 공개하지 않았다.
- 이전 Pages 아티팩트 2개까지 삭제 후 총 3개 아티팩트만 남는 것을 확인했다. 정리된 Actions 아티팩트는 이전 앱 빌드 32개 + 이전 Pages 2개다.
- 최신 앱 ZIP의 SHA256: macOS `23890fd4f4040ad8945648db2e11b662b1bac195f7b026cf16434007d0fac4b8`, Windows `0d05944ef5ba4889beb0b1be5752ca5d4885f84a25c64af48e41f345909aff56`. GitHub와 로컬 최신 배포본의 보존 기준이 같다.
- 앱 소스와 이 보고서는 `main`의 정리 커밋에 반영한다. `[skip ci]`로 새 앱 빌드를 유발하지 않는다. 저장소 내용·현재 매뉴얼 갱신과 기존 최신 실행 파일 유지가 이번 작업의 범위다.

로컬 정리 근거: `cleanup-plan.json`, `local-trash-result.json`, `remote-cleanup-result.json`, `old-pages-artifacts-removed.json`, `releases-after-cleanup.json`, `artifacts-final.json`, `public-url-checks.json`, `cleanup-tests.log`. 이 파일들은 개발자 로컬 감사 폴더에 보관하며 개인 로컬 경로가 든 원본 기록을 공개 저장소에 올리지 않는다.
