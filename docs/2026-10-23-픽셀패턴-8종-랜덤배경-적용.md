## 제작과 최적화

- 소품을 참조한 픽셀아트 제작은 imagegen으로 진행했다. 생성 프롬프트와 입력 파일 목록은 `sources.json`에 기록했다.
- 최종 제작 PNG 8종은 `raw/`에 별도로 보존했다. 4번은 첫 생성물의 가장자리 소품 잘림을 확인해 다시 제작했다.
- 전달용 이미지만 512×512, 최근접 리사이즈, 64색 팔레트, 투명 WebP로 최적화했다. WebP 인코딩은 무손실이며, 제작 PNG와 비교하면 해상도와 색상 수는 줄어든다.
- 배경은 512px 단위로 반복하고 불투명도 12%로 표시한다. 흰색 본문 카드·입력창·모달 등 기존 UI 표면은 유지한다.
- 생성물과 검사 기록: `outputs/chida-pattern-assets/2026-10-23/pixel-backgrounds-v1/`. 이 위치는 프로젝트 상위 작업 폴더 기준이며, 앱 배포에는 포함하지 않는다.

## 표시 방식

`pattern-background.js`가 문서를 열 때 1~8 중 하나를 고르고, `pattern-background.css`가 해당 로컬 이미지를 반복 배경으로 표시한다. 한 문서에서는 선택된 배경만 사용한다. 8장을 미리 다운로드하는 코드나 애니메이션은 없다.

페이지를 새로 열거나 새로고침하면 다시 선택한다. 무작위이므로 직전과 같은 배경이 나올 수도 있다. 앱의 작업 단계·VOD를 바꾸거나 매뉴얼 안에서 검색·이동할 때에는 배경을 다시 선택하지 않는다. 앱과 매뉴얼의 선택은 서로 독립적이다.

## 변경 파일과 적용 범위

- 앱: `web/pattern-background.js`, `web/pattern-background.css`, `web/patterns/` 및 `web/index.html` 연결.
- 서버: `archive/server.py`의 정적 허용 목록에 CSS·JS와 정확한 이미지 8개만 추가.
- 매뉴얼: 생성 스크립트 `scripts/build.py`와 생성 HTML에 CSS·JS 연결, 배포 폴더에 `patterns/` 추가.
- 앱과 매뉴얼의 GitHub용 로컬 체크아웃에도 같은 파일을 반영했다. 매뉴얼 체크아웃의 루트 출력 방식은 유지했다.
- GitHub 커밋·푸시, 공개 사이트 게시, 앱 패키징은 이번 작업에서 진행하지 않았다. 이미 설치된 앱과 공개 매뉴얼은 별도 배포 전까지 기존 상태다.

## 기존 기능 영향과 예외 처리

- VOD 원본, 채팅, 전사, 화자 배정, 분석 결과와 AI 처리 코드는 변경하지 않았다. 검증 과정에서 다운로드·전사·분석 작업도 실행하지 않았다.
- 루프백 바인딩, 임의 경로 접두사, Host·Origin 검사와 CSP는 유지했다. 서버에 폴더 전체 공개나 새로운 외부 연결은 추가하지 않았다.
- 장식 레이어는 `pointer-events: none`으로 클릭을 가로채지 않는다. 화면 배치에 공간을 차지하지 않는다.
- 인쇄와 강제 고대비 모드에서는 장식을 숨긴다. 스크린리더에 새로운 설명 요소를 추가하지 않는다.
- 이미지·스크립트가 누락되거나 WebP를 표시하지 못하면 기존 단색 배경을 사용한다. 다운로드·분석 제어와는 독립적이다.
- 매뉴얼을 옮길 때에는 HTML뿐 아니라 CSS·JS·`patterns/`·`screenshots/`도 함께 옮겨야 한다.
- 배경을 바꾸기 위해 작업 중 새로고침을 강제하지 않는다. 새로고침 시 UI 상태 처리는 기존 앱 동작을 따른다.

자동 검사는 특정 원본 VOD나 사용자 자료에 의존하지 않는다. 전체 다운로드·분석 회귀 검사와 Windows 실기 검증은 이번 변경 범위에서 하지 않았다. 선택한 한 장만 사용하는지는 CSS 선택 구조로 확인했으며, 브라우저 네트워크 전송량을 별도 실측하지는 않았다.

로컬 매뉴얼과 8종 갤러리의 `file://` 열기는 내부 브라우저의 URL 정책으로 거절되어 우회하지 않았다. 해당 HTML은 정적 정합성 검사까지 완료했고, 매뉴얼 전체의 실제 렌더링은 이번 작업에서 확인하지 못했다. 앱은 기존 인증 경로를 사용하는 루프백 화면으로 확인했다.
