# 0.19.0 GitHub 업로드와 OS별 빌드

작성일: 2026-10-20

## 범위

현재까지 완료한 VOD 리스트 통합, 완료 단계 재사용, 내장 임시 채팅 DB 복구, 별도 화자 실행 도구 설치, 전사·화자 결과 분리, 검토 탭, 확대 시간축, 방송 배경 설명, 정상·실패 문맥 참고 표시와 버튼 글자 클릭 보강을 배포 소스에 반영한다.

- 저장소: https://github.com/redpanya/Chi_Da_analyzer (공개).
- 앱 버전: 0.19.0. 새 리포트·화면·조립·검사 기대 버전을 통일한다.
- macOS Apple Silicon / Windows x64 CPU+Vulkan 선택형을 각 OS 러너에서 빌드한다. Intel Mac, DMG는 생성하지 않는다.
- 새 실행 파일은 초안 릴리스로 준비한다. 기존 공개 릴리스·자산은 교체하지 않는다.
- 영상·채팅·전사·모델·수동 배정·개인 로그·인증 파일은 업로드하거나 재생성하지 않는다.

## 영향·예외

- 새 앱을 실행해도 기존 설정·모델·보관함 경로를 이동하지 않는다. 제거된 신규 로컬 영상 입력은 410이며 기존 자료 열람은 유지한다.
- 배경 설명이 없는 과거 요약의 이어받기 지문은 유지한다. 실패 요약을 성공으로 바꾸지 않는다.
- macOS는 임시 서명이며 Developer ID 서명·Apple 공증은 없다. Windows Authenticode 서명도 없다.
- FluidAudio는 Apple Silicon 전용이다. Windows 별도 화자 실행 도구는 아직 미게시이며 파일이 없으면 앱에서 미배포 안내를 표시한다. 기본 sherpa 실행기는 앱에 포함한다.
- 실제 모델 추론·긴 VOD·Windows GPU 성능·Safari 탐색 문제는 CI 통과와 구분한다.

## 검사 기준

1. 정확히 업로드할 저장소 사본에서 영향 범위 Python·JavaScript 검사를 수행한다.
2. 두 OS에서 잠금·한글 경로·미디어 복구·원음 추출·리포트·새 API/정적 파일을 확인한다.
3. macOS ZIP의 서명·해제·실행, Windows의 기본 실행과 CPU/Vulkan 도구 포함을 검사한다.
4. 두 빌드가 통과한 동일 커밋의 ZIP·대응 소스·검사 JSON·체크섬을 초안에 모은다.

## 진행 결과

- 최신 제품 소스와 신규 모듈을 배포 사본에 반영했다. 로컬 자료 경로가 포함된 개인 진단 JSON은 추가하지 않았다.

- JavaScript 검사 프로그램 14개 통과. 시간축·화자 검토·전사·문맥 참고·댓글 선택·도구 상태·기존 자료 보존을 포함한다.

### 공개 경로 재검사

첫 푸시는 자동 승인 검토에서 개인 경로 노출 가능성으로 차단되어 원격에 전송되지 않았다. 변경 파일 외에 기존 추적 문서 전체까지 검사해 과거 macOS 진단 문서의 실제 다운로드 경로도 일반 표기로 치환했다. `/Volumes/external`, `/Volumes/chzzk-연결안됨-검증`, `/Users/개인`은 경로 처리·개인정보 제외를 검사하는 합성 테스트 값이며 실제 사용자 경로가 아니다. 인증 문자열과 실제 사용자 홈·볼륨 이름이 없는지 다시 확인했다.

### 첫 CI와 보완

- 첫 [Actions 실행 39402277056](https://github.com/redpanya/Chi_Da_analyzer/actions/runs/39402277056)에서 Windows의 화자 취소·잠금 검사가 설치 도구 없음으로 실패했다. 제품의 미설치 차단은 정상 동작이었고, 검사 코드가 개발 장치의 기존 설치에 의존한 것이 원인이었다.
- 해당 검사의 엔진 준비 상태를 명시적으로 모의 처리했다. 실제 엔진 없이 취소·잠금·이전 결과 보존을 검사하며 제품의 설치 확인은 그대로 유지했다. 로컬 화자 검사 11개 재통과.

- macOS 첫 실행도 동일한 검사 환경 의존성 실패로 확인했다.
- PowerShell에서 여러 외부 명령 중 앞선 실패가 마지막 성공으로 가려지지 않도록 `check_source.py`가 Python·Node 검사를 순서대로 실행하고 실패 코드를 전달한다. 새 실행기도 로컬에서 통과했다.

- 두 번째 [Actions 실행 39402849167](https://github.com/redpanya/Chi_Da_analyzer/actions/runs/39402849167)에서 macOS 소스 검사는 통과했으나 Windows 화자 취소 검사의 고정 5초 대기가 먼저 만료되어 잠금 검사가 실패했다. 작업 시작 응답의 사양 수집 소요 시간과 경합하므로, 검사 작업은 명시적인 중단 신호까지 유지하고 `finally`에서 종료하도록 수정했다. 제품 잠금 로직은 변경하지 않았다. 단독 회귀 검사 재통과.

### OS별 확인

- Windows: Python 75개 모두 통과(36.968초), Node 검사 9개 통과. CI의 UTF-8 강제 설정을 끈 cp1252 환경에서도 한글·공백 경로와 다국어 미디어 제목 처리 통과. Windows 잠금·Job Object 종료 검사 포함.
- macOS: 같은 소스 검사에서 Windows 전용 검사는 제외. 새 웹 모듈들이 동결 패키지에서도 HTTP 200으로 제공됨. `ditto`·`unzip` 해제 후 서명 유지, 영문 앱 경로, LaunchServices 실행과 HTTP 응답 통과.
- 양쪽 패키지: H.264/AAC 생성·읽기·디코딩, 원음 정보/추출 API, 수신 후 검증 재개, 시간축 시작 오프셋 복구, 기존 채팅 응답 재사용(네트워크 요청 0회), 원본·기존 파일 보존, 순차 작업 초기 상태, VOD 번호 포함 리포트, 구형 리포트 보존, 이메일 안내·자동 업로드 API 410 확인.

### 남은 제한

- macOS는 임시 서명이다. 실제 CI Gatekeeper 판정은 `rejected`이며 Apple 공증은 없다. 인터넷에서 내려받은 앱의 첫 실행이 모든 Mac에서 허용된다는 의미가 아니다. Windows Authenticode 서명도 없다.
- Windows 러너에는 Vulkan 드라이버가 없어 CPU 경로로 검사했다. GPU 실행기 포함과 설정 변경은 확인했지만 GPU 추론·속도는 실측하지 않았다.
- 실제 VOD 전체 다운로드·장시간 전사·화자 분리·Gemma 요약, 외장 디스크 실물, Safari의 탐색 재생은 이번 CI에서 재검증하지 않았다.
- Windows용 별도 sherpa·pyannote 설치 ZIP은 미게시 상태 그대로다. 기본 앱의 sherpa는 사용할 수 있고, 추가 실행 도구는 별도 배포가 필요하다. FluidAudio는 macOS Apple Silicon 전용이다.
- 모델·사용자 영상·채팅·전사·수동 배정·요약·인증 자료는 추가 업로드·삭제·재생성하지 않았다. DMG는 생성하지 않았다.

향후 빌드: Actions → 앱 빌드 → Run workflow. `draft_tag`를 비우면 OS별 아티팩트만 만들며, 새 태그를 입력하면 양 OS 성공 후 새 초안 릴리스를 만든다. 기존 릴리스 태그를 재사용하거나 자산을 덮어쓰지 않는다.
