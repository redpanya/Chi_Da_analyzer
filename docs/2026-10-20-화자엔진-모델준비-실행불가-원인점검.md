# 화자 엔진 변경 후 모델 준비가 진행되지 않는 원인

작성일: 2026-10-20
대상: 실행 중인 macOS 0.18.3 기본 앱 패키지
범위: 원인 점검·문서 기록. 제품 수정·모델 재다운로드·분석·빌드 없음.

## 결론

**모델 파일은 준비되어 있지만 pyannote와 FluidAudio 실행기가 현재 앱 패키지에 없다.** 선택 버튼의 요청은 정상 전달되며, 준비 작업이 시작 직후 실행기 검사에서 실패한다. 이번 현상은 Safari 재생 문제와 별개이고, 확인된 실패는 HF 인증이나 모델 다운로드 단계 이전에 발생했다.

현재 앱의 읽기 전용 `voices-result` 응답:

| 엔진 | 모델 준비 `ready` | 실행기 `engine` | 장치 지원 `supported` | 실제 사용 조건 |
| --- | --- | --- | --- | --- |
| sherpa-onnx | 참 | 참 | 참 | 엔진·모델 준비됨. 분석에는 현재 전사 등 별도 입력 조건 필요 |
| pyannote.audio + Community-1 | 참 | 거짓 | 참 | 모델은 있지만 앱에서 실행 불가 |
| FluidAudio + Community-1 계열 | 참 | 거짓 | 참 | 모델은 있지만 앱에서 실행 불가 |

`supported`는 운영체제·장치가 지원 대상이라는 뜻이다. 패키지에 해당 실행기가 실제 설치됐다는 뜻은 아니다.

## 실제 실패 기록

VOD 15655103의 기존 `voices/state.json`에서 다음을 확인했다.

- 요청: `action=prepare`, `backend=fluid`
- 결과: `state=error`
- 메시지: “기본 배포본에는 sherpa 실행기가 포함됩니다. 다른 엔진은 개발용 별도 설치가 필요합니다.”
- 실행 시간: **42ms**
- 기록 시각: 2026-10-20 15:42:34 KST
- 진행 수치: 빈 객체

이 기록은 사용자가 실행했던 요청을 읽은 것이다. 점검 중 준비 버튼을 다시 실행하거나 VOD 상태를 변경하지 않았다. 종료가 매우 빨라 화면에서 진행 중 상태가 보이지 않고, 기존 상태 조회 시 이미 오류로 나타날 수 있다.

## 코드와 패키지 대조

1. `web/voices.js`의 준비 버튼은 선택한 `backend`를 포함해 `voices-start`에 `action=prepare`를 전달한다. 기존 UI 검사에서도 pyannote 선택 값 전달이 확인된다.
2. `archive/jobs.py`의 `voices_start()`는 엔진 식별자·장치 지원을 확인한 후 작업을 시작한다. 실행기 파일 존재 여부는 이 단계에서 차단하지 않는다.
3. `archive/diarization_run.py`의 `prepare()`는 sherpa 외 엔진에서 `supported`와 `engine`을 확인한다. 실행기가 없으면 모델 검사·다운로드 전에 설치 안내 오류로 종료한다.
4. `web/voices.js`의 `controls()`는 준비 버튼을 작업 잠금·장치 미지원일 때 비활성화하지만, `engine=false`만으로는 비활성화하지 않는다. 실제 준비를 수행할 수 없는 선택에서도 버튼이 활성화되어 혼동을 준다. 전체 화자 분석 버튼은 `engine` 조건으로 차단된다.
5. `packaging/release/assemble.py`는 `basic-release.json`을 `{\"speakers\":[\"sherpa\"]}`로 기록하며, 추가 화자 실행기를 패키지에 복사하지 않는다. 실제 0.18.3 앱에도 이 선언과 동일하게 pyannote·FluidAudio 실행기가 없다.
6. `archive/diarization_backends.py`의 `executable()`은 패키지 실행 시 앱 리소스 아래 `diarization/pyannote/pyannote-worker` 또는 `diarization/fluid/archive-fluid-diarizer`를 찾는다. 소스 실행 때 사용하는 `.diarization-tools` 경로는 패키지에서 사용하지 않는다.

이 Mac의 개발 폴더에는 pyannote Python 환경과 FluidAudio 실행기가 남아 있다. 하지만 현재 앱은 그 경로를 탐색하지 않는다. 따라서 개발용 설치 스크립트를 다시 실행하거나 AI 모델 폴더 경로를 바꾸는 것만으로 현재 앱의 문제가 해결되지는 않는다.

현재 `voices.js`와 `voice-model-help.js`는 0.18.3 패키지와 개발 소스가 바이트 단위로 같았다. 오래된 화면 파일 하나 때문에 선택값이 잘못 전달되는 현상이라는 증거는 없다.

## 수정 방향과 영향

제품 수정은 아직 하지 않았다.

- **실제 기능 제공:** 다른 엔진을 앱에 포함하거나, 앱 밖에서 별도로 설치한 실행기를 앱이 인식하고 사용할 경로를 구현해야 한다. 모델 다운로드 버튼만으로 엔진 설치를 대신할 수는 없다.
- **UI 상태 구분:** “모델 준비 완료 / 실행 도구 없음”을 구분하고, 도구가 없으면 준비 버튼 대신 실행 도구 설치 안내를 제공해야 한다. 요청 시작 전에도 같은 조건을 검증하여 즉시 실패하는 작업 기록을 불필요하게 생성하지 않도록 한다.
- **일반성:** macOS·Windows의 실제 실행 가능 조건을 기반으로 처리하고, 특정 VOD·사용자 경로나 개발 환경을 하드코딩하지 않는다.
- **기존 자료:** 기존 모델 폴더, 화자 결과·이름·수동 배정, 전사·문맥 결과를 옮기거나 지울 필요가 없다.
- **부작용·예외:** 실행기를 함께 포함하면 패키지 크기가 증가한다. 외부 설치 방식은 엔진 버전·운영체제·아키텍처 적합성과 설치 실패·부분 설치를 다뤄야 한다. 준비된 모델을 이미 보유한 사용자에게 불필요한 HF 재로그인이나 재다운로드를 요구하지 않는다.

## 점검 및 미검증 범위

- 실행 중인 앱의 엔진별 준비 상태 조회, 실제 사용자 실패 기록, 앱 패키지의 실행기 존재 여부, 제품 코드 경로를 대조했다.
- 기존 `tests/test_voices_ui.mjs`, `tests/test_voice_model_help.mjs` 통과. 이 검사들은 정상 선택값·안내 동작을 확인하며, 추가 실행기를 포함하지 않은 배포본에서 준비 성공까지 보장하지는 않는다.
- 모델 다운로드, 실제 화자 추론, HF 로그인 검사, 별도 엔진 설치, 제품 코드 수정, 패키징은 실행하지 않았다.
- 원본·전사·수동 화자 배정·기존 분석 결과는 변경하지 않았다.
