# 문맥 목록 구간 재생 멈춤 원인 점검

작성일: 2026-10-19 · 범위: macOS 0.18.3 원인 점검, 제품 수정·빌드 없음

갱신일: 2026-10-20 · 사용자의 Safari/Chrome 비교 결과 반영

## 결론

사용자가 설명한 증상은 **시각은 이동하지만 화면·소리가 멈춤**이다. 구간 재생은 브라우저의 `currentTime`을 먼저 바꾸므로, 표시 시각의 이동은 실제 영상 데이터 준비·재생 성공을 뜻하지 않는다.

현재 제품의 `web/player.js`를 그대로 사용하는 별도 합성 영상에서 **영상 데이터 전달 지연 시 같은 외형의 증상**을 재현했다. `seeking=true`, `readyState=1`, `waiting`·`stalled` 이벤트가 발생했지만 UI에는 “선택한 시각으로 이동했습니다.”만 남았다. 약 12초 뒤 데이터가 도착하자 재생됐다. 이 대기를 식별하는 표시·시간 제한·복구 동작이 없다.

추가로 일시 파일 응답 오류 후 **재클릭으로 복구되지 않는 동작**을 재현했다. 오류가 남은 영상에 대해 `seek()`가 즉시 반환하고, 같은 파일 주소이면 화면 갱신도 다시 로드하지 않기 때문이다. 동일 합성 파일을 명시적으로 재로드하자 재생됐다.

다만 **사용자의 실제 실패 순간은 포착하지 못했다.** 그 순간의 원인이 외장 저장장치 지연, 브라우저 탐색·디코딩, 파일 응답 중단 중 무엇인지는 확정할 수 없다. 외장 디스크 불량·원본 손상·문맥 시각 오류로 단정하지 않는다. 위 재현은 제품의 대기 안내와 오류 복구 결함을 입증하며, 과거 사건의 최초 원인을 확정하는 것은 아니다.

## 2026-10-20 사용자 추가 확인

- 사용자가 **Safari에서만 발생하고 Chrome에서는 정상**이라고 확인했다. 에이전트가 두 브라우저에서 직접 재현한 결과와 구분한다.
- 이 비교로 Safari와 현재 플레이어·영상 전달 방식 사이의 호환성을 우선 조사할 근거가 생겼다. 같은 자료의 Chrome 정상 재생은 영상 자체가 일관되게 재생 불가능한 상황일 가능성을 낮추지만, 모든 파일·서버 문제를 배제하지는 않는다.
- 우선 비교할 대상은 같은 파일·같은 구간에서 `seeking` → `seeked` → `playing`의 진행 여부, `play()`의 실패 사유, 실제 프레임·시간 진행, Range 응답 및 대기 시간이다. 자동 재생 차단이나 Safari 자체 결함으로 아직 단정하지 않는다.
- 후속 수정은 Safari 이름에 따른 임의 지연·무조건 재로드가 아니라 실제 미디어 상태에 따른 공용 대기·복구 처리로 진행한다. Chrome 정상 동작, 사용자 일시정지, 연속 구간 선택을 함께 보존해야 한다.
- 임시 사용은 사용자가 정상 동작을 확인한 Chrome으로 가능하다. 이번 추가 작업은 진단 문서 갱신만 수행했으며 제품 수정·브라우저 추가 검사·빌드는 하지 않았다.

## 현재 처리 흐름과 확인된 결함

1. `web/context.js:30–31`: 문맥 버튼은 `player.seek(start, true, end)`를 호출하고 즉시 구간 안내를 표시한다. 재생 성공 여부는 반환받지 않는다.
2. `web/player.js:33–42`: 길이가 유효하면 대기 요청을 지우고 `pause()` → `currentTime` 지정 → `play()` 순서로 처리한다. 안내는 실제 `playing` 전에 갱신된다.
3. `web/player.js:55–61`: `timeupdate`, `loadedmetadata`, `error` 등은 처리하지만 `waiting`, `stalled`, `seeking`, `seeked`, `playing` 상태에 따른 대기 안내·재시도는 없다.
4. `web/player.js:30–31`: `play()` 실패의 오류 이름·내용을 버리고 동일 문구만 표시한다. 요청 취소, 자동 재생 거부, 미디어 오류의 구분이 안 된다.
5. `web/player.js:47–49`: `video.error`가 남으면 재클릭해도 종료한다. `web/app.js`의 `render()`도 URL이 같으면 `src`를 새로 설정하거나 `load()`하지 않는다. 일시 오류가 해소되어도 기존 오류 상태가 지속될 수 있다.

`currentTime` 지정 직후 `play()`하는 것 자체가 잘못된 것은 아니다. 이번 메타데이터 지연 조건에서도 브라우저가 정상 대기 후 재생했다. 따라서 무조건 `seeked` 뒤로 `play()`를 옮기는 것만으로 해결됐다고 판단하면 안 된다. 동일 시각 재클릭, 처음 로딩, 사용자가 직접 누른 일시정지, 빠른 연속 선택을 함께 고려해야 한다.

## 실제 앱 확인

- 실행 중 앱: macOS arm64 0.18.3. 내부 브라우저에서 해당 앱 서버에 연결해 점검했다. 당시 사용자가 현상을 겪은 브라우저는 미확인이었고, 2026-10-20 사용자가 Safari라고 추가 확인했다.
- 소스의 `player.js`, `context.js`, `app.js`가 0.18.3 앱 번들의 파일과 바이트 단위로 동일함을 확인했다.
- VOD 15655103, 영상 길이 49,940.437초, 문맥 756개가 표시된 결과를 사용했다. 새 분석은 시작하지 않았다.
- 문맥 시작 00:01:21, 중간 06:45:39, 끝 13:52:01에서 재생이 시작되는 것을 확인했다. 끝에서 앞쪽 00:02:35로 돌아온 후에도 재생되어 00:03:02.560의 구간 끝 정지까지 확인했다. 이것은 일부 구간의 확인이며 13시간 전체 디코딩 검사는 아니다.
- 영상 파일 앞·중간·끝의 1,024바이트 Range 요청은 모두 HTTP 206 및 올바른 Content-Range를 반환했다. 응답 시간은 각각 약 39ms, 11ms, 5ms였다. 지속 부하나 디스크 절전 후의 응답은 측정하지 않았다.
- 실행기 로그에 해당 재생 오류가 없었지만, 서버가 일반 요청 로그를 남기지 않고 플레이어도 상세 오류를 보존하지 않으므로, 로그가 조용하다는 사실을 오류 부재의 증거로 사용하지 않는다.

## 분리한 재현 검사

실제 VOD 대신 직접 생성한 30초 H.264/AAC 영상을 사용했다. 제품 `player.js`는 수정하지 않고 그대로 불러왔다. 진단 화면만 미디어 이벤트와 `play()`의 성공·실패를 기록했다. 임시 서버는 루프백에만 바인딩했다.

| 조건 | 관측 | 해석 |
| --- | --- | --- |
| 메타데이터 응답 8초 지연 후 재생 | 5초로 이동, `waiting` → `seeked` → `playing` → 10초 구간 끝 정지 | 이번 내부 브라우저에서는 초기 로딩 지연만으로 영구 실패하지 않음. 자동 재생 정책 차단은 재현되지 않음 |
| 메타데이터 이후 영상 본문 12초 지연, 20초 구간 클릭 | 시각 20초, `paused=false`, `seeking=true`, `readyState=1`, `waiting`·`stalled`. UI는 이동 완료 문구 유지 | 재생 버튼 표시·이동 시각만으로 실제 프레임 재생 성공을 판단할 수 없음 |

## 후속 수정 방향과 주의점

제품 수정은 이번 요청 범위에 포함하지 않았다. 후속 수정에서는 다음을 공용 플레이어 단위로 처리해야 한다.

1. 이동 요청, 탐색 중, 데이터 대기, 실제 재생 시작, 구간 종료, 오류 상태를 구분한다. 실제 성공은 `playing`과 재생 위치 진행으로 확인한다.
2. 마지막 구간 선택을 보존하고 이전 요청의 늦은 실패가 새 요청의 안내를 덮지 못하게 한다. 사용자가 직접 일시정지하거나 다른 메뉴·VOD로 이동한 경우 자동 재생 의도를 폐기한다.
3. 짧은 버퍼링 동안에는 재로드하지 않는다. 오래 지속되는 대기·복구 가능한 파일 오류에서는 제한된 재시도 또는 명시적인 “영상 다시 불러오기”를 제공한다. 무한 재시도, 주기적 `render()` 때마다 재로드하는 방식은 피한다.
4. 원본 파일은 변경하지 않고 플레이어 연결만 다시 만든다. 재로드 후 선택 시작·끝 범위와 배속은 유지하되, 범위를 벗어난 값·끝 지점·동일 시각 재선택을 안전하게 처리한다.
5. 구간 자동 정지는 탐색 중의 중간 상태와 실제 재생을 구분해야 한다. 통합 분석·전사·화자 화면도 공용 플레이어를 사용하므로 기존 시각 이동과 일시정지를 회귀 검증한다.
6. 진단에는 오류 코드, 대기 시간, 재생 준비 상태, 선택·실제 시각 정도만 남긴다. 로컬 접근 토큰·전체 파일 경로·채팅/전사 본문은 기록하지 않는다.

검증 기준은 정상·초기 로딩·먼 시각 탐색·느린 응답·일시 오류 후 회복·빠른 연속 클릭·재생 중 메뉴 이동·수동 일시정지·파일 미존재·구간 끝 정지이다. 합성 조건과 실제 여러 VOD 확인을 구분해 기록하며 특정 VOD 번호나 문맥 제목에 대한 예외를 추가하지 않는다.

## 보존 범위

제품 소스·패키지·영상·채팅·전사·화자 배정·문맥 결과에 수정 명령을 실행하지 않았다. 점검용 문서와 합성 진단 자료만 추가했다. 실제 VOD에 대한 브라우저 조회와 재생만 수행했으며, 선택 상태 같은 탭 내부 UI 상태는 바뀔 수 있다. 임시 진단 서버와 이번 점검에서 만든 브라우저 탭은 종료했다. 실행 중인 사용자 앱은 종료하지 않았다.
