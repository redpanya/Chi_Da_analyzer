# VOD 리스트 등록 통합 구현·검증

작성일: 2026-10-18
상태: **구현 완료 · macOS 회귀/화면 검사 완료 · 개발 앱 실행 · 패키징/업로드 없음**

후속 요청에 따라 macOS 0.18.3 앱 패키지를 별도로 만들었다. [패키징 기록](2026-10-18-macOS-0.18.3-패키징.md)을 참조한다. 아래 구현·검사 기록은 패키징 전 작업의 결과다.

기준 설계: [VOD 리스트 등록 기본 흐름 통합 설계](2026-10-18-VOD리스트등록-기본흐름-통합설계.md)

## 사용자 동작

1. 가져오기의 **VOD 리스트 등록**에 주소를 입력하거나 **저장한 VOD 선택**에서 복수 선택한다. 사이드바의 **목록 등록** 버튼도 사용할 수 있다.
2. 등록할 자료의 ↑·↓로 순서를 정하고 진행 범위를 선택한 뒤 **목록에 등록**한다. 저장한 VOD는 치지직 서버에서 정보를 다시 조회하지 않는다.
3. **순차 작업 시작·이어가기**를 누른다. 각 VOD의 필요한 단계만 처리한 뒤 다음 VOD로 넘어간다. 등록 자체는 작업을 시작하지 않는다.

초기 진행 범위는 기존처럼 `영상·채팅 다운로드만`이다. 이미 다운로드한 VOD를 분석하려면 `다운로드부터 AI 요약까지`로 등록한다. 기존 대기 항목은 각 행에 표시된 설정을 계속 사용한다.

## 반영 내용

- 온라인 단일 주소의 `정보 확인 → 다운로드 시작` 폼을 제거하고 주소 한 개/여러 개를 같은 등록 경로로 통합했다.
- 저장 VOD 선택창에 제목·번호·영상/채팅/전사/요약 상태를 표시한다. 선택 순서를 유지하며 등록 전 새 주소와 순서를 바꿀 수 있다.
- 사이드바 제목은 기존 VOD 열기, 별도 `목록 등록` 버튼은 등록 전 선택이다. 버튼을 중첩하지 않는다.
- 미실행 대기 항목만 선택해서 현재 처리 설정을 적용할 수 있다. 실행 이력·리포트가 생긴 항목은 기존 설정으로 이어간다. 화질은 최초 등록된 프로젝트 값을 유지하며 이미 받은 영상을 교체하지 않는다.
- 완료된 다운로드 항목이 목록에 남아 있어도 후속 분석을 새 항목으로 등록할 수 있다. 새 작업 ID·새 리포트를 사용하고 이전 이력을 유지한다.
- 같은 보관함·VOD의 미완료 항목은 URL/단축 주소/저장 선택 경로와 무관하게 중복을 막는다.
- 일부 주소/저장 항목의 등록 실패는 성공 항목을 취소하지 않는다. 실패한 입력만 화면에 남는다.
- 보관함 변경 시 저장 VOD 선택·대기 설정 체크를 지우고 해당 보관함의 목록을 다시 읽는다. 실행/등록/첨부 중 보관함 입력은 잠근다.
- `내 비디오 사용`은 별도 영역으로 유지한다. 파일·연결할 VOD 주소·시작 시각을 입력하고 `비디오 가져오기`를 누르면 정보 확인 후 기존 조각 복사·검증을 진행한다.
- 명칭과 사용 순서, 설정 적용 범위는 기존 💡 도움말을 갱신했다. 오류와 진행 상태는 화면에 남는다.

## 완료 자료 확인과 보존

영상·채팅 준비 단계에서 다음을 실행한다.

| 보유 상태 | 처리 |
| --- | --- |
| 유효한 영상·채팅 완료 | 다운로드 작업자를 호출하지 않고 `기존 자료 사용`으로 기록 |
| 영상 완료·채팅 미완료 | 채팅만 시작. 기존 저장 페이지·경계 응답을 기존 복구기에서 재사용 |
| 영상 검증 정보 미완료 | 완료 표시만 신뢰하지 않고 기존 검사/복구기로 연결 |
| 채팅 `review` | `일부 자료도 분석` 옵션이 켜지고 결과 파일이 있을 때만 사용. `일부 완료` 유지 |
| 로컬 비디오 완료 | 첨부 파일을 재사용하고 필요한 채팅/후속 단계 진행 |
| 로컬 비디오 미완료 | 같은 파일 재첨부 안내. 온라인 영상으로 자동 대체하지 않음 |
| 원본이 검사 기록과 다름 | 기존 파일을 보존하고 오류 표시. 덮어쓰기·자동 교체하지 않음 |

새 영상 검사 결과에는 원본/재생본의 파일 식별 정보(경로·크기·수정 시각)를 추가한다. 완료 기록과 실제 파일을 실행 직전에 확인한다.

구버전 결과에는 이 정보가 없을 수 있다. 이때 기존 원본 SHA-256을 대조하고, 별도 재생본이면 기존 패킷 시간축 검사와 디코딩 검사를 사용한다. 일치한 결과는 `diagnostics/automation-media.json`에 별도 저장하므로 기존 검사 결과를 덮어쓰지 않는다. **구버전의 첫 재사용은 추가 검사 시간이 걸릴 수 있다.** 파일 식별 정보가 그대로이면 이후에는 이 확인을 재사용한다. 전제는 앱이 관리하는 로컬 검사 기록이며 악의적인 파일/기록 동시 변조를 탐지하는 보안 기능은 아니다.

이후 원음·전사·선택 화자·반응·요약 단계는 기존 입력/옵션 일치 판정을 사용한다. 기존 수동 교정·화자 배정·결과 버전을 삭제하지 않는다. 설정이 다르면 기존 결과를 보존하는 버전 생성 규칙을 그대로 따른다. 모델 설치·HF 동의를 자동 실행하지 않는다.

기존 `.automation/queue.json` 버전 1을 유지하고 표시용 필드만 선택적으로 추가했다. 기존 큐를 초기화하지 않는다. 앱 재실행 후에도 사용자가 이어가기를 눌러야 한다. 목록 제거는 VOD 파일이나 리포트 삭제가 아니다. 내장 임시 채팅 DB 처리, loopback 주소/요청 보호, 단일 실행 잠금은 유지했다.

## macOS 검증 결과

### 자동 검사

- Python: 총 53개 중 **52개 통과**, Windows 읽기 스레드 전용 **1개 제외**.
  - `test_queue_registration`, `test_automation_reports`, `test_local_import`, `test_import_recovery`, `test_video`, `test_media_probe`: 50개 중 49개 통과, 1개 제외.
  - `test_server_assets`: 3개 통과. 신규 JS를 포함한 웹 모듈 제공 확인.
- JavaScript: `test_local_import_ui.mjs`, `test_reports_ui.mjs`, `test_speech_ui.mjs` 모두 통과.
- 변경 JS 문법 검사 및 `git diff --check` 통과.

신규 목록 검사는 네트워크/모델/실사용 보관함을 사용하지 않는 임시 자료로 수행했다. 오프라인 등록, 선택 순서, 일부 실패, 중복, 완료 후 새 보고서, 다운로드 작업자 미호출, 채팅 단독 복구, 영상 재검사 연결, 로컬 미완료 차단, 원본 변경 탐지·보존, `review` 정책, 설정 경합/이력 보호, 경로/연결 파일 거부, 검사 취소를 확인했다.

로컬 첨부 UI 검사는 내부 정보 확인→복사 순서, 이미 복사한 조각 확인, 메타데이터 확인 실패 시 복사 차단과 입력 복구를 확인했다. 후속 분석 전체 흐름은 기존 모의 엔진 통합 검사로 확인했으며 실제 AI 모델을 다시 실행한 결과는 아니다.

### 내부 브라우저

실제 사용자 자료와 분리된 1초 합성 영상 3개의 임시 보관함에서 확인했다.

- 저장 선택창에서 1번→3번 선택 후 같은 순서로 등록.
- 한 대기 항목만 AI 요약 설정으로 변경. 다른 항목의 다운로드 설정 유지.
- 두 항목을 다운로드 범위로 순차 실행하여 둘 다 `영상·전체 채팅: 기존 자료 사용`으로 완료.
- 실행 중 보관함 입력·로컬 비디오 시작 잠금, 완료 후 해제.
- 완료 항목을 새 분석 항목으로 재등록해 이전 완료 이력과 함께 표시.
- 잘못된 주소와 저장 VOD를 함께 등록해 저장 VOD만 성공, 실패한 주소는 남음.
- 보관함을 바꾸면 등록 전 저장 선택이 사라지고 기존 보관함의 큐가 복원됨.
- 최종 소스로 다시 실행한 화면에서 기존 실제 큐가 그대로 보이며 사이드바 선택은 등록 전 상태에만 추가됨.

실제 보관함에서는 새 다운로드/전사/요약을 시작하거나 큐 항목을 변경하지 않았다. 개발 앱은 `127.0.0.1`의 새 임의 포트로 실행했으며 기존 패키지 앱을 교체하지 않았다. 사용자 확인용 내부 브라우저 탭을 열어두었다.

## 남은 확인과 주의점

- **Windows 실제 실행은 미검증**이다. 이번 패키징·배포도 수행하지 않았다.
- 장시간 실제 VOD의 새 다운로드부터 AI 요약까지 전 과정을 재실행하지 않았다. 신규 모델 추론 속도/품질 측정도 하지 않았다.
- 구버전 장시간 영상의 첫 추가 검사는 오래 걸릴 수 있다. 이후 같은 파일에는 재사용 캐시가 적용된다.
- 미완료 로컬 파일은 브라우저 파일 선택이 필요하므로 무인 첨부 대기열은 지원하지 않는다.
- 저장 시각·파일 유효성은 등록 시 예상과 실행 시 실제가 다를 수 있다. 디스크 분리·공간 부족·모델 미준비 시 기존 일시정지 정책을 따른다.
- 기본 범위/화질 선택을 바꾸는 것만으로 이미 등록된 항목은 바뀌지 않는다. 해당 체크박스와 설정 적용 버튼을 사용해야 한다.
