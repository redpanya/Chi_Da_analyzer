# 순차 다운로드·자동화·선택 제출 구현 결과

## 범위와 상태

소스 구현 및 macOS의 대상 검사를 진행했다. 빌드·패키징·GitHub 업로드·CI 실행은 하지 않았다. 기존 영상·채팅·전사·수동 교정·화자 배정·요약을 삭제하거나 일괄 재생성하지 않았다. 실제 보관함에 자동 작업을 등록하거나 실행하지 않았다.

수집 서버는 없다는 사용자의 확인에 따라 **앱 제출 기능과 운영자용 서버 코드까지 준비**했다. 실제 원격 수집 서버와 Google Drive는 연결하지 않았으며 전송은 기본 비활성화다. 외부 제출 성공을 검증했다고 볼 수 없다.

## 화면과 사용 순서

1. 가져오기 → **여러 VOD 순차 작업**에서 주소를 입력한다. ＋로 입력칸 추가, −로 입력칸 삭제.
2. 진행 범위(영상·채팅 다운로드만 / AI 요약까지), 최대 화질을 선택한다.
3. 자동 분석은 언어·발화 검출·용어 힌트·선택적 화자 구분·Gemma 사고 여부를 설정한다. 화자 구분은 기본 꺼짐이다.
4. **입력 순서대로 목록 등록**으로 주소를 하나씩 확인하고 순서를 저장한다. 등록 설정은 각 항목에 고정된다. 등록은 실행과 구분된다.
5. **순차 작업 시작·이어가기**를 누른다. 한 VOD의 선택 단계가 끝난 뒤 다음 VOD를 처리한다.
6. 상태·현재 단계·오류·완료 단계가 목록에 표시된다. **VOD 열기**로 기존 진행 게이지·전사·요약 결과를 확인한다.
7. **일시정지**는 현재 작업자의 파일 정리와 잠금 해제를 기다린다. 이후 개별 조치 또는 목록 이어가기를 선택한다.
8. 마지막 **7 리포트** 메뉴에서 선택한 VOD의 실행 기록과 처리량을 확인한다. 새로고침으로 최신 기록을 읽는다.

다중 입력은 치지직 다운로드 목록용이다. 기존 내 비디오 가져오기는 그대로 제공하며, 이미 내 비디오로 등록된 VOD를 온라인 목록에 덮어쓰지 않는다.

도움말은 제목 옆 💡에 넣었다. 상태·오류·제출 정보 및 동의 문구는 화면에 남긴다. 기존 데스크톱 배치를 유지한다.

## 실행 순서와 복구

`영상·전체 제공 채팅 다운로드/검증 → 원음 추출 → 원음 전사 → 화자 구분(선택) → 채팅 반응 분석 → Gemma 문맥 요약 → 다음 VOD`

- 말소리 분리·STEM 단계와 옵션을 추가하지 않았다.
- 같은 VOD의 영상·채팅 작업자는 기존 동시 수집을 사용한다. 다른 VOD나 AI 단계는 병렬로 시작하지 않는다.
- 기존 Manager 작업 API와 ProjectLock을 이용한다. 순차 작업 중 같은 실행기의 수동 작업·삭제·모델 설정 변경은 차단한다.
- 작업자가 닫히고 잠금을 놓은 뒤 다음 단계로 이동한다. 화면 새로고침은 작업 실행에 영향을 주지 않는다.
- 큐는 보관함의 `.automation/queue.json`에 원자적으로 저장하고 별도 잠금을 사용한다. 다른 실행기가 같은 큐를 편집/실행하는 것을 막는다.
- 앱이 종료되면 실행 항목을 재열기 때 일시정지로 표시한다. 앱을 켠 것만으로 자동 실행하지 않는다.
- 일반 작업 오류는 해당 VOD에 남기고 다음 VOD를 처리한다. 누락된 모델·도구, 저장 공간 문제는 목록 전체를 일시정지한다.
- 자동화가 모델 사용 조건이나 HF 인증을 승인하지 않는다. 각 메뉴에서 모델을 준비한 뒤 이어간다.
- 영상/채팅 이어받기는 기존 체크포인트와 파일 검증 로직을 사용한다. 동일 VOD의 원래 주소·단축 주소 중복을 막는다.
- 오디오 트랙이 여러 개면 임의 선택하지 않고 해당 VOD에 조치 필요를 표시한다. 기존 음성 전사 메뉴에서 트랙을 추출한 뒤 재시도할 수 있다.
- 기본은 검증 완료 채팅만 사용한다. **경계 검증이 필요한 일부 자료도 분석**을 선택했을 때만 `review` 상태의 저장 채팅을 사용한다. 오류 상태를 빈 채팅으로 바꾸지 않는다.
- 화자 작업 오류는 선택한 계속 진행 옵션에 따라 화자 불명으로 요약을 진행한다. 화자 모델 미준비는 일반 추론 실패와 구분해 전체 대기한다.
- 요약 일부 실패는 일부 완료로 남기고 다음 VOD로 넘어간다. 기존 요약의 개별 실패 표시를 유지한다.
- 반응 분석은 기존 동기 계산을 이용하므로 일시정지는 현재 반응 계산이 종료된 뒤 반영된다.
- 목록 최대 100개. 완료·오류 항목의 **목록에서 제거**는 큐 항목만 제거하며 VOD 파일을 삭제하지 않는다.

## 기존 결과 영향

| 자료 | 처리 |
|---|---|
| 영상·제공 채팅 | 기존 완료/검증 규칙으로 재사용 또는 이어받기. 원본 삭제 없음 |
| 원음 | 현재 영상과 일치하는 기존 WAV 형식·길이를 확인해 재사용 |
| 전사 | 현재 입력·언어·옵션에 맞는 완료 전사를 재사용. 새 전사는 기존 버전/교정 보존 정책 사용 |
| 수동 화자 배정 | 현재 전사와 연결된 화자 결과가 있으면 재사용. 자동화가 다른 엔진 선택만으로 수동 배정을 교체하지 않음 |
| 채팅 반응 | 현재 입력 결과면 재사용. 갱신 시 기존 analysis_store의 versions 보존 사용 |
| 요약 | 입력 지문·모델·방식·사고 설정에 맞는 완료 결과 재사용, 가능한 미완료 결과 이어가기, 새 요약은 기존 버전을 남김 |
| 리포트 | diagnostics/reports 아래 별도 JSON 이력. 기존 결과 파일에 리포트를 끼워 넣지 않음 |

설정과 입력의 호환성 때문에 기존 요약을 이어갈 수 없는 경우 해당 항목을 오류로 남긴다. 기존 결과를 삭제해 해결하지 않는다. 사용자가 개별 메뉴에서 새 요약을 진행할 수 있다.

## 리포트 내용과 계측 한계

- CPU 모델·물리 코어·논리 스레드, GPU 모델, RAM, OS/버전/아키텍처. macOS는 sysctl/system_profiler, Windows는 지정 CIM 필드만 조회한다. 컴퓨터 이름·장치 ID·일련번호를 조회하지 않는다.
- 앱 버전, 전사 모델·발화 검출·언어, 용어 힌트 문자 수(내용 제외), 화자 엔진, Gemma/사고 설정, 요청 장치 모드.
- 실제 사용 장치는 작업 상태에 명시된 경우만 기록한다. 감지된 GPU를 실제 사용 GPU로 추정하지 않는다. 미계측은 unknown/null이다.
- 단계별 실행 시간·상태·재사용/생략·정해진 실패 코드, 시작/종료 이벤트, 관찰된 진행 메시지와 로컬 오류 상세.
- 영상 길이, 전사 완료 범위·발언 수·문자 수, 채팅 수·문자 수, 요약 입력 후보 전사/채팅 문자 수.
- 기존 요약 계측 파일의 입력 평가·생성 시간/토큰, 요청 수, 체크포인트 재사용, 모델 로딩, 토큰 계산, 미계측 요청 수.
- 입력 후보 문자 수는 모델에 실제로 전송한 고유 토큰 수가 아니다. 토큰 계측은 해당 요약 실행 폴더 누적값이며 재시도를 포함한다. 입력 평가 토큰에는 캐시로 생략한 입력이 빠질 수 있다.
- 단계 벽시계 시간에는 준비·검증·파일 정리가 포함된다. 다운로드에는 네트워크 대기가 포함된다. 전사/화자 모델 로딩·순수 추론 시간을 별도로 분리했다고 주장하지 않는다.
- 이번 버전 이전의 누락된 시간은 복원/역산하지 않는다. 비정상 종료로 정확한 종료 시간을 모르는 단계는 중단·미계측으로 표시한다.
- 상세 진행 로그는 0.5초 간격으로 바뀐 상태를 관찰하므로 매우 짧은 중간 메시지는 빠질 수 있다. 실행 이벤트와 단계 실패는 별도로 기록한다. 로그의 최근 최대 1,500건을 유지한다.
- 진행 중 제출 미리보기는 그 순간의 고정 사본이다. 이후 결과 변경은 자동으로 그 사본에 합쳐 보내지 않는다.
- 로컬 리포트 쓰기 실패는 기존 수동 분석 결과에 영향을 주지 않도록 분리하고 안내한다. 큐 자체의 저장 공간 오류는 일시정지 사유다.

## 제출·보안 경계

1. 리포트의 **제출 정보 미리보기**로 전송할 JSON을 고정한다.
2. 정보 종류·제외 항목·운영자·문의처·보관 안내를 확인한다.
3. 이번 리포트 동의 체크(기본 해제) 후 **동의한 데이터 보내기**를 누른다. 체크만으로 전송하지 않는다.
4. 서버는 고정 사본의 토큰·정책 버전·명시적인 동의를 다시 확인한다. 브라우저 버튼 상태만 믿지 않는다.
5. 사본 만료는 15분. 다른 리포트/새로고침/화면 이동/재실행 시 동의를 초기화한다. 서버 설정이 바뀌면 새 미리보기와 동의가 필요하다.
6. 자동 전송·자동 재시도·앱 시작 시 재전송은 없다. 실패 후 사용자가 재동의하여 같은 사본을 다시 보낸다. 수신 확인과 저장 확인은 구분한다.

제출에는 영상·음성·전사·채팅·요약 원문, 닉네임·수동 화자명, VOD 번호/주소/제목·채널, 파일 경로, 로그인 토큰·쿠키·용어 힌트 본문·자유 오류 로그를 넣지 않는다. 로컬 상세 로그와 제출 페이로드는 별개다. 수치/정해진 코드/지정 하드웨어 필드만 허용하는 닫힌 스키마를 앱과 수집 서버가 공유한다.

안내 목적은 분석기 속도·안정성·오류 개선이다. 동의하지 않아도 분석을 이용할 수 있다. 개인정보 원문을 제출 대상에서 제외하지만 “유출 가능성 0%”나 “완전 익명”이라고 보장하지 않는다. 네트워크 인프라의 IP/접속 시간 처리 가능성도 안내한다.

앱 GUI의 127.0.0.1 바인딩·임의 경로 토큰·Origin/Host 검사·CSP를 유지했다. 새 외부 수신 포트·방화벽 예외·터널을 만들지 않았다. 사용자의 동의가 있는 경우에만 설정된 공개 HTTPS 서버로 발신한다. 리디렉션을 따르지 않으며 사설/루프백 수집 주소를 거부한다. Google 자격 증명은 서버 환경 변수로만 보관한다.

## 준비한 수집 서버

`report_collector/server.py`와 `report_collector/README.md`에 구현·운영 절차를 분리했다.

- 지정 스키마/최대 128 KiB, 요청 한도, 제출 번호·내용 해시 기반 멱등 처리.
- Google Drive 전용 비공개 폴더에 JSON 저장. Drive 파일 ID 확인 후에만 저장 완료 반환.
- 서버 장애 후 같은 제출본을 재시도하면 Drive appProperties 대조로 중복 방지.
- 실제 Drive 권한, HTTPS 프록시, OAuth 계정/갱신 토큰, 보관 기간·운영자 연락처는 아직 미설정.
- 공개 서버는 별도 WSGI 서버·HTTPS 프록시·본문/시간/속도 제한과 최소 접속 로그 정책이 필요하다. 기본 수집 한도는 단일 프로세스 기준이다. 여러 인스턴스 분산 잠금은 범위 밖이다.
- 보관 기간 만료 삭제 명령을 제공했다. 실제 운영 스케줄·비밀/DB 백업 접근 제어·삭제 요청 처리는 운영자가 구성해야 한다.
- 기존 Google Drive MCP 연동의 사용자 토큰을 제품 코드에 재사용하거나 복사하지 않았다.

## 검증 결과

- 임시 보관함의 신규 제어·제출 검사 **15개 통과**: 순서/선택 화자/분리 없음, 정규화 VOD 중복, 목록 제거 시 파일 보존, 일반 실패 후 다음 VOD, 모델 누락 시 전체 일시정지, 중단/이어가기, 수동 작업 배제, 재시작 비자동 실행, 큐 프로세스 잠금, 수동 다운로드 계측, 실제 Manager를 연결한 모의 전체 흐름, 스키마/원문 배제, 서버 미연결·동의 없음·만료·안내 변경 차단, 전송 실패 자동 재시도 없음, 수집 중복 방지.
- 기존 다운로드·원음 전사·반응 분석·전체 문맥·실행 시간·정적 자산 대상 회귀 검사와 함께 최종 **76개 통과**했다. 명령: `PYTHONPATH=tests .venv/bin/python -m unittest test_archive test_server_assets test_speech test_analysis test_context_full test_task_timing test_automation_reports -q`.
- JS: 리포트 동의 UI, 다운로드/검증 완료의 전사 화면 자동 인식, 기존 원음 전사 설정 UI 통과. 변경 JS 구문과 Python 모듈 구문 검사 통과.
- 내부 브라우저: 새 메뉴/＋입력칸/−삭제/리포트 하드웨어 표시 확인. M1 Pro 8코어·8스레드, 16 GiB로 표시됨. 모델 폴더의 준비 상태 기존 표시도 유지.
- 신규 코드 전송 테스트는 모의 서버/저장기로 제한했다. 실제 외부 제출을 하지 않았다.
- 최초 로컬 HTTP 테스트는 샌드박스의 소켓 바인딩 제한으로 한 건 실패했으며, 127.0.0.1 테스트 권한으로 다시 실행해 통과했다.

## 남은 확인

- 사용자가 실제 VOD 목록으로 다운로드→요약 전체 흐름, 장시간 진행·앱 강제 종료 후 복구를 확인할 것. 이번 검증은 실제 전체 VOD 재다운로드나 AI 모델 재추론이 아니다.
- Windows 실기 실행/CIM 정보/종료·복구 검증은 미실시.
- 실제 HTTPS 수집 배포, Google OAuth 권한과 Drive 저장/보관 만료 삭제/동시성/남용·부하 검증은 미실시.
- 기본 수집 서비스가 연결되기 전에는 전송 버튼이 활성화되지 않는다. 로컬 리포트 확인과 JSON 저장은 가능하다.
- 패키징/서명/공증/배포는 이번 작업에 포함하지 않았다.
