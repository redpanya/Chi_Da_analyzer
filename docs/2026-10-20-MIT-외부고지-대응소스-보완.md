# MIT 적용·외부 고지·대응 소스 보완

작성일: 2026-10-20. 대상: 자체 소스, 기본 macOS·Windows 패키징, 선택 화자 도구 패키징, GitHub 배포 안내.

## 변경

- 자체 코드에 `Copyright (c) 2026 redpanya and contributors`의 표준 MIT 원문을 적용했다. 외부 도구·모델·콘텐츠를 자체 MIT 범위에 포함시키지 않는다.
- README는 현재 공개 앱 릴리스, HTML 사용설명서, 라이선스 안내만 남겼다. 공개 다운로드는 `v0.18.1-preview.1`, HTML 설명서는 `https://redpanya.github.io/Chi_Da_analyzer/`로 확인했다. 앱 0.19.0 초안은 일반 사용자의 다운로드 링크로 표시하지 않는다.
- `THIRD-PARTY-NOTICES.md`와 `licenses/`에 ONNX Runtime, Python, OpenSSL, llama.cpp 내부 코드, FluidAudio 내부 코드, 음성 라이브러리·코덱, 모델의 고지·출처를 보충했다.
- 기존 파일명 앞부분만 검사하던 고지 수집을 개선해 `ThirdPartyNotices.txt`, `fastcluster-LICENSE.md`, 저작권·저작자 문서도 수집한다. 기본 앱과 추가 화자 도구가 같은 수집·검사 코드를 사용한다.
- 빌드 시 실제 Python 런타임 버전의 공식 LICENSE를 수집하고 출처·해시를 남긴다. 빌드 환경 패키지 목록이 실제 동봉 목록과 다르다는 범위를 명시한다.
- `legal_sources.json`에 libsndfile, 정적 코덱, vcpkg 소스·패치, certifi·tqdm 대응 소스의 URL·SHA-256을 고정했다. 받은 파일은 해시 검사 후 사용하며 불일치·다운로드 실패를 완료로 처리하지 않는다.
- LGPL 라이브러리의 수정·교체·디버깅 권리를 제한하지 않는다는 안내와 macOS 재서명 예외를 추가했다.
- 이후 CI 빌드는 고지 원문 검사, 대응 소스 다운로드 검사, OS별 고지 ZIP·대응 소스 ZIP 생성을 수행한다. `.gitattributes`로 원문 바이트를 보존하고 ZIP의 시각·권한·생성 OS를 고정한다. 이미 압축된 소스는 재압축하지 않아 zlib 버전 차이도 배제한다.
- FFmpeg 전체 환경변수 덤프인 `build-config.log`는 새 패키지에 복사한 뒤 제거한다. 고정 소스·빌드 명령·옵션은 기존 빌드 스크립트에 그대로 남긴다.

## 확인한 출처

ONNX Runtime은 sherpa 1.13.8의 OS별 빌드 파일과 현재 Mac 라이브러리의 공개 버전 조회 API에서 **1.28.2**로 확인했다. 이 버전의 Microsoft LICENSE와 ThirdPartyNotices를 사용한다.

SoundFile 0.13.1의 하위 저장소는 `bastibe/libsndfile-binaries@a3e6f9769d0c7e91d2d036cf0fdbe5b4bbf18b87`이다. libsndfile은 1.2.2이며 정적 코덱도 함께 존재한다.

| 구분 | Mac | Windows |
|---|---|---|
| Ogg / Vorbis / FLAC | 1.3.5 / 1.3.7 / 1.4.3 | 1.3.5 / 1.3.7 / 1.4.3 |
| Opus | 1.4 | 1.5.2 |
| mpg123 | 1.32.3 | 1.32.9 |
| LAME | 3.100 | 3.100 |

Windows vcpkg 자료는 `80d54ff62d528339c626a6fbc3489a7f25956ade`에 고정했다. mpg123 소스와 세 패치의 결합 해시 `66150af195`, Opus 소스·패치 결합 해시 `81ed242155`가 실제 DLL의 소스 경로 기록과 일치했다. libsndfile·Opus의 vcpkg 입력 압축은 포트가 요구하는 SHA-512까지 대조했다. 원 배포처의 스크립트·triplet·출처 자료를 함께 제공한다.

이 자료는 정확한 과거 컴파일러·운영체제 전체를 재현해 바이너리가 바이트 단위로 같다는 증명은 아니다. 확인한 버전·패치를 보존하고 별도 완전 재현 시험은 미실시로 구분한다.

ERes2Net은 이번에는 ModelScope 원 모델 README를 받아 `Apache License 2.0` 표기를 확인했다. 앞선 검사에서 시간 초과로 남았던 원 가중치 카드 확인을 보완했다. Gemma·Fluid의 고정 리비전 자료와 모델 고지 원문은 가중치를 포함하지 않고 제공한다.

## 기존 배포본 보존

기존 앱·화자 도구 ZIP을 교체하거나 삭제하지 않는다. 다음 배포물에 대한 고지를 별도 `license-notices.zip`으로 보충하고 `legal-corresponding-sources.zip` 및 체크섬을 함께 제공한다.

- 앱 `v0.18.0-preview.5`: macOS·Windows
- 앱 `v0.18.1-preview.1`: macOS·Windows
- 앱 `v0.19.0-preview.1` 초안: macOS·Windows
- `speaker-tools-v1`: macOS sherpa·pyannote·FluidAudio

각 입력 ZIP의 SHA-256을 GitHub 릴리스의 자산 해시와 대조한 뒤 기존 고지 원문을 보존했다. 보충 ZIP의 `적용대상.json`에 대상 파일명·버전·원 ZIP 해시를 기록했다. GPL 대상 FFmpeg·x264 소스는 각 원 릴리스의 `native-corresponding-sources.zip`을 계속 사용한다.

별도 고지·소스 보충은 새 앱 버전을 발행한 것이 아니다. 이후 빌드에서만 앱 내부 고지 폴더가 갱신된다. 기존 사용자의 설치 앱이나 모델 캐시에 파일을 자동으로 추가하지 않는다.

## 사이드이펙트·예외

- 고지 파일만 추가해도 앱 서명·ZIP 해시는 바뀐다. 기존 서명된 ZIP을 직접 수정하지 않고, 미래 빌드에서는 고지 포함 후 서명한다.
- 다운로드 출처가 사라지거나 해시가 달라지면 빌드를 중단한다. 검증되지 않은 대체 파일로 조용히 넘어가지 않는다.
- 원문 파일을 임의로 번역·줄바꿈 변경하면 고지 해시 검사가 실패한다. 안내 문서는 한국어, 법적 원문은 원래 언어를 유지한다.
- 설치된 Python 패키지 버전이 바뀌면 자동 수집하는 고지도 달라질 수 있다. 새로운 네이티브 의존성과 모델은 별도 검토 후 목록을 갱신해야 한다.
- 영상·채팅·전사·수동 교정·화자 배정·AI 요약 결과와 모델 가중치는 변경하지 않았다. 음성·요약 엔진 버전도 바꾸지 않았다.

## 배포 확인

- 소스 반영: `1804e4a`(MIT·고지·대응 소스), `cc7c036`(Windows 경로 검사), `2a8c62d`(macOS 번들 파일명). GitHub API가 저장소 `LICENSE`를 **MIT**로 인식함을 확인했다.
- [보충 자료 릴리스](https://github.com/redpanya/Chi_Da_analyzer/releases/tag/license-supplement-20261020)를 게시했다. 새 앱 버전이 아닌 자료 전용 사전 릴리스이며 `latest=false`로 설정했다.
- 기존 앱 릴리스 3개와 `speaker-tools-v1`에도 같은 보충 자료 3개씩을 추가했다. 기존 릴리스 **8개·자산 46개**의 파일 ID·크기·해시와 공개/초안·사전 릴리스 설정이 모두 유지됨을 API로 대조했다.
- 5개 릴리스에 추가한 보충 자산 **15개**의 원격 해시가 로컬 파일과 일치했다. README의 공개 앱 릴리스·HTML 사용설명서와 보충 자료 페이지는 HTTP 200 응답을 확인했다.
- 첫 [CI 실행](https://github.com/redpanya/Chi_Da_analyzer/actions/runs/39409948231)에서 새 경로 검사 하나가 Windows에서 실패했다. Windows의 `/tmp/...`는 드라이브가 생략된 루트 경로여서 `is_absolute()`만으로 차단되지 않았다. Windows 루트·드라이브·UNC·대체 스트림 경로를 OS와 무관하게 거부하도록 수집기를 보완했다. 앱 동작 코드 변경은 없다.
- 두 번째 [CI 실행](https://github.com/redpanya/Chi_Da_analyzer/actions/runs/39410290597)에서 Windows의 회귀·패키지 독립 실행·자료 생성은 통과했다. macOS는 기존 ASCII 파일명 검사에서 새 한국어 안내 파일명이 거절됐다. 검사 기준을 낮추지 않고 배포 안내를 `docs/third-party-source-guide.md`로 변경했으며 내용은 한국어로 유지했다. 종전 GitHub 문서 주소에는 이동 안내를 남겼다. 실제 고지 원문 61개와 안내 파일을 복사한 폴더의 파일명·해시 검사를 로컬에서 통과했다.
- 게시된 보충 ZIP과 체크섬 파일을 다시 내려받아 ZIP 무결성, 고지 원문 61개·대응 소스 14개 및 외부 체크섬이 모두 일치함을 확인했다. 이 보충 자료는 기존 배포물에 대한 고정 자료이며, 그 뒤의 패키징 도구 보완은 저장소와 새 CI 산출물에 적용한다.
- 최종 [CI 실행](https://github.com/redpanya/Chi_Da_analyzer/actions/runs/39411148353)은 **macOS-arm64·Windows-x64 모두 성공**했다. 두 OS의 앱 구성·독립 실행·고지 검사·대응 소스 생성까지 통과했다. 앱은 CI 산출물로 생성했으며 기존 앱 릴리스 자산을 교체하거나 초안을 공개하지 않았다.
- 두 번째 CI의 Windows 산출물도 직접 다운로드했다. 실제 앱 ZIP 내부의 MIT·고지 원문 61개, 소스 ZIP의 14개 원본, 전체 산출물 체크섬을 확인했다. 최종 변경과 비교했을 때 외부 원문·코덱 소스·빌드 자료는 같고, 고지 문서 링크·패키징 보조 코드·안내 파일명만 달라졌다. 최종 두 OS CI ZIP을 모두 내려받아 서로의 전체 압축 해시를 비교하는 추가 검사는 하지 않았다. 초안 생성 경로는 두 OS의 대응 소스 ZIP 해시가 다르면 중단하도록 구성했다.
