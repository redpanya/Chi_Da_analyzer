# VOD 리스트 등록을 기본으로 통합하는 설계

작성일: 2026-10-18
상태: **2026-10-18 구현 완료. macOS 검증 결과는 [통합 구현·검증 기록](2026-10-18-VOD리스트등록-통합-구현검증.md) 참고. 패키징·배포 없음.**

아래 내용은 당시 승인한 설계 기준이다. 실제 구현 세부 사항·검사 범위와 미검증 항목은 연결된 구현 기록을 우선한다.

## 1. 목표와 기본 원칙

가져오기에서 단일 치지직 주소의 별도 `정보 확인 → 다운로드 시작` 흐름을 없애고, 현재 `여러 VOD 순차 작업`을 **VOD 리스트 등록**으로 통합한다. 주소가 하나여도 같은 목록을 사용한다. 새 VOD와 이미 저장된 VOD를 같은 목록에 넣고, 선택한 진행 범위에서 필요한 단계만 순서대로 실행한다.

- 원본·기존 결과·수동 전사 교정·화자 배정·리포트는 유지한다.
- 등록과 실행은 분리한다. 등록만으로 다운로드나 AI 처리를 시작하지 않는다.
- VOD 사이의 순차 실행, 작업 잠금, 중단·재개, 앱 재시작 후 수동 이어가기를 유지한다.
- 말소리 분리는 추가하지 않는다. 화자 구분은 선택 기능이다.
- 진행 범위의 초기 기본값은 기존처럼 `영상·채팅 다운로드만`으로 둔다. 기본 진입점을 목록으로 통합한다는 요청을 AI 자동 실행의 기본 활성화로 해석하지 않는다.
- macOS와 Windows에 같은 동작 규칙을 적용한다. 외장 보관함과 작업용 내장 임시 DB의 분리는 유지한다.

## 2. 현재 구현에서 확인한 사항

| 현재 상태 | 설계에 반영할 내용 |
| --- | --- |
| 단일 주소 입력과 여러 주소 입력이 동시에 보임 | 온라인 입력을 하나로 통합 |
| 기존 단일 주소 폼을 로컬 비디오 가져오기도 공유함 | 폼 삭제로 파일 가져오기를 깨뜨리지 않도록 별도 연결 수정 |
| 등록 시 `manager.inspect()`를 먼저 호출함 | 저장한 VOD 등록은 서버 조회 없이 프로젝트 자료로 처리 |
| `Automation.add()`는 완료 항목까지 같은 VOD의 중복으로 막음 | 완료된 다운로드 항목을 후속 분석 작업으로 다시 등록할 수 있도록 구분 |
| 옵션은 항목을 등록할 때 고정됨 | 등록 설정과 이미 대기 중인 항목의 설정을 UI에서 구분 |
| `Manager.start()`에는 완료 작업 생략과 미완료 작업 재개가 존재함 | 새 실행기를 만들지 않고 이 흐름을 재사용 |
| 다운로드 재사용 판단은 실행 전 상태로 계산하고 목록에는 `complete`를 반환함 | 실제 검증 후 재사용 여부를 판정하고 목록에도 `기존 자료 사용`으로 표시 |
| 로컬 영상 프로젝트는 현재 온라인 목록 등록에서 거부함 | 저장 완료된 로컬 영상은 저장한 VOD 경로로 분석 목록에 추가 가능하게 변경 |

내부 브라우저에서도 단일 입력과 순차 입력의 중복, 설정 영역의 `AI 요약까지`와 기존 대기 항목의 `다운로드만`이 함께 보이는 상태를 확인했다. 이는 항목별 설정이 저장된 결과이며, 목록 기본화 시 설명과 설정 적용 동작을 명확히 해야 한다.

## 3. 화면과 사용 순서

### 기본 가져오기 화면

사이드바 `＋ 새 VOD 가져오기`를 `＋ VOD 리스트 등록`으로 바꾼다. 상위 단계 이름 `1 가져오기`는 유지하고 해당 화면의 제목은 `VOD 리스트 등록`으로 바꾼다.

화면 구성 순서:

1. **등록할 자료**: 새 VOD 주소 입력과 `저장한 VOD 선택` 버튼.
2. **작업 설정 💡**: 진행 범위, 신규 다운로드 최대 화질, 언어·발화 검출·용어 힌트, 선택적 화자 구분, Gemma 사고 여부 등 기존 옵션.
3. **목록에 등록**: 입력·선택한 항목을 현재 설정으로 등록.
4. **등록된 VOD 목록**: 순서, 제목, 등록된 설정, 예상 시작 단계, 진행 상태, 오류, 기존 자료 사용 여부.
5. **순차 작업 시작·이어가기 / 일시정지**: 등록과 명확히 구분한 실행 버튼.
6. **내 비디오 사용**, 보관함·모델 폴더 및 Windows 처리 장치 설정: 기존 기능을 별도 영역으로 유지.

새 주소 입력은 기존 ＋/− 입력칸을 사용한다. 단일 온라인 주소 폼, 별도의 `정보 확인` 버튼, 온라인용 하단 `영상·채팅 다운로드 시작` 버튼은 제거한다. 정보 확인은 `목록에 등록` 내부에서 실행하고 결과는 각 등록 항목에 표시한다. 서버의 확인 API 자체는 새 주소 확인과 로컬 가져오기에 필요하므로 삭제하지 않는다.

설명은 기존 💡 오버레이에 넣고, 등록 실패·모델 미준비·진행 상태는 화면에 남긴다. 데스크톱 배치는 유지하며 레이아웃 전면 개편은 하지 않는다.

### 저장한 VOD 선택

- 현재 보관함의 저장된 VOD를 선택창에서 복수 선택한다. 제목·VOD 번호·영상/채팅 상태·전사/요약 상태를 표시한다.
- `영상·채팅 완료, 분석 전` 항목을 쉽게 찾을 수 있게 표시한다. 다운로드만 끝난 항목만 허용하는 것은 아니며 중단된 항목이나 전사까지 끝난 항목도 등록할 수 있다.
- 사이드바 각 VOD에 `목록 등록` 보조 버튼을 둔다. 누르면 등록 화면으로 이동해 해당 VOD를 선택 상태로 보여준다. 기존 제목 클릭은 그대로 VOD 열기다. 버튼 안에 버튼을 중첩하지 않는다.
- 선택 항목은 등록 전 순서를 보여주고 그 순서대로 기존 대기열 끝에 추가한다. 선택 중 자동 새로고침으로 순서를 바꾸지 않는다.
- 저장된 프로젝트의 메타데이터를 사용하므로 주소 재입력·치지직 서버 재조회가 필요 없다. VOD가 서비스에서 삭제됐더라도 필요한 자료와 모델이 로컬에 있으면 후속 분석이 가능하다.
- 다른 보관함의 VOD를 섞어 등록하지 않는다. 폴더를 바꾸면 선택 자료를 지우고 해당 보관함의 목록을 다시 표시한다. 실행 중 보관함 변경은 차단한다.

### 설정 적용 범위

설정 영역 제목/안내에 `새로 등록할 항목에 적용`을 명시한다. 이미 등록한 항목이 조용히 바뀌지 않도록 각 행에 적용된 진행 범위·화질 정책·화자 포함 여부를 표시한다.

아직 실행하지 않은 대기 항목은 체크해서 `선택한 대기 항목에 설정 적용`을 할 수 있게 한다. 서버는 잠금 안에서 여전히 미실행 대기 상태인지 확인한다. 실행 중·중단 정리 중인 항목은 수정하지 않는다. 이미 실행 이력이 있는 중단/오류 항목의 단순 이어가기는 원래 설정을 사용한다. 설정을 바꾸려면 해당 항목을 목록에서 제거한 뒤 새 작업으로 등록하도록 안내하며, 제거해도 VOD와 리포트는 유지한다.

완료된 다운로드 항목은 `저장한 VOD 선택`에서 다시 골라 `AI 요약까지`로 등록할 수 있다. 이 경우 새 작업 ID·새 리포트를 만들고 과거 완료 항목과 리포트를 덮어쓰지 않는다. 목록 제거는 실제 VOD 삭제와 구분한다.

## 4. 실제 실행 흐름

`영상·채팅 준비 → 원음 추출 → 음성 전사 → 화자 구분(선택) → 채팅 반응 분석 → AI 문맥 요약 → 다음 VOD`

진행 범위가 다운로드만이면 영상·채팅 준비 뒤 다음 VOD로 이동한다. 이미 준비된 단계는 기존 자료를 확인하고 재사용한다.

| 등록 시 보유 자료 | AI 요약까지 선택한 경우 |
| --- | --- |
| 새 주소, 저장 자료 없음 | 다운로드·검증부터 전체 선택 단계 실행 |
| 영상·채팅 완료 | 다운로드 재실행 없이 원음 추출부터 시작 |
| 영상만 완료, 채팅 미완료 | 영상 재사용, 채팅만 수집·복구 후 원음 추출 |
| 영상 수신 완료, 검증 미완료 | 저장 영상 검사·복구를 먼저 진행. 상태명만 보고 생략하지 않음 |
| 원음까지 완료 | 입력 영상과 일치하면 원음도 재사용하고 전사부터 시작 |
| 전사까지 완료 | 입력·언어·전사 옵션이 일치하면 전사 재사용 후 선택 화자/반응/요약 진행 |
| 요약까지 완료 | 현재 입력·설정과 맞으면 전부 기존 결과 사용으로 종료 |
| 완료된 로컬 비디오 가져오기 | 첨부 영상 재사용. 필요한 채팅만 처리하고 후속 분석 |

영상·채팅을 각각 판단한다. `영상·채팅 완료`라는 묶음 표시만 보고 둘 다 생략하지 않는다.

### 단계별 재사용 기준

| 단계 | 재사용 조건과 예외 |
| --- | --- |
| 영상 | 완료 기록, 필수 파일, 기존 검증 정보와 현재 파일의 일치 여부 확인. 등록 시 전체 영상 디코딩/해시를 반복하지 않는다. 실행 직전에 다시 확인하고 변경·검증 미완료는 기존 검증/복구 루틴으로 보낸다. 필요한 유효성 정보를 구버전이 갖고 있지 않으면 확인 필요 상태로 처리하고 검증 없이 완료를 가정하지 않는다. |
| 채팅 | `complete/empty/unavailable`의 실제 결과·제공 상태를 확인. 미완료이면 `chat-pages`와 저장 경계 응답부터 재사용한다. 작업 DB는 내장 임시 위치에 만든다. |
| 채팅 `review` | 기존 `일부 자료도 분석` 옵션이 켜진 경우에만 유효한 저장 JSONL을 사용하고 불완전성을 표시한다. 오류 상태를 채팅 없음으로 바꾸지 않는다. |
| 원음 | 영상의 식별 정보와 연결된 정상 WAV인지 기존 검사를 사용한다. 오디오 트랙이 여러 개면 임의 선택하지 않는다. |
| 전사 | 현재 음성 입력·언어·옵션과 일치하는 완료 전사 재사용. 다른 설정이면 새 결과가 필요하다는 것을 표시하고 기존 전사/교정 버전을 보존한다. |
| 화자 | 선택하지 않으면 단계 생략. 현재 전사에 연결된 유효한 기존 배정·수동 배정은 유지한다. 다른 엔진을 고른 것만으로 기존 수동 배정을 자동 교체하지 않는다. |
| 반응 분석 | 현재 채팅과 설정에 맞으면 재사용. 채팅 미제공이면 생략 사유 표시. |
| 문맥 요약 | 현재 입력 지문·모델·처리 버전·사고 설정과 일치하면 재사용, 가능한 부분 결과는 이어가기. 호환되지 않는 결과를 덮어쓰거나 강제로 이어붙이지 않는다. |

공통 옵션의 최대 화질은 **새로 다운로드하는 영상**에 적용한다. 저장된 480p 영상을 등록하면서 1080p를 선택해도 자동으로 다시 받거나 교체하지 않는다. 중단 영상의 화질도 기존 작업 값을 유지하고 `기존 화질로 이어받음`을 표시한다.

## 5. 목록 표시와 재시작

각 행은 `확인 중 / 대기 / 진행 중 / 일시정지 / 완료 / 일부 완료 / 확인 필요`를 표시한다. 단계는 `새로 처리 / 기존 자료 사용 / 옵션으로 생략 / 확인 필요`를 구분한다.

예: 저장된 영상·채팅을 AI 요약까지 등록한 행은 `영상·채팅: 기존 자료 사용 → 원음 추출: 대기 → 전사: 대기 → 요약: 대기`로 표시한다. 목록 위에는 `3개 중 1개 진행`처럼 전체 순서도 표시한다. 예상 시작 단계는 등록 당시의 가벼운 점검 결과이며 실행 직전에 다시 판단한다.

완료 단계는 다운로드 시간이 새로 발생한 것처럼 리포트에 기록하지 않는다. 기존 `reused/skipped` 구분을 유지하며 이전 실행 시간은 과거 리포트에 남긴다. 전체 완료 자료를 재등록한 경우에도 새 실행 기록은 기존 자료 사용으로 식별한다.

앱 재시작 후 실행 중이던 항목은 일시정지로 표시한다. 사용자가 이어가기를 누르면 현재 파일을 다시 확인하고 첫 미완료 단계부터 진행한다. 이전 단계 문자열만 보고 중간 작업을 건너뛰지 않는다.

## 6. 로컬 비디오 가져오기 보존

단일 온라인 입력을 제거하면서 `내 비디오 사용`까지 없애지 않는다. 이 영역에는 비디오 파일, 연결할 치지직 VOD 주소, 시작 시각, 연속 영상 확인을 유지한다. 별도의 `정보 확인` 버튼 대신 `비디오 가져오기` 동작 내부에서 주소/파일 정보를 확인하고 기존 파일 복사·검증·채팅 수집을 수행한다. 정보 확인 실패 시 복사를 시작하지 않는다.

로컬 파일의 최초 첨부는 브라우저가 파일을 가지고 있어야 하므로 이번 목록 기본화에서 무인 파일 첨부 대기열로 확장하지 않는다. 복사·검증이 완료되면 저장된 VOD로 목록에 등록할 수 있다. 미완료 로컬 영상은 같은 파일 재첨부가 필요하다고 표시하며 온라인 다운로드로 대체하지 않는다.

## 7. 저장 형식과 모듈 변경 범위

기존 `.automation/queue.json`과 기존 단계 실행기를 사용한다. 별도의 두 번째 대기열을 만들지 않는다. 보관함과 VOD 번호가 같은 미완료 항목은 하나만 허용한다. 원래 주소·단축 주소·저장한 VOD 선택을 섞어도 같은 항목으로 판정한다. 완료 이력 뒤의 새 후속 작업은 별도 ID로 허용한다.

| 대상 | 구현 시 변경 |
| --- | --- |
| `web/index.html`, `web/app.js` | 온라인 단일 입력/시작 버튼 제거, 기본 목록 진입, 사이드바 보조 동작, 제거한 DOM 참조와 초기화 의존성 정리 |
| `web/queue.js` | 저장 VOD 복수 선택, 새 주소 등록과 통합, 미실행 대기 항목 설정 적용, 항목별 실제 설정·재사용 표시 |
| 저장 VOD 선택 UI 모듈 | 선택창·선택 순서·중복 안내를 분리. 전체 목록을 갱신할 때 선택과 포커스를 잃지 않게 함 |
| `web/local-import.js` | 공유 단일 폼 의존성을 제거하고 로컬 입력/확인/복사 흐름을 자체 처리 |
| 도움말 자료 | 명칭·등록과 실행의 차이·재사용·설정 적용 범위 갱신 |
| `archive/automation.py`, `archive/server.py` | 저장 VOD 등록과 대기 설정 변경 API, 상태별 중복 규칙, 후속 작업의 새 리포트 생성 |
| `archive/automation_steps.py`, `archive/jobs.py` | 기존 자료 검증 후 재사용 판정, 영상/채팅 중 필요한 작업만 시작, 현재 결과와 단계 표시 일치 |
| 테스트 | 등록·재사용·중단·로컬 입력·리포트·보존 관련 회귀 검사 확장 |

저장 VOD 등록 API는 `root`, 순서가 있는 `vod_ids`, `options`만 받는다. 임의 파일 경로나 클라이언트가 전달한 완료 상태를 신뢰하지 않는다. 서버에서 현재 보관함 안의 프로젝트 식별·경로·잠금을 확인한다. 기존 경로 탈출·심볼릭 링크 차단 및 loopback/요청 검증을 유지한다.

기존 큐 버전 1은 읽을 수 있도록 유지한다. 등록 경로 등의 표시용 필드는 선택 필드로 추가하며 기존 항목의 옵션을 새로운 화면 기본값으로 덮어쓰지 않는다. 새 등록이나 재시작 시 전체 큐를 초기화하지 않는다.

## 8. 오류·부작용 처리

| 상황 | 처리 |
| --- | --- |
| 여러 새 주소 중 일부가 잘못됨 | 성공한 등록은 유지하고 실패한 입력과 이유를 남김. 재시도 시 성공 항목 중복 등록 방지 |
| 이미 대기/중단/오류/일부 완료 상태로 등록됨 | 새 미완료 항목을 만들지 않고 기존 행으로 안내. 미실행 대기는 설정 적용, 실행 이력이 있으면 이어가기 또는 목록 제거 후 새 등록 |
| 과거 다운로드만 완료한 항목이 목록에 남아 있음 | 기존 완료 이력과 리포트를 유지하고 후속 분석용 새 항목 허용 |
| 목록 등록 후 파일 삭제·교체 | 실행 시 다시 검사. 누락을 완료로 간주하지 않고 복구/재첨부/확인 필요 표시 |
| 서비스에서 VOD가 삭제됨 | 로컬 자료가 충분한 후속 분석은 계속. 새 다운로드가 필요한 단계만 해당 항목 오류로 표시 |
| 외장 디스크 분리·저장/임시 공간 부족 | 목록 전체 일시정지. 원본·완료 결과 유지. 재연결/공간 확보 후 이어가기 |
| 전사·Gemma 또는 선택 화자 도구 미준비 | 기존 정책대로 전체 일시정지하고 준비 위치 안내. 등록 자체는 가능하며 모델 다운로드·HF 동의를 자동 실행하지 않음 |
| 한 VOD의 일반 작업 오류 | 해당 항목 오류를 남기고 다음 VOD로 진행. 화자 오류/요약 일부 실패는 기존 선택 정책 유지 |
| 자동화와 개별 처리 동시 요청 | 기존 Manager 잠금·프로젝트 잠금 유지. 다른 VOD를 병렬로 처리하지 않음 |
| 모든 단계가 이미 완료 | 재처리 없이 기존 자료 사용으로 종료. 기존 결과의 활성 참조도 불필요하게 교체하지 않음 |
| 새 전사·요약이 필요한 설정 변경 | 재사용 불가 사유 표시. 새 버전으로 저장하고 기존 교정/배정/요약을 보존. 새 버전과 맞지 않는 수동 배정을 임의 이전하지 않음 |
| 목록에서 제거 | 작업 항목만 제거. 실제 파일 삭제는 별도의 VOD 삭제 기능에서만 수행 |

기존 최대 100개 목록 제한은 유지한다. 완료 이력도 용량을 차지하므로 한도 도달 시 완료 항목을 목록에서 제거하도록 안내한다. 원본과 결과 폴더를 지워 해결하도록 안내하지 않는다.

## 9. 구현 순서

1. 저장한 VOD의 등록 경로, 완료 이력 후 재등록, 미실행 대기 설정 적용을 서버에 추가하고 기존 큐 호환성 검사.
2. 단계별 준비/재사용 판정과 결과 표시를 연결. 영상·채팅이 유효하면 다운로드 작업자를 호출하지 않고, 미완료 쪽만 기존 복구 경로로 실행.
3. 기본 입력을 목록으로 통합하고 저장 VOD 선택/사이드바를 연결. 로컬 비디오 입력과 기존 개별 진행 화면의 동작을 보존.
4. 다음 검증 기준으로 확인하고 docs에 실제 통과·실패·미검증을 구분해 기록. 패키징은 별도 요청 때만 진행.

## 10. 구현 후 검증 기준

아래는 예정된 수용 기준이며 이번 설계 작업에서 통과했다고 주장하지 않는다.

| 검사 | 통과 기준 |
| --- | --- |
| 기본 입력 통합 | 온라인용 입력 경로가 목록 한 곳으로 정리되고 주소 1개/여러 개 모두 등록·시작 가능 |
| 새 VOD + 저장 VOD 혼합 | 등록 순서대로 각 VOD의 선택 단계가 끝난 뒤 다음 VOD 시작 |
| 다운로드만 완료한 자료의 후속 분석 | 영상·채팅 수신 호출 0회. 필요한 원음/전사/요약 단계만 실행 |
| 영상 완료·채팅 미완료 | 영상 다운로드 호출 0회, 저장 페이지 재사용 후 채팅 완료/검증 상태를 정확히 반영 |
| 종료됐지만 검증 안 된 영상 | 단순 완료 생략 없이 기존 파일 검증 수행. 실제 손상은 다음 단계 차단 |
| 완료 원음·전사 재사용 | 입력과 옵션이 같으면 해당 엔진 호출 0회, 다른 옵션이면 새 버전 필요 표시와 이전 결과 보존 |
| 이미 끝난 다운로드 큐 재등록 | 과거 완료 항목/리포트 유지, 새 분석 항목 ID/리포트 생성, 재다운로드 없음 |
| 중복·설정·경합 | 원래 URL/단축 URL/저장 선택의 같은 VOD 중복 차단. 미실행 대기에만 선택 옵션 적용. 실행 진입과 설정 변경 경합 시 한쪽을 안전하게 거부 |
| 서비스 오프라인/삭제된 VOD | 자료·모델이 충분한 저장 VOD는 메타데이터 서버 호출 없이 등록·분석 시작 |
| 부분 등록 실패 | 실패 항목만 수정·재시도 가능하고 성공 항목 순서/설정 유지 |
| 로컬 비디오 | 새 파일 첨부·중단 후 같은 파일 재첨부 정상. 완료된 로컬 영상의 후속 분석 시 온라인 영상 다운로드 0회 |
| 실행 중 파일 변경/외장 분리 | 해당 단계 확인 필요 또는 전체 일시정지. 완료 표시 위조와 데이터 삭제 없음 |
| 재시작·취소 | 자동 재시작하지 않음. 이어가기 시 완료 자료 재사용, 작업자/잠금 종료 후 다음 항목 처리 |
| 데이터 보존 | 원본·기존 전사/교정·화자 배정·요약·리포트의 파일 해시 유지. 프로젝트 상태 변경은 의도된 항목만 발생 |
| 표시·접근성 | 설정 적용 범위, 예상 단계/실제 단계, 기존 자료 사용, 오류를 구분. 키보드로 복수 선택·등록·취소 가능 |
| OS별 | macOS 실제 보관함과 Windows 빌드에서 등록/경로/재사용을 각각 확인. 한 OS 결과를 다른 OS 통과로 간주하지 않음 |

## 이번 작업 기록

현재 소스와 내부 브라우저의 가져오기 화면을 읽어 설계했다. 실제 큐 추가·설정 변경·다운로드·분석·파일 정리는 실행하지 않았다. 앱 코드와 기존 앱 패키지는 변경하지 않았다.
