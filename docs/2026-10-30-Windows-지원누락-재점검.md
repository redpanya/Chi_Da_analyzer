# macOS 추가 기능의 Windows 배포 지원 재점검

## 점검 기준

- 일자: 2026-10-30.
- 대상: 공개 `v0.20.0-preview.5`, 앱 빌드 커밋 `6d67d5c`.
- [앱 릴리즈](https://github.com/redpanya/Chi_Da_analyzer/releases/tag/v0.20.0-preview.5), [기존 OS별 빌드·검사](https://github.com/redpanya/Chi_Da_analyzer/actions/runs/41022083419), [별도 화자 도구 릴리즈](https://github.com/redpanya/Chi_Da_analyzer/releases/tag/speaker-tools-v1)를 기준으로 확인했다.
- 현재 작업본·배포용 체크아웃·내려받은 두 OS ZIP·최종 CI 로그·현재 공개 자산 목록을 대조했다. 새 Windows 실행이나 빌드는 하지 않았다.
- macOS 배포 ZIP에서 FFmpeg만 임시 폴더로 꺼내 `-protocols`를 실행했다. 앱·모델·사용자 VOD 처리는 실행하지 않았다.
- 이번 변경은 점검 문서와 근거 파일뿐이다. 앱 코드·원본·기존 결과·공개 릴리즈는 변경하지 않았다.

## 결론

최근 기능의 소스 파일이 Windows에서 빠진 상태는 아니다. 하지만 실행에 필요한 네트워크 기능과 별도 도구 배포가 누락되어 있으며, 리포트의 Windows 사양 조회에도 문제가 있다. 이전 CI 통과를 실제 네트워크 수신·AI 추론·GUI 전체 검증으로 해석하면 안 된다.

| 우선순위 | 판정 | 항목 | 사용자 영향 |
|---|---|---|---|
| P1 | 확정 | FFmpeg HTTPS/TLS 누락 | 원격 구간 다운로드 및 같은 수신 함수를 사용하는 원격 부분 분석 중단. **Windows와 macOS 배포본 모두 해당** |
| P1 | 확정 | Windows pyannote 도구 ZIP 미배포 | 앱의 별도 설치 기능으로 pyannote를 준비할 수 없음 |
| P2 | 확정 | Windows sherpa 별도 도구 ZIP 미배포 | 별도 설치·재설치 경로 실패. 앱에 내장된 기본 sherpa 경로는 존재 |
| P2 | 코드 경로 확인 | Windows 사양 리포트의 PowerShell 검색 경로 | 표준 설치 환경에서 CPU·GPU·물리 코어·RAM 정보가 비어 있을 수 있음 |
| P2 | 조건부 위험, Windows 재현 전 | 미리듣기 캐시 정리 중 열린 파일 삭제 | 여러 탭·느린 전송 중 캐시가 교체되면 선택 오디오 미리듣기가 실패할 가능성 |

## 1. 원격 영상 수신: 두 OS 공통 누락

`packaging/release/build_ffmpeg.sh:30`은 `--disable-autodetect`를 사용하면서 TLS 백엔드를 명시하지 않는다. 최종 CI의 활성 프로토콜 목록에도 `https`, `tls`가 없다.

- Windows: `windows-ci.log:2002` 이후.
- macOS: `macos-ci.log:1131` 이후.
- 이번 macOS 배포 바이너리 실행에서도 종료 코드 0, HTTPS/TLS 목록 없음으로 재확인했다.
- `archive/remote_media.py:18`은 HTTPS 주소를 FFmpeg 입력으로 전달한다. 프로토콜 허용 목록에 HTTPS를 적는 것만으로 빌드에 없는 기능이 생기지는 않는다.
- `archive/range_download.py:31`의 새 구간 다운로드와 `archive/range_jobs.py:73`의 원격 범위 작업이 영향을 받는다. 이미 저장된 영상에서 범위를 추출하는 경로는 별개다.
- 종료 코드 `2964172552`는 signed 값 `-1330794744`, FFmpeg의 `AVERROR_PROTOCOL_NOT_FOUND`와 일치한다.
- `archive/speech_media.py:71`은 모든 비정상 종료에 음성 처리·메모리·디스크 문구를 사용하므로 이번 오류의 실제 원인을 전달하지 못한다.

보완 방향: Windows Schannel, macOS Secure Transport 등 해당 OS TLS 백엔드를 명시하고 인증서 검증을 유지한다. 실제 배포 바이너리의 HTTPS/TLS 목록과 HTTPS 구간 수신을 빌드 검사에 추가한다. Python 네트워크 경로·로컬 미디어 복구는 따로 검증하고, 기존 부분 파일을 지우는 방식으로 우회하지 않는다.

## 2. Windows 화자 도구 배포 누락

공개 `speaker-tools-v1`의 현재 자산에는 macOS용 sherpa·pyannote·FluidAudio ZIP만 있다. 다음 Windows 파일은 없다.

- `chida-pyannote-Windows-x64.zip`
- `chida-sherpa-Windows-x64.zip`

`archive/speaker_tools.py:25`는 sherpa와 pyannote를 Windows 지원으로 표시하고, `archive/speaker_tools_install.py:44`는 플랫폼에 맞는 정확한 ZIP 이름을 찾는다. 파일이 없으면 59행에서 미배포 오류를 반환한다.

pyannote는 본체 번들에서 torch·torchaudio를 제외하므로 별도 실행 도구를 설치해야 한다. 따라서 현재 신규 Windows 사용자는 해당 설치 경로로 이용할 수 없다. sherpa는 본체의 내장 실행 경로가 있어, 기본 화자 구분까지 전부 불가능하다는 뜻은 아니다.

보완 방향: 별도 Windows 도구를 빌드하고 실행 계약·라이선스·대응 소스·해시를 확인한 뒤 같은 배포 규칙으로 제공한다. 앱에서 파일 존재 여부까지 확인해 준비 상태를 표시한다. 기존 설치본과 모델은 교체·삭제하지 않고 새 버전을 확인한 뒤 활성화한다.

## 3. 리포트의 PC 사양 조회

- `archive/runtime.py:47-49`는 패키지 실행 시 PATH를 앱 도구 폴더, `System32`, `SystemRoot`로 제한한다.
- `archive/report_hardware.py:27`은 절대 경로 없이 `powershell`을 실행한다. 표준 PowerShell 위치인 `System32\WindowsPowerShell\v1.0`은 위 PATH에 없다.
- 실행 실패는 29행에서 처리되고 CPU·코어·RAM·GPU가 `null`로 남는다. 운영체제명·논리 스레드 수는 별도로 기록되어 리포트 전체가 실패한 것처럼 보이지 않을 수 있다.
- `packaging/release/report_smoke.py:18-19,35`는 hardware 객체와 OS 값만 확인하므로 이 누락을 검출하지 못한다.
- 영상 나누기의 파일 선택창은 `archive/split_picker.py:20`에서 PowerShell 절대 경로를 사용하므로 같은 문제가 아니다.

보완 방향: 제한된 PATH 정책은 유지하고 시스템 PowerShell의 절대 경로를 사용한다. 표준 Windows CI에서 CPU·RAM 등 실제 조회값을 확인하며, 조회 권한이나 관리 정책으로 거부된 경우에는 빈 값의 이유를 안내한다. 과거 리포트는 덮어쓰지 않는다. 이번에는 사용자 Windows에서 사양 조회를 직접 실행하지 않았다.

## 4. 선택 오디오 미리듣기 캐시의 조건부 위험

`archive/split_audio.py:91-96`은 캐시 8개를 초과하면 가장 오래된 항목을 먼저 목록에서 제거하고 파일을 삭제한다. 삭제 실패 유예가 없다. `archive/server.py`는 여러 HTTP 요청을 동시에 처리하며 캐시 파일을 열어 전송한다.

Windows에서 이전 미리듣기 파일이 아직 열려 있다면 삭제가 거부될 수 있고, 예외가 새 미리듣기 준비까지 실패시킬 가능성이 있다. macOS와 파일 삭제 동작이 다른 구간이다. **이번에는 코드상의 동시성 위험을 확인했으며 실제 Windows 재현은 하지 않았다.** 원본 영상과 저장된 분할 결과를 삭제하는 경로는 아니다.

보완 시에는 전송 중인 임시 파일의 정리를 유예하고, 정리 실패가 새 재생 요청이나 캐시 인덱스를 훼손하지 않는지 검증한다.

## 기존 Windows 실행 근거가 있는 범위

다음은 새 실측이 아니라 **이번에 다시 대조한 최종 Windows CI 기록**이다.

- 기본 Python 검사 129개, 추가 미디어·기능 검사 138개 통과.
- 한글·공백 경로의 H.264/AAC 생성·읽기·원음 추출, 저장 자료의 오프라인 복구.
- 전체 3개/선택 2개 오디오 트랙의 무인코딩 분할, 영상·선택 오디오 패킷 해시 동일, 원본 해시 유지.
- 선택 AAC 미리듣기 파일 생성과 패킷 보존.
- 동봉 Jua 한글 글꼴·공백 렌더링, PNG 자막 및 이미지 클립 합성.
- 세로 분할 화면·자막·페이드·여러 구간 연결.
- 외부 AI ZIP 검증·가져오기, 댓글 목록 수정·충돌 보호, Windows 휴지통·잠금 처리.
- 채팅 임시 DB는 Windows에서도 보관함 외 `%LOCALAPPDATA%\ChiDaAnalyzer\temporary` 사용.
- 자동화·부분 분석의 상태/계약 검사가 있으나 실제 모델·네트워크를 대체한 검사도 포함된다.

## 의도한 제한 및 아직 확인하지 않은 항목

- FluidAudio는 Apple Silicon macOS 전용이다. Windows ZIP 누락과는 구분한다.
- pyannote의 현재 Windows 처리 장치는 CPU이다. 앱의 CPU+GPU 옵션은 Whisper·Gemma의 Vulkan 경로에 적용된다.
- 클립 영상 인코딩은 양쪽 모두 libx264 CPU 처리다. NVENC·QSV·VideoToolbox 가속이 한쪽에서 누락된 상황이 아니다.
- 영상 나누기의 H.264/AAC MP4·단일 영상 트랙·일정 프레임률 등 입력 제한은 양 OS 공통이다.
- 실제 Windows GPU 추론, 설치된 모든 글꼴, 파일 선택창 조작, 브라우저의 오디오 전환·동기화는 미검증이다.
- 긴 VOD, 외장 디스크 탈착·공간 부족·긴 경로·보안 소프트웨어 차이는 별도 실환경 검증이 필요하다.
- macOS 공증·Windows Authenticode 서명은 미적용 상태를 유지한다.

## 다음 수정 시 검증 기준

1. 배포 FFmpeg의 HTTPS/TLS 확인 후 두 OS에서 실제 HTTPS 영상의 짧은 구간 수신·취소·재시도·출력 검사. 실패 메시지에 정확한 원인과 로그 위치 제공.
2. Windows 기본 앱만 설치한 상태에서 pyannote/sherpa 도구 다운로드·검증·활성화·재실행·기존 모델 재사용. FluidAudio는 지원하지 않는 OS에서 설치를 유도하지 않음.
3. 깨끗한 Windows 환경에서 제한된 PATH 그대로 CPU·GPU·RAM 리포트 조회. 조회 거부 시 이유 표시 및 과거 리포트 보존.
4. 오디오 캐시 8개 초과, 파일 전송과 정리 동시 실행, 삭제 거부·앱 종료 상황을 Windows에서 확인. 원본·완료 출력의 해시 유지.

## 근거 파일

프로젝트 상위 `outputs/windows-support-audit-20261030/`에 이번 점검 근거를 저장했다.

- `package-inventory.json`: 실제 두 ZIP의 웹 자산·Python 모듈·의존성·실행기 목록.
- `ffmpeg-capabilities.json`: CI 코덱·필터·프로토콜 집합 비교 및 이번 macOS 바이너리 프로토콜 실행 결과.
- `speaker-tools-release.json`: 재조회한 공개 화자 도구 자산 목록.

기존 실행 근거는 `outputs/github-builds/2026-10-30-cross-platform/`의 OS별 CI 로그와 `release/*-smoke.json`을 사용했다. 이번 점검으로 기존 문서의 통과 기록을 취소하는 것은 아니지만, 그 기록은 해당 검사 범위에만 유효하다.
