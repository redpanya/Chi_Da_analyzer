# 패턴 크기 50% 축소와 간격 조정

작업일: 2026-10-23

## 적용 값

- 패턴 이미지의 표시 크기: 512×512px → **256×256px**. 안의 각 소품도 가로·세로가 기존의 50%다.
- 패턴 묶음 사이 기본 간격: **96px**. 묶음 안의 소품 배치는 원본을 유지하며 함께 축소한다.
- 화면 위·아래 여백 기준: 간격의 절반인 48px. 가로는 들어갈 수 있는 묶음을 좌우 가장자리까지 균등하게 배치하며 남는 너비를 간격에 더한다. 따라서 실제 가로 간격은 최소 96px이고 창 너비에 따라 더 넓어질 수 있다.
- 불투명도: 직전 조정값 **28% 유지**.

크기만 256px로 줄여 반복하면 면적당 반복 수가 약 4배가 된다. 이를 피하려고 이미지 크기와 반복 간격을 분리했다. 80px 간격의 앱 시안을 먼저 확인했으며, 여러 액세서리가 들어 있는 패턴의 반복이 빽빽해 보이는 점을 고려해 96px로 넓혔다. 최종 앱 화면에서 작은 모자·리본과 본문 사이 여백을 확인했다.

이 값은 화면에 들어갈 수 있는 칸 수가 바뀌는 CSS 격자 방식이다. 창이 커지면 장식 칸을 추가하며, 화면 밖의 칸은 잘라 표시한다. 창 크기 변경이나 앱 메뉴 전환 때 배경 종류를 새로 뽑지 않는다.

## 변경 범위

- `web/pattern-background.css`: 단일 반복 배경 대신 256px 장식 칸과 독립적인 96px 간격을 지정.
- `web/pattern-background.js`: 문서 시작 시 장식 레이어를 만들고 화면 크기에 맞는 칸 수를 배치. 칸 수가 같으면 다시 생성하지 않음.
- `tests/test_pattern_background.cjs`: 8종 선택, 정확한 50% 크기, 간격, 창 크기별 칸 수, 재배치 중 종류 유지와 접근성 검사를 보완.
- 로컬 매뉴얼과 GitHub용 앱·매뉴얼 체크아웃에 같은 CSS·JS 반영.
- 매뉴얼의 CSS·JS 요청 주소에 파일 내용 해시를 붙여, 배경 변경 후 예전 파일 캐시가 남는 문제를 방지. 생성·검사 스크립트에서 해시와 실제 파일의 일치 확인.

## 영향·예외 처리

- 픽셀 그림을 다시 생성하거나 리사이즈해 저장하지 않는다. 기존 WebP 8종과 원본 소품, 전체 이미지 용량 183,728바이트는 동일하다.
- 장식 레이어는 `aria-hidden`으로 내용 탐색에서 제외하고 `pointer-events: none`으로 버튼·입력을 가리지 않는다. 고정 레이어이므로 본문 배치 공간을 차지하지 않는다.
- 선택된 같은 이미지 파일을 여러 칸에서 재사용하며 다른 7종을 미리 불러오지 않는다. 외부 요청·애니메이션·주기적 작업은 없다.
- 인쇄와 강제 고대비에서는 장식을 숨긴다. 이미지가 없으면 기존 단색 배경을 유지한다.
- 매우 좁은 창에서는 256px 칸 일부가 잘릴 수 있으나 가로 스크롤을 추가하지 않는다. 기존 데스크톱 본문 배치에는 개입하지 않는다.
- VOD·전사·요약·화자 배정·사용자 설정에는 영향이 없다. 앱 패키지는 이번 표시 수정에서 다시 빌드하지 않는다.
