# 화자 실행 도구의 앱 내 별도 설치

## 요청과 원인

sherpa·pyannote·FluidAudio 실행 도구를 모델과 별개로 설치할 수 있게 한다. 기존 모델과 전사·화자 결과·수동 배정은 유지한다. 앱 전체 패키징은 이번 작업 범위에 포함하지 않는다.

기존의 `선택 모델 준비·검사`는 모델만 준비했다. 기본 배포본에 없는 pyannote·FluidAudio를 선택하면 버튼을 눌러도 실행기 없음 오류로 끝났다. 개발용 가상환경·Swift 빌드는 일반 사용자의 앱 설치 방법이 아니다.

## 구현

- 도구 설치, 실행 도구 검사, 모델 준비·검사를 별도 버튼으로 구분한다.
- 미설치 / 앱에 포함됨 / 개발 환경 도구 / 별도 설치됨 / 현재 장치 미지원 상태를 표시한다.
- 도구가 없으면 모델 준비·전체 화자 분석을 비활성화한다. API에서도 동일 조건을 검사한다.
- 설치·검사 중에는 엔진 변경과 중복 작업을 막고 기존 진행률·소요 시간·중단 버튼을 사용한다. 오류 메시지는 작업 상태에 남긴다.
- 설치된 외부 도구를 우선 사용한다. 외부 설치가 없으면 기존 앱 내 도구 또는 개발 환경을 재사용한다. 포함된 sherpa를 삭제하지 않는다.
- sherpa의 외부 도구는 화자 분석뿐 아니라 전사의 발화 검출과 화자 보정 후보 음향 비교도 처리한다.
- pyannote의 이미 받은 모델은 로컬 해시 검사로 준비 완료를 확인할 수 있다. 정상 모델에 HF 인증·재다운로드를 다시 요구하지 않는다. 최초 gated 모델 다운로드의 이용 동의·로컬 인증은 별도이며 기존 정책을 유지한다.
- 모델 폴더 설정, 모델 서명, 분석 결과 서명과 저장 형식은 변경하지 않는다.

## 위치와 배포 계약

| 구분 | 위치 |
|---|---|
| macOS 실행 도구 | `~/Library/Application Support/치지직 보관함/speaker-tools/<엔진>/` |
| Windows 실행 도구 | `%LOCALAPPDATA%\ChiDaAnalyzer\speaker-tools\<엔진>\` |
| 모델 | 기존 사용자가 지정한 AI 폴더 그대로 |
| 전사·화자 결과 | 기존 VOD 보관함 그대로 |

실행 도구는 사용자 권한으로 설치하며 시스템 Python·pip·Swift·관리자 권한을 요구하지 않는다. 원본 VOD나 전사·채팅·HF 토큰을 설치 패키지에 넣지 않는다.

다운로드 대상은 `redpanya/Chi_Da_analyzer`의 고정 `speaker-tools-v1` Release에 있는 아래 이름만 허용한다. 일반 앱의 최신 릴리스를 임의로 실행하지 않는다.

- `chida-sherpa-macOS-arm64.zip`
- `chida-pyannote-macOS-arm64.zip`
- `chida-fluid-macOS-arm64.zip`
- Windows는 `chida-sherpa-Windows-x64.zip`, `chida-pyannote-Windows-x64.zip` 계약을 사용한다. Windows 실행 검증과 이 두 파일 배포는 별도로 필요하다.
- FluidAudio는 Windows에서 비활성화한다.

상태 조회·엔진 선택만으로 인터넷에 접속하지 않는다. 사용자가 설치 버튼을 눌렀을 때 공개 GitHub API의 파일 크기와 SHA-256을 확인하고 HTTPS로 내려받는다. 사용자 임의 URL·로컬 스크립트·셸 명령을 설치 API 입력으로 받지 않는다.

## 설치 단계와 예외 처리

1. 해당 엔진 설치 폴더에 프로세스 잠금 획득.
2. 공개 릴리스·파일명·HTTPS 주소·크기·해시 메타데이터 확인.
3. 새 임시 폴더에 내려받아 크기·SHA-256 검사.
4. 압축의 상위 경로 탈출·절대 경로·연결 파일·중복 경로·Windows 장치명/ADS·과도한 압축 해제 크기 거부.
5. 앱 프로토콜·OS·엔진·실행 파일명 검사.
6. 모델이나 사용자 음성을 읽지 않는 실행 검사를 최대 2분 수행.
7. 새 버전 폴더를 만든 뒤 `active.json`만 원자적으로 교체.

취소·네트워크 오류·공간 부족·잘린 파일·실행 실패·잘못된 패키지는 활성 도구를 교체하지 않는다. 정상 종료·실패·취소 시 이번 임시 설치 폴더를 정리한다. 이전 도구 버전은 제거하지 않아 반복 재설치 시 디스크 사용량이 늘어날 수 있다. 강제 종료로 남은 `.install-*` 임시 폴더는 활성 도구가 아니며 다음 실행에서 사용하지 않는다.

원격 파일이 아직 배포되지 않았으면 “설치 파일이 아직 공개 배포되지 않았습니다”, OS용 파일이 없으면 해당 OS 미배포 안내를 표시한다. 이를 설치 완료나 모델 인증 실패로 표시하지 않는다. GitHub 요청 제한은 잠시 후 재시도 안내로 구분한다.

## 영향과 범위

- 설치 작업은 VOD의 진행 상태·작업 시간을 기록하지만 기존 결과의 활성 버전, 수동 이름·배정, 전사 교정과 원본 파일을 변경하지 않는다.
- 외부 도구가 활성화되면 같은 엔진을 사용하는 이후 작업부터 적용한다. 실행 중인 이전 도구 파일은 삭제하지 않는다.
- 설치 파일 검증은 다운로드 무결성과 기본 실행 확인이다. 모델 품질이나 모든 PC에서의 동작을 보증하는 검사는 아니다.
- macOS 별도 실행 파일은 로컬 빌드의 임시 서명이며 Developer ID 서명·공증을 추가하지 않았다. Gatekeeper 정책을 자동으로 해제하지 않는다.
- 기존 앱은 내장 코드가 바뀌지 않는다. 이번 변경을 배포 앱에 반영하려면 추후 앱 빌드가 필요하다.

### 실제 macOS 설치 확인

공개 [실행 도구 전용 사전 배포](https://github.com/redpanya/Chi_Da_analyzer/releases/tag/speaker-tools-v1)에 3개 도구와 해당 소스 ZIP을 게시했다. 기존 앱의 최신 릴리스 지정은 변경하지 않았다. GitHub가 기록한 해시와 로컬 해시가 모두 일치했다.

앱과 동일한 설치 함수를 사용해 인증 토큰 없는 HTTPS 다운로드부터 실제 내장 앱 지원 폴더 설치·실행 확인까지 수행했다. 설치 도구는 해당 Mac에서 그대로 사용할 수 있다.

| 엔진 | ZIP 크기 | 다운로드~설치·실행 검사 | 결과 |
|---|---:|---:|---|
| sherpa | 53,414,911 bytes | 22.68초 | 통과 |
| pyannote | 242,413,022 bytes | 113.33초 | 통과 |
| FluidAudio | 2,161,460 bytes | 1.86초 | 통과 |

이 시간은 네트워크·디스크·최초 모듈 로드가 포함된 단일 설치 측정이며 화자 분석 성능 측정이 아니다. pyannote의 검사 로그에는 선택적 TorchCodec/FFmpeg 디코더 경고가 있다. 현재 앱은 기존과 같이 SoundFile로 WAV를 읽어 파형을 넘기며 TorchCodec 디코더를 사용하지 않는다. 이번에는 설치·모듈 로드만 확인했고 긴 VOD 재분석은 하지 않았다.

내부 브라우저에서 실제 기존 VOD를 열어 다음을 확인했다.

- FluidAudio 실행 도구 검사 완료.
- 설치 버튼 → 진행 중 잠금 → 다운로드·검사 → “실행 도구 설치 완료” → “다시 설치” 버튼으로 갱신.
- pyannote 선택 시 “실행 도구 · 별도 설치됨”, “모델 준비 완료 · 바로 사용 가능 (오프라인)” 표시.
- 기존 모델 경로와 기존 화자 결과 1개 유지. 기존 결과를 재분석하거나 이름을 변경하지 않았다. 설치/검사 작업 상태와 새 검사 로그만 추가했다.

검증 기록은 워크스페이스의 `outputs/speaker-tools-validation-20261020/result.json` 및 `remote-result.json`에 저장했다. 전자는 격리 폴더의 로컬 ZIP 설치, 후자는 실제 공개 다운로드 설치 기록이다.

### 남은 범위

- Windows용 sherpa·pyannote ZIP은 아직 배포하지 않았다. 이 두 플랫폼의 설치 경로·명령 구성은 구현했으나 Windows 설치 버튼은 파일 미배포 안내를 반환한다. Windows 제작·실기 확인 후 해당 태그에 별도 파일을 추가해야 한다.
- macOS Developer ID 서명·공증과 다른 Mac/OS 버전에서의 실행은 미검증이다.
- 앱 전체 패키지를 새로 만들지 않았다. 수정판은 소스로 실행했으며 기존 `.app`에 반영하려면 후속 빌드가 필요하다.

## 실행 도구 패키지 제작

앱 빌드와 분리된 `packaging/speaker_tools/build.py`로 도구별 ZIP과 검증 JSON을 생성한다. 이 스크립트는 업로드하지 않는다. 고정 버전 의존성이 설치된 전용 환경에서 실행한다.

```sh
.release-venv/bin/python packaging/speaker_tools/build.py sherpa --output ../outputs/speaker-tools-v1/macos-sherpa
.diarization-tools/pyannote/venv/bin/python packaging/speaker_tools/build.py pyannote --output ../outputs/speaker-tools-v1/macos-pyannote
```

FluidAudio는 고정 소스의 `native/fluid-diarizer`를 먼저 빌드한 뒤 `--fluid <빌드된 실행 파일>`을 지정한다. 각 ZIP에 실행 검사 응답과 프로토콜 정보, 라이선스·출처를 포함한다. Python 도구는 Python 실행 환경을 같이 포함한다. 모델 파일은 포함하지 않는다.

공개 배포 시 기존 `speaker-tools-v1` 파일을 덮어쓰지 않는다. 프로토콜·의존성이 달라지는 후속 배포는 새 태그를 만들고 앱의 고정 태그를 함께 변경한다.
