# Electron 포터블 앱 1.2.0 구현과 빌드 검증

## 실행과 업데이트

동일한 웹 화면과 Python 처리 서버를 Electron 45.3.3의 앱 창에서 실행한다. 별도 트레이는 없다. 동봉한 Python 처리기는 창이 닫힐 때 작업을 정리한다. 원본, 분석 결과, 모델은 기존 위치를 사용한다. 첫 화면의 돋보기 렌즈를 녹색(#00FFA3) 원으로 채웠다. 메뉴 이동 시 기존 20개 개별 픽셀 소품이 번갈아 표시된다. 설정과 설명서에 스트리머와 클리퍼를 위한 비공식 도구이며 네이버 및 치지직과 관계가 없다는 안내를 추가했다.

| 앱 설정에서 선택하는 동작 | 처리 |
|---|---|
| 업데이트 확인 | 공식 GitHub 정식 릴리스의 태그, OS, CPU, 배포 목록의 Ed25519 서명을 확인한다. 새 버전이 있어야 다운로드 버튼이 활성화된다. |
| macOS Apple Silicon | 받는 폴더를 직접 선택한다. 크기와 SHA-256 검증을 마친 DMG만 표시한다. 같은 이름의 파일은 보존한다. Finder에서 DMG를 열고 앱을 종료한 뒤 수동으로 교체한다. |
| Windows x64 | 받기가 완료되면 전용 보조 실행기가 ZIP을 다시 검증하고 임시 폴더에 먼저 푼다. 실행 중이거나 대기 중인 작업, 앱 안의 사용자 자료, 권한 문제는 기존 앱을 유지한 상태에서 안내한다. 교체 후 새 창과 Python 서버가 기동을 확인하면 이전 사본을 정리한다. 기동 실패 시 이전 프로그램으로 복귀한다. |

1.1.0의 브라우저 실행기에서 이 버전으로 처음 전환할 때는 DMG 또는 ZIP을 직접 받는다. 업데이트 발행 서명과 macOS 코드 서명은 용도가 다르다. macOS 앱은 Apple Silicon 실행용 로컬 서명만 사용한다. Apple Developer ID 및 공증은 사용하지 않는다. Windows 빌드에도 별도의 Authenticode 게시자 인증서를 적용하지 않았다.

## 라이선스와 발행 절차

자체 프로그램은 MIT이다. 설정에서 실제 패키지의 고지 폴더를 열 수 있다. Electron MIT, Chromium 전체 고지 HTML, Node.js 24.22.3 통합 고지, Python 런타임과 종전 엔진 및 글꼴의 원문을 함께 제공한다. 화면 재생용 공유 FFmpeg의 고정 소스와 Electron 패치 및 빌드 자료는 별도 ZIP에 들어 있다. CLI용 FFmpeg와 x264의 GPL 대응 소스 및 기존 음성 라이브러리 대응 소스도 함께 제공한다. 사용한 모델의 이용 조건 및 입력 영상 권리는 각각 적용된다. [재배포 고지](../THIRD-PARTY-NOTICES.md), [소스와 교체 경로](third-party-source-guide.md)

공식 버전을 발행할 때 두 플랫폼 빌드의 체크섬 검사를 통과한 파일을 한 폴더에 모은 뒤 아래 명령을 실행한다. 앱에 내장한 공개키와 맞는 개인키는 빌드 및 소스 저장소 밖에서 보관한다.

```sh
node packaging/release/sign_update.cjs 배포폴더 --key 개인키파일
```

같은 버전의 DMG, ZIP, 고지, 대응 소스, `update-manifest.json`, `update-manifest.sig`를 그 버전의 GitHub 정식 릴리스에 첨부해야 앱 설정에서 새 버전으로 표시된다. Actions의 산출물이나 초안은 앱 업데이트 대상으로 표시하지 않는다.

## 검증

로컬 macOS에서 격리한 보관함으로 실제 Electron 창을 열었다. Python 서버의 준비 신호, 첫 화면, 샌드박스 안의 설정 IPC, 버전 1.2.0, 정상 종료를 확인했다. 별도로 만든 로컬 DMG도 읽기 전용으로 마운트해 Electron 45.3.3 창에서 녹색 렌즈, 앱 설정, 고지 버튼, 비공식 안내와 수동 교체 안내를 확인했다. 제품 설정과 원본 VOD는 사용하지 않았다. [상세 검사 기록](verification/2026-11-16-Electron-실행과-종료.md)

macOS와 Windows의 자동 검사에서는 합성 자료로 자막이 들어간 클립, H.264/AAC 처리, 다중 오디오 분할, 다운로드 복구 및 원본 보존을 다룬다. Windows의 포터블 검사에서는 임시 구버전 실행 파일을 준비한 뒤 배포 ZIP 자체로 교체한다. 새 앱 시작을 의도적으로 실패시킨 경우 이전 실행 파일 복원과 재기동을 별도로 검사한다.

### Windows의 실제 교체 결과

Windows Server 2022 x64에서 검사 대상으로 쓰는 구버전 실행 파일을 종료한 뒤 실제 배포 ZIP으로 교체했다. 새 Electron 45.3.3 창과 새 Python 서버의 기동을 확인했다. 두 번째 시험에서는 새 앱의 준비 사본에 시작 실패를 유도했다. 교체 도구가 구버전을 복원하고 이전 실행 파일을 다시 열었다. 두 경우 모두 프로그램 밖의 결과 파일과 원래 ZIP의 SHA-256을 보존했다.

Windows 장경로와 짧은 별칭을 같은 파일로 인식하도록 보완했고, 실제 ICO를 EXE에 넣었다. 검증에서는 빈 보관함, 모델, 사용자 설정 폴더를 명시해 현재 사용자의 설정을 읽기 전에 분리했다. 사용자가 편집한 댓글의 저장이 대기 중이거나 실패한 경우와 AI 또는 미디어 작업이 진행 중인 경우에는 업데이트를 보류한다.

2026년 11월 16일, 소스 커밋 `1ca41b6340e0ab301eefaa54c3ebb7b3031eb0f8`에서 macOS Apple Silicon 및 Windows x64 빌드 작업이 모두 성공했다. [GitHub Actions 실행 43843138532](https://github.com/redpanya/Chi_Da_analyzer/actions/runs/43843138532)

|---|---:|---|

| ChiDaanalyzer-1.2.0-Windows-x64.zip | 308,788,240 | `1353fce1f654206dbc6b25d51fff0519119365b78cb87fe7148d58ddaff3b323` |

각 러너에서 완성된 DMG 또는 ZIP으로 실제 Electron 창을 띄워 녹색 렌즈, 앱 설정, 라이선스 버튼, 버전, 독립 도구 안내 및 해당 OS의 업데이트 안내를 검사했다. 매체와 원본 보존 검사는 샘플 VOD로 진행했다. Windows에서는 포터블 교체와 복원을 추가로 검증했다. 다운로드한 최종 DMG를 Apple Silicon Mac에서 다시 마운트하고 정상 기동 및 종료를 확인했다. Windows ZIP의 등록된 파일 564개와 실제 파일 목록도 일치했다.

최종 파일 두 건의 크기와 SHA-256을 대조한 후 배포 목록을 Ed25519로 서명했다. 로컬에서 GitHub 응답만 대체해 앱의 실제 업데이트 수신기를 실행했다. 서명된 DMG는 수동 교체 대기 상태, ZIP은 재실행 대기 상태에 도달했고 저장된 두 파일의 해시가 배포 원본과 일치했다. 프로그램 폴더와 같은 위치에 있는 고지 ZIP, 대응 소스 ZIP, 두 운영체제의 검사 JSON, 서명 파일, 체크섬 목록을 함께 보관한다.

빌드 검증 브랜치에 소스와 워크플로를 올렸다. 검증 시점의 GitHub 공개 정식 릴리스는 v1.1.0이다. 실제 공개 릴리스를 통한 사용자 업데이트, 인터넷에서 받은 미공증 앱의 기기별 최초 허용, 장시간 VOD의 AI 모델 추론 및 Windows 물리 GPU 성능은 이 검증에 포함하지 않았다.
