상태: 아이디어 검토와 설계 제안. 기능 구현, 모델 설치, 앱 빌드, 외부 서비스 생성·게시·업로드는 하지 않았다. 아래 기본값과 단계는 권장안이며 구현 완료 상태가 아니다.

## 1. 전체 판단

세 기능은 함께 구성하면 효과가 크다. 다운로드 목록을 공통 작업 대기열로 만들고, 자동화가 각 VOD의 단계를 실행하며, 리포트가 같은 실행 기록을 집계하는 구조를 권장한다. 각각 별도 실행기를 만들면 작업 중복·중단 복구·시간 기록이 서로 어긋날 수 있다.

현재 구현과 추가 요청을 반영한 처리 기준은 다음과 같다.

1. **현재 화자 구분은 전사 완료 후 실행한다.** `archive/voices.py`의 `input_audio()`는 현재 오디오와 일치하는 완료 전사를 요구하고, 화자 분석 후 그 전사 구간에 화자를 배정한다. 따라서 기본 자동화 순서는 전사 → 화자 구분이 맞다. 화자 음향 분석 자체를 먼저 하는 방식은 가능하지만, 현재 코드를 음향 분석과 전사 배정의 두 단계로 나누는 추가 설계가 필요하다.
2. **말소리 분리는 자동화·신규 개발 범위에서 제외한다.** 별도 분리 옵션·모델 설치·분리음 전사·실패 대체 경로를 만들지 않고 기존 원음 추출·전사 흐름을 사용한다. 과거 분리 결과의 파일과 열람 기능은 이번 범위 제외를 이유로 삭제하지 않는다. 누가 말했는지 배정하는 화자 구분은 별도의 선택 기능으로 유지한다.

## 2. 다시보기 다운로드 목록

### 입력과 실행 화면

- 가져오기 페이지에서 행마다 `순번 / VOD 주소 / 확인된 제목·길이 / 입력 상태 / −`를 표시한다. 목록 하단 `+ 주소 추가`로 입력칸을 늘린다.
- 입력 전 빈 행의 `−`는 행만 제거한다. 대기열에 등록된 항목은 ‘목록에서 제외’로 표현하여 기존 VOD 파일 삭제와 구분한다.
- 실행 중 항목은 바로 제거하지 않고 중단 완료 후 대기열에서 제외한다. 보관함 자료는 남긴다.
- `다운로드만`과 `자동 분석까지` 두 실행 범위를 제공한다. 선택한 범위와 총 영상 길이를 시작 버튼 위에서 확인할 수 있게 한다.
- 등록 후에는 `대기 / 영상·채팅 수집 / 검증 / 분석 단계 / 완료 / 일부 완료 / 조치 필요 / 중단됨`을 행에 표시한다. 실패 이유와 재시도도 해당 행에 붙인다.
- 설명은 기존 💡 오버레이 원칙을 따르고, 진행 상태·실패 원인은 화면에 남긴다. 현재 데스크톱 배치와 저장 폴더 설정은 유지한다.

### 순서와 저장 기준

- VOD 사이에는 입력 순서를 지킨다. 기본안은 **1번 VOD의 선택된 전체 작업 완료 → 2번 VOD 시작**이다. `다운로드만`이면 영상·채팅 수집과 검증을 마친 뒤 다음 항목으로 이동한다.
- 한 VOD 안의 영상·채팅 수집은 기존 동작을 재사용할 수 있지만 서로 다른 VOD의 수집·추론을 동시에 시작하지 않는다.
- 주소 문자열이 달라도 같은 VOD ID로 해석되면 중복 등록을 알린다. 기존 보관함에 있는 VOD는 완료 결과와 입력 조건을 확인해 이어받기·재사용하며 무조건 다시 받지 않는다.
- 각 VOD의 기존 독립 저장 폴더를 유지한다. 목록에서 제거하는 행위가 자료 삭제로 이어지면 안 된다.
- 화질 설정은 특정 영상의 format ID를 전체 영상에 복사하지 않고 ‘가능한 최고 화질 / 지정 해상도 이하’ 같은 선택 정책으로 저장한다. 없는 화질의 대체 규칙을 표시한다.
- 실행 설정은 항목 등록 시 저장한다. 실행 중 전역 설정 변경이 현재 작업을 바꾸지 않게 하고, 대기 항목에 적용할 때도 적용 대상을 명확히 한다.

## 3. 자동화 권장 순서

```text
영상·전체 제공 채팅 다운로드
→ 영상 검증·채팅 제공 범위 확인
→ 원음 추출
→ 음성 전사
→ 화자 구분·전사 배정 (선택, 기본 꺼짐)
→ 채팅 반응 분석
→ AI 문맥 요약
→ 실행 리포트 확정
→ 다음 VOD
```

채팅 반응 분석은 기존 🤩 표시와 클릭 가능한 반응 시각을 만들기 위해 자동화에도 포함해야 한다. 화자 구분을 건너뛰더라도 기존 내용 중심 요약을 사용할 수 있다. Gemma 기본 모델과 사고 설정은 기존 값을 유지하고 자동화 시작 시 저장한다.

### 원음 전사와 기존 결과 보존

- 새 자동화의 전사 입력은 영상에서 추출한 원음으로 고정한다. 화자 구분을 선택하면 현재 오디오와 전사 입력의 일치 여부를 기존 방식으로 검증한다.
- 완료 결과는 입력 영상·오디오 해시, 모델·버전·설정이 일치할 때만 재사용한다. 과거 분리음 전사를 원음 전사의 완료 결과로 잘못 재사용하지 않는다.
- 이전 전사·수동 교정·화자 배정에 새 자동 결과를 덮어쓰지 않고 새 결과 버전을 만든다. 기존 수동 결과를 재사용할 때도 실제 입력과 설정이 맞는지 확인한다.

### 상태 전환과 복구

자동화는 브라우저 타이머나 버튼 자동 클릭으로 구현하지 않고 기존 작업 관리자의 백엔드에서 실행한다. 새로고침·메뉴 이동은 실행 수명에 영향을 주지 않아야 한다. 앱 자체가 종료되면 작업은 멈추며, 다음 실행에서 대기열과 완료 구간을 복구한다. 재실행 직후 사용자 의사 확인 없이 장시간 GPU 작업을 자동 시작하기보다는 ‘이어 진행’ 상태로 복원하는 것을 기본안으로 한다.

다음 단계는 앞 단계의 상태 문구만 보고 시작하지 않는다. 성공 상태, 필요한 결과 파일·버전, 실행 종료와 잠금 해제를 확인한다. 완료 이벤트를 놓쳐도 저장된 상태로 복구하며 같은 단계를 두 번 시작하지 않아야 한다. UI의 완료 표시 갱신 수정은 이 백엔드 자동화 자체를 대체하지 않는다.

| 상황 | 권장 처리 |
| --- | --- |
| 일시적 다운로드·채팅 통신 실패 | 제한된 재시도 후 해당 VOD를 조치 필요로 남기고 다음 항목 진행 |
| 삭제·비공개·로그인 필요 VOD | 접근 제한을 우회하지 않고 해당 항목 보류, 이유 표시 |
| 공식 미제공·빈 채팅 | 실패와 구분하여 전사 기반 처리 가능, 리포트에 미제공 기록 |
| 채팅 경계 검증 실패·일부만 수집 | 완전 수집으로 표시하지 않음. 부분 자료 사용을 미리 허용한 경우에만 경고를 유지하며 계속 |
| 디스크 부족·저장 볼륨 분리·필수 엔진 부재 | 모든 후속 작업에서 반복 실패할 수 있으므로 전체 대기열 일시정지 |
| 선택한 화자 구분 단계 실패 | 미리 정한 ‘건너뛰고 계속’ 정책 적용 가능. 생략·실패를 리포트에 기록 |
| 필수 전사 실패 | 해당 VOD의 의존 단계는 시작하지 않고 다음 VOD 진행. 범위 일부 전사 허용은 별도 명시 필요 |

| 사용자 중단 | 안전하게 현재 작업을 정리하고 다음 VOD를 시작하지 않음. 완료 결과 유지 |
| 앱 비정상 종료·PC 절전 | 미확정 작업은 중단 상태로 복구. 기록하지 못한 시간·처리량은 추정하여 채우지 않음 |

모델은 시작 전 준비 상태를 검사한다. 다운로드할 모델 크기·이용 동의 필요 여부를 알리고 사용자 승인 없이 HF 약관 동의를 대신하지 않는다. 모델 준비 시간은 분석 실행 시간과 분리한다.

## 4. 분석기 리포트

### 메뉴와 표시

AI 문맥 정리 다음에 **`7 리포트`** 메뉴를 추가하는 안을 권장한다. 완료 후뿐 아니라 실행 중·실패 상태에서도 열 수 있어야 한다.

상단에 PC 정보와 해당 실행의 전체 시간을, 가운데에 단계별 시간·처리량 표를, 하단에 접을 수 있는 실행 로그와 업로드 영역을 둔다. VOD 한 개와 전체 대기열을 선택할 수 있게 하되, 첫 구현의 상세 기준은 VOD별 실행 한 건으로 잡는다.

### 기록할 항목

| 구분 | 기본 수집·표시 항목 |
| --- | --- |
| PC | OS·버전·아키텍처, CPU 모델·코어/스레드 수, GPU 모델, RAM 총량 |
| 처리 장치 | 단계별 CPU/Metal/Vulkan 등의 요청 방식과 엔진에서 확인한 실제 사용 장치, 확인 불가 여부 |
| 프로그램 | 앱 버전·빌드 식별, 엔진·모델 버전, 양자화, 사고 설정, 주요 전사·화자 옵션 |
| 대상 크기 | 원본 영상 길이, 실제 처리 범위, 해상도·코덱·파일 크기, 음성 샘플레이트·채널 수 |
| 단계별 시간 | 시작·종료, 실제 실행, 준비·모델 로딩·검증, 대기·중단, 재시도 시간 및 횟수 |
| 전사량 | 원본·현재 유효 전사의 발언 수·문자 수, 실제 처리 음성 길이, 기존 결과 재사용 여부 |
| 채팅량 | 수집 건수·문자 수, 중복 처리 후 건수, 실제 분석 대상 범위·사용량, 수집 완전성 |
| 요약량 | 고유한 입력 발언·채팅 수와 문자 수, 모델 요청 전체 입력·출력 토큰, 캐시·재시도·완료 결과 재사용 수 |
| 결과 | 성공·일부 완료·실패·취소·생략·재사용, 실패 단계·오류 코드·정리된 오류 메시지 |

CPU·GPU·RAM 조회는 가능한 범위에서 운영체제와 엔진 장치 정보를 사용한다. GPU가 여러 개이면 감지된 장치와 실제 실행 장치를 구분한다. Apple 통합 메모리를 별도 VRAM처럼 더하지 않고, 조회할 수 없는 정보는 `확인 불가`로 둔다. 전체 시스템 진단 출력에는 기기 일련번호 등이 섞일 수 있으므로 필요한 필드만 추출한다.

기본 사양 정보만으로 충분히 시작할 수 있다. 지속적인 CPU/GPU 사용률 감시는 첫 범위에 넣지 않는 편이 낫다. 사용률을 비교하려면 측정 오버헤드·다른 프로그램의 부하·OS별 측정 차이를 별도로 검증해야 하기 때문이다.

### 성능 해석 기준

- **음성 처리 시간비 = 해당 단계의 실행 시간 ÷ 실제 새로 처리한 음성 길이.** 예를 들어 60분 음성을 30분에 처리하면 0.5이며, 설명용 가상 예시다. 완료 결과를 모두 재사용했다면 0으로 계산하지 않고 ‘재사용’으로 표시한다.
- 전체 영상 길이만으로 요약 속도를 비교하지 않는다. 발언 밀도, 채팅 양, 실제 모델 입력량, 모델·양자화·사고 설정이 같거나 비슷해야 의미 있는 비교가 된다.
- 고유한 원문량과 겹치는 문맥·재시도로 모델에 반복 입력한 양을 별도 기록한다. 입력 토큰 수를 모두 합친 값을 고유한 전사량으로 표시하지 않는다.
- 모델이 알려준 토큰 수를 우선 사용한다. 없으면 문자 수를 기록하고 토큰 수는 미측정으로 둔다. 서로 다른 모델의 토큰/초는 그대로 같은 척도로 취급하지 않는다.
- 다운로드는 PC 추론 성능과 분리한다. 네트워크 속도·원격 서버 상태 때문에 다운로드 시간이 달라질 수 있다.
- ‘사용자가 기다린 전체 시간’과 ‘단계별 실제 실행 시간’을 함께 표시한다. 초기 모델 다운로드·처음 로딩과 이미 준비된 모델의 실행을 구분한다.
- 실패·중단·절전으로 측정이 끊긴 실행은 불완전 측정으로 표시하며 성공 실행과 섞어 순위를 매기지 않는다. 사용자 자발적 업로드는 표본 편향이 있으므로 대표적인 PC 성능이라고 단정하지 않는다.

### 기존 계측과의 관계

`archive/task_timing.py`의 경과 시간과 `archive/context_metrics.py`의 모델 로딩·토큰·캐시·재사용 통계를 재사용한다. 다만 현재 음성 작업 상태는 모델 준비·추출·전사 사이에 최신 상태로 바뀌므로, 마지막 상태 파일만으로 모든 과거 단계 시간을 복원할 수는 없다.

새 실행부터 단계 시작·종료·실패·재시도 이벤트와 종료 시 통계를 별도 기록한다. 기존 원본과 분석 결과 형식은 유지하고 실행 ID로 연결한다. 과거 기록이 없는 값은 ‘미기록’으로 표시한다. 로그는 용량 한도와 교체 보관 규칙을 두어 장시간·다중 VOD에서 계속 커지지 않게 한다.

## 5. 버튼 한 번으로 운영자 Google Drive에 업로드

### 가능한가

가능하다. 여기서 ‘내 구글 드라이브’는 **분석기 운영자인 요청자의 Drive**에 이용자 리포트를 모으려는 뜻으로 해석했다. 이용자 자신의 Drive에 저장하는 기능과는 인증 구조가 다르다.

권장 경로는 다음과 같다.

```text
앱이 허용된 항목만 담은 작은 JSON 리포트와 미리보기 생성
→ 사용자가 정보 종류·보호 방식·개선 목적을 확인
→ 선택 동의 체크 (기본 미체크)
→ 활성화된 ‘데이터 보내기’ 클릭
→ HTTPS 수집 API
→ 서버에서 형식·크기·중복·전송 한도 검사
→ 운영자 Google Drive의 비공개 전용 폴더에 저장
→ 접수번호와 성공/실패 반환
```

이 구조에서는 이용자가 운영자의 Google 계정으로 로그인할 필요가 없다. 운영자가 최초에 저장 권한을 설정하고 자격 증명은 서버에서만 관리한다. 데스크톱 앱은 비밀값을 안전하게 숨길 수 있는 환경이 아니라는 Google 안내가 있으므로, 운영자 토큰·서비스 계정 개인키를 배포 앱에 넣지 않는다. [Google 데스크톱 OAuth 안내](https://developers.google.com/identity/protocols/oauth2/native-app)

### 구현 경로 비교

| 경로 | 적합한 범위 | 제약 |
| --- | --- | --- |
| Google Apps Script 웹 앱, 운영자 권한 실행 | 소규모 시험·운영 검증 | 실행 시간·동시 실행 등 한도, 공개 수집 주소 악용 방어, 계정·조직별 공개 배포 설정 확인 필요 |
| 별도 HTTPS 수집 API + Drive API | 공개 배포 권장 | 작은 서버 운영과 인증정보 관리 필요. 전송 제한·검증·중복 방어를 제어하기 좋음 |
| 각 이용자의 Google OAuth 로그인 | 이용자 본인의 Drive 백업 | 최초 로그인·동의가 필요하며 운영자 Drive 수집과는 다른 기능 |

Apps Script는 POST 요청을 받아 소유자 권한으로 실행하는 웹 앱을 지원한다. 공개 접근 허용 여부는 실제 계정·조직 설정에서 확인해야 한다. 단순히 URL이나 앱에 공통 키를 넣는 것은 악용 방지 인증으로 충분하지 않다. [웹 앱 동작·실행 권한](https://developers.google.com/apps-script/guides/web)

Apps Script는 현재 안내상 실행당 6분 제한 등이 있으며 한도를 넘으면 실행이 중단될 수 있다. 짧고 작은 리포트 저장에는 검토할 수 있지만, 운영자의 이용량과 악성 반복 요청까지 포함해 시험해야 한다. [Apps Script 한도](https://developers.google.com/apps-script/guides/services/quotas)

일반 개인 Drive는 운영자 OAuth 권한 또는 운영자 권한 Apps Script로 저장하는 방향이 맞다. 서비스 계정은 자체 파일 소유가 불가능하므로 ‘개인 Drive 폴더 ID와 서비스 계정 키만 있으면 된다’고 설계하지 않는다. 서비스 계정 방식을 택한다면 Workspace 공유 드라이브 등 저장 구조를 별도로 확인해야 한다. [Drive 파일 소유 제한](https://developers.google.com/workspace/drive/api/guides/folder)

### 전송 내용과 보안 기준

- 업로드 전까지는 로컬에만 보관한다. 자동화 완료가 자동 업로드를 뜻하지 않는다.
- 화면에 제출 정보 종류·제출받는 운영자·Google Drive 저장 방식·분석기 개선 목적·보호 조치를 안내한다. 명시적 동의 후 `데이터 보내기`를 눌렀을 때만 전송하며, 전송 전 확인한 리포트 스냅샷만 사용한다.
- 제출 데이터는 분석기의 처리 속도·안정성·오류 개선과 PC 사양별 성능 분석에만 사용한다. 광고·이용자 추적·전사나 요약 모델의 학습 데이터 수집 목적으로 사용하지 않는다. 목적이나 수집 범위를 바꾸려면 안내를 갱신하고 다시 동의를 받는다.
- 영상·음성·전사 본문·채팅 본문·요약 본문·사용자가 입력한 용어 힌트·수동 교정·화자 이름·쿠키·HF/Google 토큰·비밀 로컬 URL·전체 파일 경로·사용자명·PC 이름·기기 ID·일련번호는 제출 항목에서 제외한다. VOD 제목·주소·채널명도 성능 비교에는 필요하지 않아 제외한다. 처리 옵션은 언어·발화 검출 모드·사고 설정 등 허용된 값만 보낸다.
- 원본 로그를 통째로 압축해서 보내지 않는다. 단계명·오류 코드·허용된 메시지 등 구조화된 로그를 우선 생성하고, 추가 진단 텍스트는 경로·인증값·대사 제거 후 크기를 제한한다. 임의 예외 문자열을 그대로 전송하면 마스킹을 피해 본문이나 비밀값이 포함될 수 있다.
- 사양 조합과 시간 정보도 이용자를 추정할 단서가 될 수 있다. ‘완전 익명’이라고 단정하지 않는다. 수집 서버 접속 기록에 IP 등이 남는지도 확인하고 보관 기간·접근자·삭제 요청 방법을 안내한다.
- 기존 GUI는 루프백 수신과 Host/Origin 검사를 유지한다. 업로드용 외부 수신 포트·방화벽 허용·포트 전달은 만들지 않는다. 지정 HTTPS 주소로 나가는 전송만 추가하며, 수집 서버가 이용자 PC에 명령하거나 파일을 요구하는 기능은 두지 않는다.
- 서버는 미리 정한 필드·크기의 JSON만 받고 임의 파일·경로·URL 첨부를 허용하지 않는다. 비공개 저장 폴더는 서버가 정한다. 이용자에게 폴더 읽기·목록 조회·삭제 권한을 주지 않는다.
- 크기 제한, 반복 전송 제한, 중복 접수 방지, 전체 수신 중지 기능을 둔다. 앱에 포함한 공통 비밀키를 유효한 이용자 인증이라고 믿지 않는다. 공개 수집에는 악용 방지용 서버 측 통제가 필요하다.
- 업로드 응답 유실 시 동일 리포트 ID로 재시도해 중복을 만들지 않는다. 이미 같은 ID로 다른 내용이 들어오면 거절한다. 서버가 Drive 저장을 확인한 뒤 성공을 표시하고, 단순 접수만 됐다면 ‘접수됨’으로 구분한다.
- 인터넷 끊김·Drive 용량 부족·권한 만료·쿼터 제한은 리포트 업로드만 실패하게 한다. 완료된 분석과 다음 VOD 처리는 영향을 받지 않는다. 로컬 리포트 저장·수동 재전송을 제공한다.

### 이용자에게 보여줄 안내 문구 초안

아래는 구현 후 실제 제출 형식·로그 검사·접근 제어가 충족됐을 때 사용할 문구다. 현재 기능이 이미 구현되거나 보안 검증이 완료됐다는 의미가 아니다.

> **분석기 개선에 참여해주세요 (선택)**
>
> 제출한 데이터는 치다 분석기의 처리 속도와 안정성을 높이고, 오류를 해결하며, PC 사양별 성능을 개선하는 데 사용합니다.
>
> **보내는 정보:** CPU·GPU·RAM 및 운영체제 정보, 앱·모델 버전과 처리 옵션, 영상·처리 구간 길이, 단계별 처리 시간, 전사·채팅의 건수와 문자 수, 개인정보와 원문 내용을 제거한 실행·오류 기록입니다.
>
> **보내지 않는 정보:** 영상·음성 파일, 전사·채팅·요약 본문, 사용자 입력 내용, 이름·계정 정보, 파일 경로, 기기 고유번호, 비밀번호·인증 토큰입니다. 전사와 채팅은 내용이 아닌 양만 전송합니다.
>
> 개인정보 노출을 줄이기 위해 제출 항목을 제한하고 로그에서 개인정보와 인증정보를 제거합니다. 데이터는 암호화된 HTTPS로 전송하며, 운영자의 Google Drive 비공개 폴더에 저장하고 접근을 제한합니다.
>
> 제출은 선택 사항입니다. 동의하지 않아도 다운로드·전사·요약 등 분석기 기능을 그대로 사용할 수 있으며, 동의 없이 리포트를 전송하지 않습니다.

체크박스 문구: **`[ ] 제출 정보와 이용 목적을 확인했으며, 이 리포트를 분석기 개선 목적으로 보내는 데 동의합니다. (선택)`**

버튼 문구: **`데이터 보내기`**. 미동의 상태에서는 비활성화한다. 체크만으로 전송하지 않고 버튼 클릭이 필요하다. 같은 영역에 `보낼 데이터 보기`를 제공하여 실제 전송 항목을 확인할 수 있게 한다.

‘개인정보가 절대로 유출되지 않습니다’, ‘100% 안전합니다’, ‘완전 익명입니다’와 같은 보장 문구는 사용하지 않는다. 개인정보를 제출 항목에서 제외하는 정책과 전송·보관 보호 조치를 구체적으로 설명한다. PC 사양 조합·서버 접속 기록 등의 식별 가능성까지 없다고 보장할 수는 없다.

배포 전에는 운영자 연락처, 보관 기간, 접근 권한자, 삭제 요청 방법과 수집 서버·호스팅의 IP 접속 기록 처리 방침을 실제 운영 설정에 맞춰 확정하고 같은 안내에서 볼 수 있게 한다. 운영 값이 미정인 상태로 실제 제출을 활성화하지 않는다.

### 동의 상태·재시도·철회 처리

- 매 리포트 제출 화면의 체크박스는 기본 미체크다. 이전 제출의 동의를 다른 VOD·새 리포트·향후 자동 업로드에 적용하지 않는다.
- 동의는 미리보기에서 고정한 리포트 ID·내용 해시·안내 버전에 연결한다. 실행 중 뒤에 생성된 로그를 몰래 추가하지 않으며, 리포트를 새로 생성하거나 안내·목적·정보 종류가 바뀌면 동의를 해제한다.
- 화면뿐 아니라 로컬 제출 API에서도 동의 여부와 대상 스냅샷을 확인하고, 미동의·불일치 요청은 외부 통신 전에 거절한다. 클라이언트의 동의 필드는 이용자 인증이나 악성 요청 방어를 대신하지 않는다.
- 동의 일시·안내 버전·리포트 ID는 제출 이력에 최소한으로 기록한다. 이 기록을 위해 계정 로그인·이름·기기 식별자를 추가 수집하지 않는다.
- 버튼을 누른 같은 전송 작업 내에서는 동의한 동일 데이터만 제한적으로 재시도할 수 있다. 실패 후 나중에 다시 제출하거나 앱을 재실행한 경우에는 다시 동의를 확인한다. 백그라운드에서 무기한 재전송하지 않는다.
- 전송 시작 전 체크를 해제하면 제출하지 않는다. 전송 시작 후 취소는 아직 보내지 않은 요청·재시도를 중단하되, 이미 접수된 데이터까지 자동 회수됐다고 표시하지 않는다. 접수된 데이터는 접수번호로 삭제 요청 절차를 안내한다.
- 제출 여부·실패 여부는 로컬 리포트 생성, 자동화 진행, 분석 결과 보존에 영향을 주지 않는다.

Drive 자체 업로드는 공식 API로 가능하다. 재개 가능한 업로드도 지원하지만 작은 JSON 리포트에서는 우선 수집 API의 접수 ID·중복 방지가 더 중요하다. [Drive 업로드 방식](https://developers.google.com/workspace/drive/api/guides/manage-uploads)

현재 이 채팅의 Drive 연결을 배포 앱이 재사용할 수 있는 것으로 간주하지 않는다. 앱 수집 서비스의 계정·저장 폴더·권한 설정은 별도 준비 사항이다.

## 6. 영향 범위와 구현 순서 제안

기존 `archive/jobs.py`의 단계별 실행·잠금·중단 처리를 재사용한다. 대기열 저장·단계 전환은 별도 모듈로, 리포트 수집·사양 조회·외부 전송은 각각 분리해 기존 파일 하나에 모두 넣지 않는다. GUI는 가져오기·진행 목록·자동화 설정·리포트 화면만 연결하고 기존 수동 실행도 유지한다.

1. **실행 기록과 로컬 리포트 기반**: 단계별 기록 규칙부터 정해야 자동화 성능 데이터를 놓치지 않는다. PC 정보 조회 실패가 작업 실패로 이어지지 않게 한다.
2. **순차 다운로드 대기열**: 주소 추가·삭제, 정규화·중복 확인, VOD별 저장, 중단·재실행 복구, 다운로드만 실행.
3. **기존 기능 자동 연결**: 원음 추출 → 전사 → 선택 화자 구분 → 채팅 반응 분석 → 요약. 전체 대기열은 한 번에 한 VOD를 처리한다.
4. **리포트 메뉴 완성 및 동의 기반 제출**: 로컬 표시·내보내기, 제출 항목 미리보기, 개인정보 보호·개선 목적 안내, 매 제출의 선택 동의를 먼저 준비한다. 운영자 계정·전용 폴더·수집 서비스의 권한과 악용 방어를 검증한 뒤 전송을 붙인다. 말소리 분리는 구현 순서에서도 제외한다.
