# 최신 기능 GitHub 반영과 Windows 빌드 검증

## 범위

2026년 11월 13일 기준 로컬 구현을 공개 저장소에 반영하고 Windows x64 실행 파일을 빌드한다. 기존 빌드 구성에 따라 macOS arm64도 함께 실행한다. 기존 공식 릴리즈는 변경하지 않고 이번 빌드 산출물로 확인한다.

최근 디자인과 다단 메뉴, 작업 상세와 복구, 분석 목록 사용성, 다운로드 조각 동시 처리 수 1~16 설정이 대상이다. 동시 처리 수는 한 VOD의 HLS 조각 수이며 여러 VOD 동시 실행 수가 아니다. 지정 구간 다운로드의 FFmpeg 경로에는 이 설정을 적용하지 않는다.

## 보존과 배포 범위

- 개발 소스와 별도의 배포 checkout에서 버전 관리를 진행한다.
- 모델, VOD, 전사, 채팅, 수동 교정, 클립 초안과 출력 결과를 변경하지 않는다.
- 공개용 소스 allowlist로 내보내고 개인 진단 문서와 실행 로그는 제외한다.
- 사용자별 경로와 인증 정보가 변경 파일에 포함되지 않았는지 검사한다.

## 배포 준비 중 수정

- 새 디자인 라이브러리 manifest에 명시된 라이선스 파일도 포함한다. 경로 안전성과 SHA-256을 확인하고 복사한다.
- 소스 반출에서 누락된 `.cjs` 검사 파일도 포함해 최신 로고와 배경 검사를 실행한다.
- 제거된 영상 나누기 기록 삭제 모듈이 배포 checkout에 남아 있던 것을 제거한다. 사용자 작업 파일 삭제와는 무관하다.
- CI에 최신 디자인, 대기열, 작업 상세, 결과 목록, 영상 나누기 검사 모듈을 추가한다.
- 실제 패키지 smoke 검사에서 새 화면 모듈과 디자인 스타일 제공 여부도 확인한다.
- 동시 다운로드 입력과 체크박스에서 담기 버튼으로 바뀐 UI를 기존 테스트 fixture에 반영한다. 등록 확인에 동시 다운로드 16개가 전달되는지 확인한다.

## 로컬 검사

- 내보낸 배포 소스의 Python 검사: 225개 실행, 실패 없음, OS 조건으로 2개 건너뜀.
- JavaScript 검사: 배포 검사 전체 모듈 통과. 최근 UI와 달라진 테스트 fixture를 갱신하고 누락된 배경 검사 파일을 반출한 뒤 확인했다. GitHub에서도 전체 실행한다.
- 변경 파일의 공백 오류 검사 통과.
- 로컬에 남은 오래된 배포 FFmpeg는 PNG 디코더 검사에 실패했다. 이 파일을 배포하지 않으며, GitHub가 고정 소스와 빌드 설정에 따라 준비하는 FFmpeg로 다시 검사한다.
