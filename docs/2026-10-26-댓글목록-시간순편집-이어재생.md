# 댓글용 타임스탬프 목록·구간 이어 재생

작업일: 2026-10-26

## 구현

- 자유 메모 대신 항목별 시각·제목 입력란·제거 버튼을 제공한다. 제목을 편집해도 시각과 영상 구간은 유지한다.
- 체크한 문맥은 항상 시작 시각순으로 배치한다. 1·2·3·6·10 선택 후 4·7 선택 시 1·2·3·4·6·7·10 순서가 된다. 같은 문맥의 중복 체크 이벤트는 중복 행을 만들지 않는다.
- 체크 해제나 ×는 해당 행과 체크를 함께 제거한다. 리스트 초기화는 확인 후 현재 결과 버전의 목록만 비운다. 원래 요약·전사는 변경하지 않는다.
- 목록 구간 이어 재생은 선택 문맥의 시작~끝 구간만 시간순으로 재생한다. 빈 시간은 건너뛰고 겹치거나 맞닿은 구간은 합쳐 한 번만 재생한다. 마지막 구간 끝에서 정지한다.
- 목록 재생의 일시정지·계속을 제공한다. 목록 추가·제거·초기화, 다른 결과·페이지·VOD 선택, 별도 시각 이동은 기존 재생 목록을 종료한다. 제목만 편집하면 구간은 바뀌지 않는다.
- 클립보드 복사하기는 편집된 목록 전체를 `HH:MM:SS 제목` 줄로 모아 복사한다. 텍스트 전체 선택 버튼은 제거했다. 클립보드 사용이 차단된 경우에만 읽기 전용 수동 복사 영역이 나타난다.
- AI 문맥 미리보기에서는 배속 선택을 숨기고 1배속·3초 뒤로/앞으로 버튼을 제공한다. 통합 분석 페이지의 기존 배속 선택은 유지한다. 3초 이동은 영상 범위를 벗어나지 않으며 현재 재생/일시정지 상태를 유지한다.

## 데이터 보존·예외 처리

- 댓글은 VOD·문맥 결과 버전별로 저장하며 원본·전사·화자 배정·요약 JSON과 별도다. 수정 제목과 선택 목록은 폴링·필터·재접속으로 덮어쓰지 않는다.
- 이전 자유 메모는 줄별로 변환한다. 연결 가능한 문맥의 시각·끝을 재사용하고 연결할 수 없는 줄·자유 문장은 보존한다. 끝 시각을 추측하지 않아 재생 범위를 모르는 행은 복사만 가능하다.
- 이전 메모 원문은 새 데이터의 `legacy_text`와 화면의 ‘이전 메모 원문 보기’로 보존한다. 첫 목록 저장 시 기존 JSON을 `<결과ID>.legacy.json`으로 보관한다. 조회만으로 기존 파일을 변경하지 않는다.
- 저장 버전 충돌은 미저장 안내로 알리며 다른 창의 수정을 덮어쓰지 않는다. 목록 형식으로 저장한 뒤 구버전 앱이 메모 형식으로 덮어쓰는 요청도 차단한다.
- 빈 목록·미준비 영상·잘못된 구간·영상 끝 이후의 구간은 이어 재생에서 제외하거나 사유를 알린다. 영상 메타데이터가 나중에 준비되는 경우 범위를 다시 제한한다.
- 처리 중·시각 확인 대상의 댓글 선택 제한과 실패·전사 없음 항목 선택은 유지한다.
- 범용 시각·식별자·상태 기반으로 처리하며 특정 VOD 번호·대사·화자에 따른 예외는 추가하지 않는다.

## 검증

- Node: 댓글 목록 시간순 삽입, 편집·폴링 보존, 중복 체크, 체크와 행 삭제 연동, 초기화, 복사/수동 대안, VOD·결과 전환, 저장·복원, 이전 메모 보존, 원본 시각 보정 검사 통과.
- Node: 재생 구간 합집합, 중간 건너뛰기, 마지막 정지, 일시정지·계속, 3초 이동·경계 제한, 일반 탐색·페이지 전환, 메타데이터 지연 검사 통과.
- Python: 목록 저장·충돌·초기화·구형 메모 백업·구버전 덮어쓰기 차단·입력 검증·심볼릭 링크 차단 4개 통과. 기존 단순화 회귀 검사 10개 통과.
- 기존 문맥 검토·문맥 보완·기본 플레이어 관련 검사도 통과.
- 내부 브라우저의 가상 20초 영상과 10개 문맥으로 화면 동작을 확인했다. 사용자의 실제 VOD와 댓글 데이터는 검증에 변경하지 않는다.

## 브라우저·서버 확인 결과

- 실제 내부 브라우저에서 1·2·3·6·10 선택, 제목 편집 후 4·7을 추가해 1·2·3·4·6·7·10 순서가 되는 것을 확인했다. 클립보드의 전체 텍스트 순서와 수정 제목도 일치했다.
- 가상 영상의 선택 7구간을 이어 재생하고 마지막 선택의 끝인 18.7초에 일시정지했다. 3초 뒤로 누르면 15.7초, 다시 앞으로 누르면 18.7초로 이동하며 일시정지를 유지했다.
- 초기 구현에서 브라우저의 지연된 탐색 이벤트가 목록 재생을 해제하는 현상을 확인했다. 탐색 완료 위치를 기준으로 확인하도록 보완한 뒤 재검증했다. 지연·중복 탐색 완료 이벤트와 이전 play Promise 취소의 회귀 검사를 추가했다.
- 가상 목록 초기화 후 모든 선택 체크가 해제되고 복사·목록 재생 버튼이 비활성화됨을 확인했다.
- 댓글 목록 저장 관련 검사 6개와 HTTP 웹 자원 검사 4개도 통과했다. 신규 JS 모듈 2개를 서버 허용 목록에 등록했고, 기존 비허용 경로 차단을 유지했다.
- 수정한 개발 앱을 127.0.0.1의 난수 주소에서 실행했다. 외장 VOD 보관함과 기존 AI 문맥 화면을 열어 저장 메모 2줄의 제목·시각이 목록에 보존되는 것을 확인했다. 실제 자료의 체크·편집·재분석은 수행하지 않았다. 브라우저 오류 로그는 없었다.
- 검증 근거: `outputs/2026-10-26-comment-list-check/`의 Python 검사 로그, 가상 영상·검사 화면과 실제 앱 화면. 개발 실행 주소는 같은 폴더의 `app-ready.json`에 기록한다.
