# 결과 확인 UI·UX와 방송 배경 설명 개선 검토

작성일: 2026-10-20
상태: 최초 문서는 조사·설계로 작성했다. 이후 사용자 승인에 따라 구현했다. 현재 구현·검증 결과는 [통합 구현 기록](2026-10-20-결과확인-UIUX-통합구현-검증.md)을 참고한다. 아래 현재 동작 표는 수정 전 조사 시점의 기록이다.

## 1. 권고 방향

기능을 모두 펼쳐 놓은 현재 화면을 **결과를 읽고, 해당 순간을 듣고, 필요한 항목만 수정하는 화면**으로 바꾼다. 여백 축소와 정보 배치 변경을 함께 진행하는 것이 좋다.

- 가져오기: VOD 리스트 등록과 저장 폴더 설정에 집중한다.
- 음성 전사: 화자 이름을 합치지 않은 전사·수동 교정 내용을 확인한다.
- 화자 구분: 선택 기능으로 유지하고, 화자 목록 / 배정된 전사 / 인식 실패 검토를 탭으로 나눈다.
- 통합 분석·재생: 영상, 간단한 재생 조작, 확대 가능한 공통 시간축을 중심으로 정리한다.
- AI 문맥 정리: 선택적인 방송 배경 설명, 대화 요약과 채팅 반응의 동시 표시, 실패 항목의 근거 기반 참고 내용을 제공한다.
- 공통: 작은 간격과 일관된 행 높이, 최소한의 테두리, 현재 상태가 명확한 도구 모음을 적용한다.

기존의 데스크톱 배치 유지, 💡 도움말, 진행·오류 상시 표시, 원본·수동 수정·기존 결과 보존 원칙은 유지한다. 특정 VOD·단어·게임 이름에 맞춘 예외를 추가하지 않는다.

## 2. 현재 코드에서 확인한 사실

| 항목 | 현재 동작 | 의미 |
|---|---|---|
| 전사 화면의 화자 표시 | `archive/speech_store.py`의 `result()`가 원 전사와 수동 교정을 읽은 다음 `voice_store.decorate()`를 호출한다. | 화자 분석 후 전사 화면에 화자 정보가 합쳐진다. 전사 본문 파일을 화자 분석으로 덮어쓰는 구조는 아니다. |
| 화자 구분된 전사 | `voice_store.rows()`도 원 전사·교정을 읽고 별도 화자 배정을 결합한다. | 두 벌의 전사 본문을 복제하지 않고 화면의 책임을 나눌 수 있다. |
| 내보내기 | `speech_store.export()`는 전사·교정 중심, `voice_store.export()`는 화자 이름·배정 포함 결과다. | 이미 분리된 내보내기 의미를 화면에도 일관되게 반영하면 된다. |
| 화자 페이지 | 준비·실행·버전, 화자 카드, 후보 검토, 실패 전사, 배정 수정, 배정된 전사가 세로로 이어진다. 실패/배정 목록은 각각 최대 100건씩 반환한다. | 페이지 분할이 있어도 두 목록과 화자 카드가 한 화면에 쌓여 길어진다. |
| 통합 화면의 반응 분석 | `web/reactions.js`는 저장 결과를 불러오며, 분석 폼 제출 시 `analyze`를 호출한다. | 화면을 여는 것만으로 항상 자동 재분석하는 것은 아니다. |
| 순차 자동화 | `automation.py`의 요약까지 진행 경로에 `reactions`가 있다. `automation_steps.py`는 유효한 기존 결과를 재사용하고 없거나 오래된 경우 분석한다. | 자동화에서는 반응 분석이 자동 진행된다. 다운로드만 하는 경로와 구분해야 한다. |
| AI 문맥 정리 | 현재 형식 10도 `context_dialogue.process()`를 사용하며, 새 실행에 `reaction-ranges.json`이 없으면 반응을 계산한다. | 요약의 🤩를 위한 계산도 자동이다. 통합 화면이 읽는 저장 결과와는 별도의 실행 스냅샷일 수 있다. |
| 시간축 선택 시 화면 이동 | `web/player.js`의 `seek()`에 `scrollIntoView()`가 있다. | 시간축 선택 시 화면이 플레이어로 이동하는 코드상 원인이 확인된다. |
| 시간축 밀도 | `web/timeline.js`는 전체 길이를 캔버스 폭에 맞춰 그린다. 확대 범위가 없다. | 긴 영상일수록 같은 폭에 많은 발언·반응이 겹친다. |
| 영상 저장 구간 | `web/explore.js`와 HTML에 범위 선택 및 “7단계 목록에 추가” 안내가 남아 있다. 현재 7단계는 리포트다. | 제거된 저장 기능의 잔여 화면·안내를 정리할 필요가 있다. |
| 정상 요약의 채팅 반응 | `web/context.js`는 `summary.context`를 본문에, `summary.chat`을 대체로 접힌 상세에 넣는다. 대화 요약이 비어 있으면 채팅을 본문에 넣는다. | “실패할 때만 채팅이 보인다”는 체감에는 표시 규칙 차이가 영향을 준다. |
| 실제 처리 실패 | `item.failed` 항목은 일반 요약 본문 표시에서 제외되고, 형식 10의 채팅 후처리도 해당 항목을 건너뛴다. | 모든 실패 항목에 이미 채팅 설명이 생성되어 있는 것은 아니다. 표시 변경과 실패 복구 처리를 나눠야 한다. |

위 내용은 현재 로컬 소스 기준이다. 사용 중인 배포 패키지와 동일하다고 가정하지 않는다.

## 3. 가져오기와 전사 분리

### 가져오기

`내 비디오 사용` 입력과 새 로컬 영상 등록 흐름을 제거하는 방향에 동의한다. 목록 등록과 자동화가 주 사용 경로라면 별도 파일 입력이 선택 부담을 늘린다.

다만 **기존에 가져온 영상은 계속 열고 분석할 수 있어야 한다.** 로컬 영상의 VOD 시작 오프셋·파일 경로를 읽는 기능까지 삭제하면 과거 프로젝트의 채팅 시각과 댓글 타임스탬프가 틀어질 수 있다.

- 새 파일 업로드 UI와 연결 이벤트를 정리한다.
- 사용하지 않는 업로드 API도 호출 관계를 확인한 뒤 함께 정리한다.
- 기존 로컬 프로젝트 읽기·재생·오디오 추출·분석과 시간 매핑은 유지한다.
- 현재 `app.js`의 목록 잠금 처리도 `local-import-start`를 참조하므로 HTML만 삭제하면 안 된다.
- 보관함 폴더와 모델 폴더 설정은 가져오기 안에 그대로 둔다.

### 전사와 화자 구분

권고는 **전사 본문은 하나로 보존하고, 보는 화면을 분리하는 방식**이다.

| 위치 | 기본 표시 | 수정 책임 |
|---|---|---|
| 음성 전사 | 시각, 전사 본문, 교정 여부, 원음 듣기 | 전사 텍스트 교정 |
| 화자 구분 | 동일 본문, 화자 이름·배정 상태, 원음 듣기 | 이름 변경·화자 배정·되돌리기 |
| AI 문맥 입력 | 선택된 전사·수동 교정 + 유효한 선택 화자 결과 | 기존 내용 중심 요약 정책 유지 |

화자 분석을 실행하거나 이름을 바꿔도 음성 전사 페이지는 바뀌지 않는다. 전사에서 사용자가 본문을 교정하면 화자 페이지에는 같은 교정문이 보인다. 이는 복사본 간 불일치를 막기 위한 의도적인 동작이다.

화자 페이지에서 본문 교정이 필요하면 해당 행의 음성 전사 편집으로 연결한다. 별도의 두 번째 교정 저장소를 만들지 않는다. 분석 버전이 전사 버전과 맞지 않으면 배정을 억지로 합치지 않고 “현재 전사와 다른 버전”을 표시한다.

## 4. 화자 페이지: 세 개의 검토 탭

상단은 엔진·모델 상태와 진행 상태를 짧게 보여준다. 준비가 끝난 도구의 상세 설치 안내는 💡 또는 설정 영역에 넣되, 미설치·인증 필요·오류·설치 버튼은 바로 보이게 한다.

```text
화자 구분 (선택)                 분석 버전 / 엔진 설정
도구 준비됨 · 모델 준비됨         [화자 분석]
진행 상태 / 시간 / 중단 / 오류

[화자 목록] [배정된 전사 N] [인식 실패 N]
─────────────────────────────────────────
현재 탭 검색·필터       선택한 발언 듣기 / 정지
현재 탭의 결과 목록     선택 항목 배정·변경 내용
이전 / 다음 · 건수
```

- **화자 목록:** 큰 카드 대신 이름·발언 수·대표 음성 듣기·이름 변경을 한 행으로 배치한다. 0개 발언과 음향 구간 존재의 차이는 상태로 구분한다.
- **배정된 전사:** 시각 / 이름·상태 / 본문 / 듣기의 일관된 행 구조를 사용한다.
- **인식 실패:** 별도의 검색·후보 묶음·개별 듣기·대상 화자·일괄 배정·되돌리기를 유지한다.
- 선택한 항목의 조작부만 자세히 보여주고, 모든 행에 큰 편집 폼을 반복하지 않는다.
- 목록 위치, 검색 조건, 선택 화자는 탭을 옮겼다 돌아와도 유지한다. VOD·분석 버전이 바뀌면 잘못된 선택을 초기화한다.
- 기존 페이지 단위 조회를 먼저 재사용한다. 수천 건을 한 번에 그리는 구조나 새 가상 목록 라이브러리는 우선 도입하지 않는다.
- 결과가 있는 VOD는 검토 내용을 우선 보여주고, 결과가 없으면 준비·분석 안내를 우선 보여준다.

탭은 한 번에 한 검토 영역을 보여주며, 키보드 좌우 이동·선택 상태·연결된 패널을 명시한다. [W3C 탭 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

## 5. 통합 분석·재생: 영상과 시간축

통합 검색, 채팅 원문 목록, 발언 목록, 영상 저장 구간 선택을 이 페이지에서 제거하는 방향에 동의한다. 전사 검토는 전사·화자 페이지, 요약 근거 확인은 AI 문맥 페이지에서 맡는다.

```text
통합 분석·재생        채팅 반응: 완료 / 준비 필요 / 이전 결과
┌────────────────────────────────────────────────┐
│                      영상                       │
└────────────────────────────────────────────────┘
[재생/일시정지]  00:00:00 / 전체 길이  [배속]
공통 시간축      [−] [10분 범위] [+] [전체] [현재 위치]
전체 영상 미니 시간축 ────[지금 보고 있는 범위]────
확대 시간축: 채팅량 / 반응 / 발언·화자 / 인식 실패
시각 눈금 · 선택 시각과 해당 반응의 짧은 설명
```

### 조작 규칙

- 시작·중간·끝·별도 시각 입력을 제거하고 재생, 배속, 현재/전체 시각을 유지한다.
- 시간축을 클릭하면 재생 위치를 바꾸고 화면 스크롤은 유지한다. 재생 중이었다면 계속 재생하고 일시정지 중이었다면 정지를 유지하는 것을 권고한다.
- 다른 페이지의 “영상에서 확인”은 페이지 이동이 필요하므로, 시간축 내부 탐색과 별도 처리한다.
- 플레이어와 시간축이 같은 작업 영역에 들어오도록 영상 높이를 제한한다. 낮은 창에서는 영상을 줄이고 시간축을 화면 밖으로 밀어내지 않는다.
- 확대는 페이지 전체 확대가 아니라 **표시 시간 범위 변경**이다. 전체 / 30분 / 10분 / 2분 범위와 +/−를 제안한다.
- 확대 중심은 현재 보고 있는 위치를 기준으로 유지한다. 전체 미니 시간축에서 범위를 옮기고, 키보드 또는 이전·다음 범위 버튼으로도 이동할 수 있게 한다.
- 드래그는 탐색 범위 이동으로 사용한다. 삭제할 “영상 저장 구간” 선택 상태를 계속 만들지 않는다.
- 재생 위치 따라가기는 가로 시간 범위만 옮긴다. 사용자가 다른 범위를 탐색하는 동안 자동으로 끌어오지 않는다.
- 원본 영상·채팅 내보내기는 없애지 않고 가져오기 진행/자료 메뉴로 옮기는 것을 권고한다.

### 긴 영상과 확대의 정확성

화면만 늘리고 원 자료를 재분석할 필요는 없다. 보이는 범위만 그리되 다음을 지킨다.

- 전체 보기에서는 여러 구간을 화면 픽셀에 맞게 집계하고, 확대하면 기존 구간 상세를 표시한다.
- 짧은 급증을 평균에 묻히게 하지 않도록 피크를 함께 보존한다.
- 현재 채팅량의 기본 그래프는 10초 단위다. 확대해도 원래 없던 초 단위 정확도를 만들어 표시하지 않는다.
- 20시간 자료, 화자 수가 많은 자료, 채팅 보정값, 영상 끝을 넘는 채팅, 미처리 구간을 구분한다.
- 화자 분석이 없으면 “발언” 트랙으로 보여주며 인식 실패로 오해시키지 않는다.
- 확대·필터 변경은 요약의 🤩 점수를 바꾸지 않는다. 반응지수의 비교 기준은 기존 전체 VOD 기준을 유지한다.

### 자동 반응 분석의 권고

현재 자동화·요약에서는 자동 계산하지만 통합 화면 진입은 저장 결과 조회다. 앞으로는 **유효한 결과가 있으면 재사용, 없으면 준비 상태를 명확히 표시**하는 규칙을 먼저 통일하는 것이 좋다.

추가로 통합 화면 최초 진입 시 자동 계산까지 적용할 수 있다. 이 경우 새 자동 실행임을 명시하고, 작업 잠금·중복 계산 방지·진행 상태를 연결해야 한다. 경계 미검증 채팅은 기존 사용 허용 선택을 우회하지 않는다. 단순히 화면을 열었다는 이유로 기존 사용자 설정이나 분석 결과를 덮어쓰지 않는다.

## 6. 방송 배경 설명: 선택 입력 권고

도움이 될 가능성이 있다. 방송 종류, 작품·게임명, 합방 여부는 애매한 고유명사와 표현을 해석할 때 참고가 된다. Google의 프롬프트 안내도 필요한 배경 정보를 별도 제공하고 지시·자료를 구분하는 방식을 설명한다. 다만 해당 문서는 일반 원칙이며 **현재 Gemma·한국어 방송에서 개선 폭이 검증됐다는 뜻은 아니다.** [Google 프롬프트 설계](https://ai.google.dev/gemini-api/docs/prompting-strategies)

권고 입력:

- 제목: `방송 배경 설명 (선택) 💡`
- 짧은 자유 입력 하나를 기본으로 한다. 예시 버튼을 누르면 편집 가능한 문장만 넣는다.
- “저스트 채팅 후 게임 진행”, “여러 방송자와 합동 방송”처럼 복합 내용을 허용한다.
- 예: `모모모의 방송. 앞부분은 저스트 채팅이고 이후 ○○ 게임을 함께 진행한다.`
- 채널·VOD 제목 등 이미 확인된 정보는 참고로 보여주되, 제목만으로 장르·참여자·구간을 확정하지 않는다.
- 기본은 공란이며 입력하지 않아도 분석할 수 있다. 초안 상한은 500자로 두고 실제 토큰 예산에도 포함한다.
- 입력 시 LLM을 추가로 호출하지 않는다. 기존 분석 요청에 짧은 자료로 넣는다.

### 모델에 적용할 규칙

1. 방송 배경은 **사용자 제공 참고 정보**로 구분한다. 방송 발언·채팅 근거 ID와 섞지 않는다.
2. 근거 없는 사건·발언·인물 귀속을 만들지 않는다. 스트리머 이름을 적었다고 모든 미확인 발언을 그 사람에게 배정하지 않는다.
3. 전사와 충돌하면 근거 없는 단정을 보류한다. 게임 방송 설명 때문에 실제 잡담을 게임 이야기로 강제 분류하지 않는다.
4. 실제 화면을 입력하지 않는 현재 요약은 영상에서만 보이는 사건을 확인할 수 없다.
5. 설명으로 원 전사, 수동 교정, 화자 배정을 변경하지 않는다.
6. 현재 Gemma 4의 대화 형식과 사고 설정을 유지한다. 배경 설명을 넣기 위해 모델을 바꾸거나 별도 보정 단계를 추가하지 않는다. [Gemma 4 공식 입력 형식](https://ai.google.dev/gemma/docs/core/prompt-formatting-gemma4)

처리 시간은 입력 토큰이 늘어 소폭 증가할 수 있다. 재시도가 줄면 전체 시간이 줄 수도 있지만 현재는 가설이다. “속도 개선 기능”으로 안내하지 않는다.

### 저장·자동화 영향

- VOD별 설명을 저장하고 요약 실행 시작 시 내용·버전을 스냅샷으로 남긴다.
- 입력 지문·응답 캐시에도 포함하여 설명이 다른 결과를 재사용하지 않는다.
- 분석 중 수정한 설명은 진행 중 결과에 섞지 않고 다음 새 분석에 적용한다.
- 기존 요약은 작성 당시 조건 그대로 보존한다. 설명을 수정했다고 자동 재요약하지 않는다.
- 순차 자동화에서도 VOD별 설명을 실행 전에 지정할 수 있어야 한다. 한 방송자의 이름·게임명을 여러 VOD에 무조건 복사하지 않는다.
- 한 영상의 장르 변화는 우선 자유 문장으로 표현한다. 정확한 구간별 배경 편집기는 첫 구현에 추가하지 않는다.

## 7. 정상·실패 요약의 표시 통일

정상 문맥 카드의 기본 구성:

```text
□ 댓글에 포함   00:12:30 ~ 00:15:10        [재생]
문맥 제목                       🤩🤩🤩 3/10
대화 요약  2~3문장
채팅 반응  실제 채팅에서 확인된 반응 1~2문장
반응 시각  [00:13:20] [00:14:50]
[근거·원문] [검토 정보]
```

- 현재 생성된 `summary.chat`을 대화 요약 바로 아래 표시하는 것은 주로 UI 변경이다. 기존 결과를 재생성할 필요가 없다.
- “화자 요약”보다는 **대화 요약** 명칭을 권고한다. 화자 미분석·인식 실패 상태에서도 의미가 맞다.
- 반응이 없거나 채팅이 제공되지 않은 경우, 처리 대기, 채팅 설명 실패를 각각 구분한다.
- 🤩는 채팅량·반복 표현의 상대 반응지수다. 긍정·재미·만족도 판정이나 요약 품질 점수가 아니다.
- 대화와 채팅이 같은 시각이라고 인과관계로 묶지 않는다. 근거 없는 “이 말 때문에 웃었다”는 설명은 추가하지 않는다.
- 원문·근거 상세는 필요할 때 열게 하되 대화 요약과 채팅 요약 자체는 기본 노출한다.

### 실패해도 참고 내용 제공

실패는 아래처럼 구분한다. 글이 보인다고 성공으로 바꾸지는 않는다.

| 상태 | 본문 | 상태·복사 정책 |
|---|---|---|
| 일부 주장만 검증됨 | 검증된 문장만 제공 | `부분 요약 · 확인 필요`, 제외된 주장 표시 |
| 구조화 요약 실패, 전사는 읽힘 | 해당 구간의 대표 원문 2~3개와 시각 제공 | 붉은 굵은 `요약 실패` + `원문 기반 참고`, 정상 요약과 구분 |
| 대화 요약 실패, 채팅 근거 있음 | 채팅 관측 내용 또는 반복 표현·건수 제공 | `채팅만 확인 가능`; 방송 사건 설명으로 바꾸지 않음 |
| 전사도 읽을 수 없거나 없음 | 실패 이유·자료 상태·영상 재생 제공 | 내용을 지어내지 않음 |

첫 구현에서는 실패마다 추가 LLM 호출을 늘리기보다 **검증된 부분 재사용 → 근거 원문 표시**를 우선한다. 형식 10의 `failed` 항목에는 채팅 후처리가 없는 경우가 있으므로 기존에 없는 채팅 설명을 UI만으로 만들어냈다고 처리해서는 안 된다.

- 연속 실패해도 기존처럼 다음 구간을 계속 처리한다. 사용자 중단, 디스크 쓰기 실패, 실행기 종료 등 작업 지속이 불가능한 오류는 별도로 남긴다.
- 실패 상태, 원 오류, 실패 시각 범위, 재시도 이력을 보존한다.
- 실패 참고문은 기본 댓글 복사에서 제외한다. 성공 결과를 대체하는 제목으로 내보내지 않는다.
- 기존 실패 기록을 자동 덮어쓰지 않는다. 기존 기록에서는 읽기 전용 참고 보기를 만들고, 재처리는 별도 결과로 저장한다.

## 8. 전체 디자인과 밀도

현재 CSS는 기본 본문 행간 1.65, 문맥 본문 1.8, 여러 곳의 20~30px 상하 여백, 바깥 패널과 내부 카드·상세 박스가 중첩되어 있다. 한 항목에 시각·제목·재생·안내·근거 버튼이 여러 줄씩 붙는 영향도 크다.

권고는 현재 따뜻한 흰색·먹색·주황 포인트를 유지한 **간결한 작업 화면**이다. 테마 교체보다 정보 계층과 간격의 통일을 우선한다.

| 요소 | 제안 초안 |
|---|---|
| 기본 본문 | 14px, 행간 1.45~1.55 |
| 보조 정보 | 12~13px, 반복 안내는 💡로 이동 |
| 일반 버튼·입력 | 높이 32~36px; 주요 시작·중단은 36~40px |
| 작은 듣기·도움말 버튼 | 클릭 영역 28~32px 이상, 이름 제공 |
| 목록 행 | 한 줄 자료 40~48px 중심; 긴 전사는 가변 높이 |
| 항목 안쪽 여백 | 10~12px |
| 항목 사이 | 6~8px |
| 섹션 사이 | 16~20px |
| 표면 구분 | 큰 바깥 카드 안에 카드를 겹치기보다 얇은 행 구분선 사용 |
| 결과 도구 모음 | 버전·검색/필터·건수를 한 줄에 정렬 |

이는 구현 후 화면에서 조정할 초안이며 가독성 검증을 통과한 수치가 아니다. 버튼을 무조건 작게 줄이지 않는다. W3C는 포인터 대상의 최소 크기 24×24 CSS 픽셀 또는 관련 예외 조건을 설명한다. 이 앱은 주요 버튼을 그보다 크게 잡고 키보드 포커스도 유지한다. [W3C 대상 크기 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)

행과 도구 모음의 일관된 크기, 전체 테이블이 아닌 선택 행의 추가 정보 노출은 Carbon의 자료 중심 UI 가이드에서도 참고할 수 있다. 라이브러리 도입 없이 현재 컴포넌트와 CSS에 적용한다. [Carbon 데이터 테이블](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)

사용 빈도가 낮은 설정은 별도 영역으로 옮기되 핵심 결과까지 숨기지는 않는다. 여러 겹의 접기 영역을 만들지 않는다. 이는 주요 기능을 앞에 두고 부가 기능을 필요할 때 제공하는 원칙과 맞는다. [NN/g 단계적 정보 공개](https://www.nngroup.com/articles/progressive-disclosure/)

스크롤은 페이지와 현재 활성 목록 중심으로 제한하고, 카드마다 작은 스크롤 영역을 만들지 않는다. 진행·오류·미설치·부분 자료 상태는 도움말 안에 숨기지 않는다. 데스크톱 배치를 유지하되 브라우저 글자 확대 시 긴 문장·조작부가 잘리지 않게 한다.

## 9. 사이드이펙트와 예외 처리

| 변경 | 위험 | 처리 원칙 |
|---|---|---|
| 로컬 가져오기 제거 | 과거 로컬/테스트 영상이 열리지 않거나 채팅 오프셋 소실 | 신규 입력만 제거하고 기존 자료 판독·시간 매핑 유지 |
| 전사 화면에서 화자 결합 제거 | 요약 입력까지 화자 정보를 잃음 | 전사 조회 화면과 요약/화자 자료 결합 경로를 분리해 확인 |
| 화자 탭 전환 | 미저장 이름·선택 묶음 소실, 음성 중복 재생 | 편집 중 상태 명시, 버전별 선택 관리, 미리듣기 하나만 재생 |
| 검색·채팅 목록 제거 | 전사 페이지의 “같은 순간 함께 보기”가 빈 화면으로 이동 | 시간축 선택·해당 시각 재생으로 연결하고 안내 변경 |
| 공통 플레이어 수정 | AI 문맥 페이지도 같은 DOM 플레이어를 옮겨 사용하므로 함께 영향 | 문맥 구간 끝 정지·배속·재생 위치·오류 안내 유지 |
| 저장 구간 UI 제거 | 남은 DOM 참조로 전체 JS 초기화 실패 | 이벤트·도움말·세션 선택 상태·서버 호출 관계 함께 정리 |
| 확대·범위 이동 | 화면 좌표가 다른 시각을 가리키거나 피크가 사라짐 | 표시 범위 변환·경계 보정·집계 및 전체 복귀 검증 |
| 반응 자동화 통일 | 중복 작업, 부분 채팅의 무단 사용, 설정 덮어쓰기 | 기존 지문·잠금·허용 상태 존중, 실패 시 수동 재시도 |
| 방송 배경 추가 | 잘못된 설명으로 의미 왜곡·화자 오인, 다른 VOD에 설명 전파 | 참고 자료 분리, VOD별 저장, 입력 스냅샷·지문, 근거 우선 |
| 실패 참고 내용 | 실패가 성공처럼 보이고 댓글에 잘못 복사됨 | 실패 표식 유지, 참고 유형 명시, 기본 복사 제외 |
| 밀도 축소 | 듣기/배정 버튼 오클릭, 글자 잘림 | 클릭 영역·포커스·긴 한국어 문장·화면 확대 확인 |

## 10. 구현 순서와 검증 기준

### 권고 순서

1. 전사/화자 표시 분리, 신규 로컬 입력·잔여 저장 구간·사용하지 않는 검색 영역 정리.
2. 화자 검토 탭과 공통 간격·행 구조 적용. 실행 도구·모델 준비 상태는 보존.
3. 영상 아래 시간축 배치, 강제 스크롤 제거, 시간축 확대.
4. 정상 요약의 채팅 반응 기본 노출과 실패 참고 보기.
5. 방송 배경 설명과 실행 스냅샷 적용 후 별도 품질 비교.

UI만 바뀌는 단계와 LLM 입력이 달라지는 단계를 분리하면 회귀 원인을 확인하기 쉽다. Gemma 모델 교체·추론 설정 변경은 포함하지 않는다.

### 검증 기준

- 화자 실행·이름 변경·수동 배정 전후에 음성 전사 화면의 본문·행 ID·시각·교정 상태가 같다.
- 전사 수동 교정은 화자 페이지에서도 동일하게 보이고, 화자 배정·되돌리기는 교정문을 변경하지 않는다.
- 기존 로컬 영상, 기존 화자 결과, 과거 형식 요약, 댓글 편집본을 다시 열 수 있다.
- 미분석, 실패만 존재, 배정만 존재, 화자 0개 발언, 1,000건 이상의 실패, 긴 발언 목록을 각 탭에서 처리할 수 있다.
- 시간축 클릭·확대 중 세로 스크롤 위치가 바뀌지 않는다. 재생/정지·배속·문맥 끝 정지가 의도대로 유지된다.
- 30분·1시간·10시간·20시간 길이에서 시작·중간·끝 선택과 확대 중심, 키보드 탐색을 확인한다.
- 확대 전후 같은 반응의 실제 시각·🤩 점수는 같고, 미처리와 실제 0건을 구별한다.
- 정상/부분/실패/채팅 없음/채팅만 존재/채팅 처리 중 상태를 서로 다른 문구로 표시한다.
- 반응 후처리가 없는 과거 실패 항목은 “없음”을 “분석 완료”로 오인시키지 않는다.
- 배경 설명 없음/정확함/일부 틀림/장르 혼합 조건을 비교한다. 설명만으로 새 사건·화자·결말이 추가되면 실패다.
- 방송 종류가 다른 여러 자료의 고정 구간으로 품질 비교한다. 특정 영상의 이름·표현을 성공 기준이나 예외에 넣지 않는다.
- 품질 비교는 원문에 없는 주장, 중요한 내용 누락, 발언 주체 오인, 주제 경계, 채팅-발언 혼동을 검토한다. 처리 시간·입출력 토큰·재시도 수도 함께 기록한다.
- 1280×720 및 1440×900에서 재생기·주요 조작·시간축 배치를 확인하고, 1024px 폭과 브라우저 200% 확대에서 기능 접근성을 확인한다.
- Safari와 Chrome의 재생을 따로 확인한다. 이번 레이아웃 변경이 과거 Safari 재생 멈춤 문제까지 해결했다고 주장하지 않는다.

## 11. 이번 조사 범위

- 로컬 소스의 전사/화자 결합, 반응 분석 실행 경로, 시간축 조작, 요약 렌더링, CSS를 읽었다.
- 공식 프롬프트 자료, 접근성 패턴, 자료 중심 UI 지침을 조사했다.
- 새 문서만 작성했다. 원본·모델·전사·화자 배정·요약 결과를 변경하지 않았다.
- 제품 구현, 분석 재실행, 처리 시간 측정, 브라우저 화면 실측, Windows 검증, 앱 패키징·배포는 하지 않았다.
