# Electron 실행과 종료 검증

로컬 macOS arm64에서 공식 Electron 45.3.3과 현재 Python 소스로 빈 보관함을 열었다. 기존 보관함이나 사용 중인 프로세스는 사용하지 않았다.

- 실제 첫 화면에서 돋보기 안쪽 채움 색이 RGB(0, 255, 163)였다. 주 메뉴에서 설정과 앱 업데이트를 눌러 버전 1.2.0, DMG 수동 교체 안내, 라이선스 버튼, 네이버 및 치지직과 제휴 관계가 없다는 문구를 확인했다. 업데이트 다운로드는 실행하지 않았다.
- 렌더러가 Node에 접근할 수 없고 제한된 설정 연결로 상태를 읽는 것을 확인했다. 창과 Python 처리가 종료 코드 0으로 끝났다. 준비 신호를 처리기 PID, 루프백 주소, 이번 실행의 난수 경로와 대조한다.
- 서버 검사에서 저장 요청 수행 중, 대기 작업이 있는 경우와 믹스 영상 생성 중에는 업데이트용 잠금을 거부했다. 유휴 시 허용한 뒤에는 새 작업 요청을 받지 않았고, 교체 실패를 가정해 해제하자 다시 요청을 받았다.
- 이전 정식 macOS 1.1.0 ZIP을 당시 SHA256SUMS와 비교한 뒤 FFmpeg와 ffprobe를 임시 폴더에 추출했다. 현재 소스와 함께 합성 VOD에서 영상과 채팅 원본 해시 보존, 원음 추출, 오프라인 복구, 실행 리포트 1.2.0, 다중 오디오 분할 패킷 동일성, 한글 PNG 자막 클립 저장을 확인했다. 직접 HTTPS, HLS, fMP4 등 원격 구간 5개와 신뢰되지 않은 인증서 거부도 통과했다. FFmpeg SHA-256은 `acbf0762ef7108d4c98062ea46809efc8197e92f0035fc28559f592b260b0ab7`이다.
- 보관함과 모델은 기존 Python 경로를 계속 쓴다. Electron의 창 설정은 별도의 사용자 프로필에 저장한다. macOS와 Windows의 최종 배포 이미지 자체에 대한 검증은 [빌드 검증 기록](../2026-11-16-Electron-포터블-구현과-빌드-검증.md)에서 구분한다.

패키지 창 검증은 빈 임시 폴더를 만들고 그 절대 경로를 `CHIDA_DESKTOP_SMOKE_DIR`로 지정한 뒤 앱 실행 파일에 `--desktop-smoke`를 전달한다. 코드 0과 해당 폴더의 `smoke.json`을 함께 확인한다. 시험은 기존 설치나 사용자 자료를 바꾸지 않는다.

Windows 교체 직전에는 현재 화면에 저장하지 않은 입력이 있는지도 확인한다. 실행기 검사 시작과 서버 동결 직후의 두 시점에서 기존 편집 화면의 종료 검사를 호출하며, 저장이 진행 중이거나 실패하면 교체를 시작하지 않는다. 실제 macOS Electron 창에서 기존 댓글 편집기를 사용해 최초 상태와 재저장 성공 후에만 교체를 허용하고, 자동 저장 직전, 저장 중, 실패 후에는 보류하는 것을 확인했다.

별도 임시 공간에서 현재 Python을 PyInstaller로 다시 묶고 공식 이전 FFmpeg를 넣은 독립 앱으로 패키지 기능 검사와 실제 첫 화면 검사를 모두 실행했다. 두 검사 모두 종료 코드 0이었다. 이 결과는 최종 GitHub DMG와 Windows ZIP 검사와 별도이며, 모델을 실제로 내려받아 추론하는 시험은 포함하지 않는다.

Windows 패키지 첫 검사에서 격리 폴더 판정이 실패했다. 최초 로그에는 실패한 폴더가 표시되지 않았다. 검증 실행기는 보관함, 모델, 설정 폴더를 빈 임시 공간 안에 만들고 Python이 설정을 읽기 전에 전용 경로를 전달한다. 실행 중 경로는 운영체제의 실제 경로로 변환해 각각 대조한다. 설정 조회 회귀 검사에서는 원래 설정을 읽지 않았고, macOS Electron에 임시 폴더의 별칭을 전달한 실제 실행도 통과했다.

최종 Windows ZIP과 macOS DMG는 양쪽 러너에서 전용 보관함, 모델, 설정 경로 확인을 통과했다. [배포 검증 결과](../2026-11-16-Electron-포터블-구현과-빌드-검증.md)
